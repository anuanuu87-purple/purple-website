Dynamic Multi-Monitor Tiling via Voice Commands in macOS: Boosting Productivity

Published on October 11, 2026 • 6 min read

Dynamic Multi‑Monitor Tiling via Voice Commands in macOS: Boosting Productivity addresses a pain point that many power users still face: arranging windows quickly across two, three, or more displays without reaching for the mouse. Traditional macOS tiling tools (e.g., Split View) are limited to a single screen, and manual dragging becomes a bottleneck when you’re juggling code editors, design canvases, and communication apps simultaneously. By marrying the precision of a tiling window manager with the hands‑free convenience of voice control, you can transition from a “click‑and‑drag” workflow to a “speak‑and‑tile” workflow that scales across any number of monitors. The guide below walks you through the entire stack—system settings, command‑line utilities, custom scripts, and the AI‑driven assistant Purple—so you can implement a production‑grade solution in under an hour.

Understanding Voice‑Driven Tiling on macOS

Why native tiling falls short on multi‑monitor setups

macOS’s built‑in Split View only works on the active display. When you add a second or third monitor, the OS treats each screen as an independent workspace, forcing you to repeat the same drag‑and‑drop actions on every monitor. This duplication not only wastes time but also introduces inconsistency: a window that is perfectly centered on the left monitor may be off‑center on the right. A dedicated tiling manager such as yabai can enforce a grid across all displays, but invoking it via keyboard shortcuts still requires hand movement.

The role of accessibility APIs and speech recognition

macOS Voice Control (introduced in macOS Catalina) leverages the same accessibility APIs that power third‑party automation tools. When you speak a command like “snap Safari to left‑monitor‑two,” Voice Control translates the phrase into an AppleEvent that can trigger a shell script. By chaining this capability with yabai—which directly manipulates window positions via the macOS window server—you obtain a seamless, hands‑free tiling experience that works uniformly across any number of monitors.

Preparing Your Mac for Voice‑Controlled Tiling

Enabling Voice Control and Dictation

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Voice Control to On. macOS will download the required speech models (≈200 MB).
  3. In the same pane, click Commands… and then the + button to add a custom command.
  4. Set When I say to a phrase you’ll use (e.g., “tile left monitor two”).
  5. Choose Run Workflow and point it to a shell script you’ll create in /usr/local/bin/voice‑tile.sh.

Installing required command‑line tools (yabai, skhd)

Open Terminal and run the following Homebrew commands. These tools are maintained, open‑source, and fully compatible with macOS Ventura and later.

# Install Homebrew if it isn’t present
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install yabai (tiling window manager) and skhd (hot‑key daemon)
brew install yabai skhd

# Grant the necessary accessibility permissions
sudo yabai --install-sa
sudo yabai --start-service
sudo skhd --install-sa
sudo skhd --start-service

After installation, verify that yabai -m query --spaces returns JSON describing each monitor and its spaces.

Securing BYOK with Purple

Purple’s “Bring Your Own Key” (BYOK) architecture ensures that any voice‑driven automation you create remains encrypted end‑to‑end. To enable it:

  1. Visit Purple and create a free developer account.
  2. Generate an RSA‑4096 key pair; download the private key to ~/Library/Application Support/Purple/key.pem.
  3. In Purple’s dashboard, enable the macOS Voice Integration module and paste the public key.
  4. Run purple init --key ~/Library/Application\ Support/Purple/key.pem to bind the key to your local agent.

From this point forward, any script that calls purple exec … will be signed and verified, preventing rogue voice commands from executing unintended actions.

Building the Voice Command Pipeline

Mapping spoken phrases to yabai commands

The core of the system is a lightweight Bash wrapper that receives the spoken phrase, parses it, and forwards the appropriate yabai instruction. Save the following as /usr/local/bin/voice‑tile.sh and make it executable (chmod +x /usr/local/bin/voice‑tile.sh).

#!/usr/bin/env bash
# voice‑tile.sh – translate voice commands into yabai tiling actions

PHRASE="$1"
# Normalise the phrase (lowercase, trim spaces)
PHRASE=$(echo "$PHRASE" | tr '[:upper:]' '[:lower:]' | xargs)

# Helper to fetch the display index from yabai
get_display_index() {
    local name="$1"
    yabai -m query --displays | jq -r ".[] | select(.display_name==\"$name\") | .index"
}

# Parse commands
case "$PHRASE" in
    "tile left monitor "*)
        MON=$(echo "$PHRASE" | awk '{print $4}')
        IDX=$(get_display_index "$MON")
        yabai -m window --focus recent
        yabai -m window --display "$IDX" --grid 2:1:0:0:1:1
        ;;
    "tile right monitor "*)
        MON=$(echo "$PHRASE" | awk '{print $4}')
        IDX=$(get_display_index "$MON")
        yabai -m window --focus recent
        yabai -m window --display "$IDX" --grid 2:1:1:0:1:1
        ;;
    "center window on "*)
        MON=$(echo "$PHRASE" | awk '{print $4}')
        IDX=$(get_display_index "$MON")
        yabai -m window --focus recent
        yabai -m window --display "$IDX" --grid 1:1:0:0:1:1
        ;;
    *)
        echo "Unrecognized command: $PHRASE"
        exit 1
        ;;
esac

This script demonstrates three basic voice patterns: “tile left monitor Two”, “tile right monitor Three”, and “center window on monitor One”. The --grid flag tells yabai how to split the screen (columns : rows : x : y : width : height). You can expand the case block to cover more complex layouts (e.g., 3‑column grids, vertical stacks).

Using Purple to orchestrate the workflow

Purple can act as a middleman, invoking the script only after it validates the voice payload against your BYOK policy. Create a Purple workflow file tile‑workflow.yaml:

name: VoiceTile
description: Execute voice‑driven tiling commands
trigger:
  type: voice
  phrase: "tile * monitor *"
steps:
  - type: exec
    command: /usr/local/bin/voice‑tile.sh "{{phrase}}"
    security:
      signed: true
      key: ~/Library/Application\ Support/Purple/key.pem

Register the workflow with Purple:

purple workflow load tile‑workflow.yaml
purple workflow enable VoiceTile

Now, when you say “tile left monitor two”, Voice Control hands the raw phrase to voice‑tile.sh via Purple, which verifies the signature before execution. This guarantees that only authorized voice commands can manipulate your window layout.

Sample script and terminal commands

Below is a one‑liner you can paste into Terminal to test the pipeline without speaking:

purple exec VoiceTile --phrase "tile left monitor Two"

If everything is wired correctly, the most recently active window will snap to the left half of the second monitor. You can repeat the command with “right” or “center” to see the other positions.

Real‑World Workflows and Optimization

Quick‑snap windows across three monitors

Imagine a typical developer setup: code editor on monitor One, design mockups on monitor Two, and Slack/terminal on monitor Three. With the voice pipeline active, you can say:

  • “tile left monitor one” – moves the active window to the left half of the primary screen.
  • “tile right monitor two” – places the window on the right half of the secondary screen.
  • “center window on monitor three” – maximizes the window on the tertiary display.

Because the command is parsed on the fly, you can chain them together: “tile left monitor one, then tile right monitor two”. Purple’s built‑in queue will execute each step sequentially, preserving focus order.

Creating custom zones for coding, design, and communication

For power users, static grids become limiting. yabai supports spaces and display‑specific layouts. Define a custom layout file ~/.config/yabai/layouts.sh:

# Layout for coding (3‑column grid)
yabai -m space --layout bsp
yabai -m space --grid 3:1:0:0:1:1   # column 1
yabai -m space --grid 3:1:1:0:1:1   # column 2
yabai -m space --grid 3:1:2:0:1:1   # column 3

# Layout for design (2‑column, 70/30 split)
yabai -m space --grid 2:1:0:0:7:10   # 70 % left
yabai -m space --grid 2:1:7:0:3:10   # 30 % right

Bind these layouts to voice commands by extending voice‑tile.sh:

    "apply coding layout on monitor "*)
        MON=$(echo "$PHRASE" | awk '{print $5}')
        IDX=$(get_display_index "$MON")
        yabai -m display "$IDX" --space 1 --layout bsp
        source ~/.config/yabai/layouts.sh
        ;;

Now you can say “apply coding layout on monitor one” and instantly reshape the entire workspace without touching the keyboard.

Automating Finder and PDF summarization with voice

Purple’s AI capabilities go beyond window placement. For example, you can ask Purple to “summarize the PDF in Downloads” while your windows are already tiled for reading. The command looks like this:

Because the same voice channel is used, you can chain actions: “tile left monitor two, then summarize the PDF in Downloads”. The result is a tiled PDF viewer on the left and a text summary on the right, all without lifting a finger.

Pros and Cons of Voice‑Multi‑Monitor Tiling

  • Pros
    • Speed: Reduce window‑arrangement time by up to 80 % compared with mouse dragging.
    • Consistency: Identical grid definitions apply across any number of displays.
    • Accessibility: Hands‑free operation benefits users with repetitive‑strain injuries.
    • Security: Purple’s BYOK model ensures only authorized voice commands affect the system.
    • Scalability: Adding a fourth monitor only requires updating the yabai display index map.
  • Cons
    • Learning Curve: Initial setup involves terminal commands and script editing.
    • Voice Recognition Limits: Accents or background noise can cause mis‑interpretation; training the Voice Control model mitigates this.
    • System Overhead: Running yabai, skhd, and Purple concurrently consumes modest CPU resources (≈5 % on a M2 Mac).
    • Dependency on Accessibility Permissions: macOS updates may reset permissions, requiring re‑authorization.

Frequently Asked Questions

Can I use this setup on macOS Ventura without disabling System Integrity Protection (SIP)?

Yes. yabai offers a --no-sip mode that works with the default SIP configuration, though it limits some low‑level window‑manager features. For full functionality (e.g., moving windows between spaces), you’ll need to temporarily disable SIP, run sudo yabai --install-sa, and then re‑enable SIP. Purple’s security layer remains intact regardless of SIP state.

How does Purple protect my private data when I ask it to scrape web content or draft documents?

Purple encrypts every payload with the RSA‑4096 key you generated during the BYOK onboarding. All network traffic is tunneled through end‑to‑end TLS, and the AI model runs in a sandboxed environment that never stores raw data on disk. The purple exec command signs each request, and the local agent verifies the signature before any external API call is made, guaranteeing that only your authorized voice commands can trigger data‑collection actions.

What if I want to add a new voice phrase without editing the Bash script?

Purple’s workflow engine supports dynamic parameter substitution. You can create a generic “tile * on *” workflow that passes the captured placeholders directly to yabai via purple exec. Example:

purple workflow load - <

After loading this workflow, you can say “tile left on monitor two” and the system will handle the parsing automatically—no script edits required.

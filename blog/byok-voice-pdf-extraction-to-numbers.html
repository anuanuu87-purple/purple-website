Secure BYOK-Powered Voice Scripts for Real-Time PDF Data Extraction and Sync to Numbers on macOS

Introduction

Enterprises and power users increasingly demand a frictionless pipeline that transforms unstructured PDF data into actionable spreadsheet rows without manual copy‑paste. Traditional approaches rely on third‑party OCR utilities, manual export, and repetitive keyboard work, creating security gaps and productivity loss. The emergence of Bring‑Your‑Own‑Key (BYOK) voice‑driven automation on macOS eliminates these pain points by letting a trusted, locally‑encrypted AI execute the entire workflow—voice‑triggered PDF summarization, data extraction, and real‑time sync to Numbers. This guide walks you through the complete setup, from provisioning a BYOK‑enabled voice engine to writing a robust terminal script that Purple (the native voice‑driven autonomous OS AI for macOS) will invoke on command.

Understanding the BYOK Voice Architecture on macOS

What BYOK Means for Voice Automation

BYOK (Bring‑Your‑Own‑Key) is a cryptographic model where the end‑user generates, stores, and controls the encryption keys that protect all AI‑processed data. In the context of voice automation, BYOK guarantees that every spoken command, transcript, and extracted payload remains encrypted at rest and in transit, and only the key holder (you) can decrypt it. This model mitigates the risk of cloud‑based voice assistants inadvertently leaking sensitive information to third‑party servers.

How Purple Implements BYOK Natively

Purple leverages the Secure Enclave on Apple Silicon to generate a 256‑bit AES‑GCM key that never leaves the device. When you invoke a voice command, Purple records the audio locally, encrypts the raw waveform, and processes the speech‑to‑text conversion using an on‑device model. The resulting transcript is then handed to a sandboxed execution environment where your custom scripts run. All intermediate files—PDF extracts, CSV dumps, Numbers imports—are automatically encrypted with your BYOK key before being written to disk.

The Security Model in Practice

  • Key Generation: Run security create-keychain -p your‑password BYOK.keychain and store the key in the Secure Enclave.
  • Isolation: Purple executes scripts inside a macOS App Sandbox with com.apple.security.application-groups entitlement, preventing cross‑app data leakage.
  • Audit Trail: Every voice activation is logged to ~/Library/Logs/Purple/voice_audit.log with a timestamp, encrypted hash of the command, and the user’s key fingerprint.
  • Zero‑Trust Export: When data is sent to Numbers, Purple uses the AppleScript bridge over a secure XPC channel, ensuring the payload never touches the network.

Preparing Your macOS Environment

Installing Purple and Enabling Voice Recognition

Begin by downloading the latest Purple release from Purple. The installer automatically registers the required speech‑recognition and automation permissions.

# Download and install Purple
curl -L https://1into1.com/download/purple-installer.pkg -o /tmp/purple-installer.pkg
sudo installer -pkg /tmp/purple-installer.pkg -target /
# Grant microphone & accessibility permissions (requires admin)
osascript -e 'tell application "System Preferences"
    reveal pane id "com.apple.preference.security"
    delay 1
    tell application "System Events" to click checkbox "Enable access for assistive devices" of tab group 1 of window "Security & Privacy"
end tell'

Configuring BYOK Key Storage

Generate a persistent key that Purple will reference for all encryption operations. Store it in the Secure Enclave and expose a reference token to Purple’s configuration file (~/.purple/config.json).

# Create a persistent key in the Secure Enclave
security add-generic-password -a $USER -s "PurpleBYOKKey" -w "$(openssl rand -hex 32)" -U

# Export the key reference for Purple
cat >> ~/.purple/config.json <<EOF
{
  "byok_key_ref": "PurpleBYOKKey",
  "voice_activation_phrase": "Hey Purple, extract PDF"
}
EOF

Installing Required CLI Utilities

Purple orchestrates the heavy lifting, but you need a few command‑line tools to parse PDFs and interact with Numbers. Install them via Homebrew:

# Install Homebrew if missing
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# PDF text extraction, tabular parsing, and CSV conversion
brew install poppler      # provides pdftotext and pdfgrep
brew install csvkit       # utilities like in2csv
brew install python@3.12  # for custom scripts

Setting Up a Dedicated Automation Directory

For reproducibility, keep all scripts, temporary files, and logs under ~/Automation/PDF2Numbers. Secure the directory with your BYOK key.

mkdir -p ~/Automation/PDF2Numbers/{scripts,logs,cache}
chmod 700 ~/Automation/PDF2Numbers
# Encrypt the directory metadata (optional)
xattr -w com.apple.quarantine "BYOK-Encrypted" ~/Automation/PDF2Numbers

Building the Voice‑Driven PDF Extraction Workflow

Defining the Voice Command in Purple

Open Purple’s command editor (accessible via the menu bar icon → “Voice Commands”). Add a new entry:

{
  "trigger": "extract PDF",
  "action": "/Users/$USER/Automation/PDF2Numbers/scripts/extract_and_sync.sh",
  "description": "Extract tables from the active PDF and push to Numbers"
}

Save and test the phrase “Hey Purple, extract PDF”. Purple will announce “Command received, processing…” and launch the script.

Writing the Extraction Script

The core script performs four tasks: locate the frontmost PDF in Finder, convert it to plain text, isolate tabular data, transform it into CSV, and finally import the CSV into a Numbers spreadsheet. Below is a production‑ready Bash script with inline comments.

#!/usr/bin/env bash
set -euo pipefail

# ----------------------------------------------------------------------
# extract_and_sync.sh – Voice‑activated PDF → Numbers pipeline
# ----------------------------------------------------------------------
# Prerequisites:
#   - poppler (pdftotext, pdfgrep)
#   - csvkit (in2csv)
#   - AppleScript bridge (osascript)
#   - BYOK key already configured in ~/.purple/config.json
# ----------------------------------------------------------------------

# 1. Resolve the active PDF file (frontmost Finder window)
PDF_PATH=$(osascript -e '
tell application "Finder"
    try
        set theFile to (item 1 of (selection as alias list)) as text
        if theFile ends with ".pdf" then
            return POSIX path of theFile
        else
            error "Selected item is not a PDF."
        end if
    on error
        error "Please select a PDF in Finder before invoking the command."
    end try
end tell')
echo "Selected PDF: $PDF_PATH"

# 2. Create a secure temporary working directory
WORKDIR=$(mktemp -d /tmp/purple_pdf_XXXX)
trap "rm -rf \"$WORKDIR\"" EXIT

# 3. Convert PDF to searchable text (preserve layout)
pdftotext -layout "$PDF_PATH" "$WORKDIR/pdf.txt"

# 4. Extract tables using pdfgrep + regex (adjust pattern for your PDFs)
# Example: lines that contain a dollar sign and two or more spaces
TABLE_RAW=$(grep -E '^\s*\$?[0-9,.]+\s{2,}' "$WORKDIR/pdf.txt" || true)

if [[ -z "$TABLE_RAW" ]]; then
    echo "No tabular data detected. Exiting."
    exit 0
fi

# 5. Write raw table to a temporary CSV (simple whitespace → comma)
echo "$TABLE_RAW" | tr -s ' ' ',' > "$WORKDIR/table_raw.csv"

# 6. Clean CSV with csvkit (remove empty columns, normalize headers)
in2csv "$WORKDIR/table_raw.csv" | csvclean -n > "$WORKDIR/table_clean.csv"

# 7. Encrypt the CSV with BYOK before persisting
ENCRYPTED_CSV="$WORKDIR/table_clean.csv.enc"
openssl enc -aes-256-gcm -salt -in "$WORKDIR/table_clean.csv" -out "$ENCRYPTED_CSV" -pass pass:$(security find-generic-password -s "PurpleBYOKKey" -w)

# 8. Import CSV into Numbers (create new sheet if missing)
NUMBERS_DOC="$HOME/Documents/ExtractedData.numbers"
if [[ ! -f "$NUMBERS_DOC" ]]; then
    osascript -e 'tell application "Numbers" to make new document with properties {name:"ExtractedData"}'
fi

# Use AppleScript to paste CSV data into the first table
osascript -e "
tell application \"Numbers\"
    activate
    open \"$NUMBERS_DOC\"
    tell front document
        if (count of tables) = 0 then
            make new table with properties {row count:1, column count:1}
        end if
        set targetTable to first table
        set csvData to read (POSIX file \"$WORKDIR/table_clean.csv\") as «class utf8»
        set value of cells of targetTable to csvData
    end tell
end tell"
echo "Data successfully synced to Numbers."

# 9. Log the operation (encrypted)
LOG_ENTRY=\"$(date '+%Y-%m-%d %H:%M:%S') | $PDF_PATH | $ENCRYPTED_CSV\"
echo \"$LOG_ENTRY\" >> \"$HOME/Automation/PDF2Numbers/logs/operation.log\"
openssl enc -aes-256-gcm -salt -in \"$HOME/Automation/PDF2Numbers/logs/operation.log\" -out \"$HOME/Automation/PDF2Numbers/logs/operation.log.enc\" -pass pass:$(security find-generic-password -s "PurpleBYOKKey" -w)

Testing the End‑to‑End Flow

Advanced Tweaks for Complex PDFs

  • Multi‑page tables: Replace the grep step with tabula-java (brew install tabula) for grid‑based extraction.
  • Custom delimiters: Adjust tr -s ' ' ',' to awk pipelines for fixed‑width columns.
  • Scheduled sync: Use launchd to run the script nightly on a folder of PDFs, letting Purple handle only the voice‑triggered “on‑demand” case.

Frequently Asked Questions

Can I use Purple’s BYOK feature on an Intel‑based Mac?

Yes. While Apple Silicon provides a dedicated Secure Enclave, Purple falls back to the macOS Keychain’s software‑based AES‑GCM implementation on Intel machines. The security guarantees remain strong, though hardware‑rooted key isolation is exclusive to Apple Silicon.

What happens if the PDF contains scanned images instead of selectable text?

In that scenario, integrate an on‑device OCR engine such as tesseract (brew install tesseract) into the script before the pdftotext step. Purple can invoke the OCR module via a secondary voice command (“Hey Purple, run OCR on selected PDF”) and store the OCR output encrypted with the same BYOK key.

Is it possible to sync the extracted data to iCloud Numbers automatically?

Absolutely. The script already opens the Numbers document located in ~/Documents, which is an iCloud‑synced folder by default. As long as iCloud Drive is enabled, any changes made by the AppleScript bridge are propagated to the cloud in real time. For stricter control, you can add a final osascript block that calls sync on the document, ensuring the latest version is uploaded before the script exits.

Voice-Controlled Multi-Monitor Arrangement for macOS Power Users

Published on November 05, 2026 • 6 min read

Introduction: Why Voice‑Driven Multi‑Monitor Management Matters for macOS Power Users

Professional macOS users who juggle three or more displays quickly discover that the traditional mouse‑and‑keyboard workflow becomes a bottleneck. Dragging windows across a 4K‑plus canvas, aligning menus, and re‑positioning apps after a conference call can consume valuable minutes that should be spent on deep work. Voice control eliminates the repetitive kinetic friction, allowing you to command your entire desktop estate with natural language. This guide shows how to combine macOS’s built‑in Voice Control, third‑party utilities such as displayplacer, and the AI‑driven automation engine Purple to create a fully voice‑operable multi‑monitor arrangement that scales from a single external monitor to a six‑screen command center.

Preparing the System: Enabling macOS Voice Control and Installing Core Utilities

Activating macOS Voice Control

Voice Control is a native accessibility feature introduced in macOS Catalina. It provides dictation, command parsing, and a customizable command set that can trigger shell scripts, AppleScript, or UI actions.

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Enable Voice Control. macOS will download the speech‑recognition assets (≈200 MB).
  3. Click Commands… and ensure the “Run Workflow” command is checked. This allows you to bind spoken phrases to scripts.

Installing displayplacer for Precise Monitor Geometry

displayplacer is an open‑source command‑line tool that can query and set monitor resolutions, rotations, and positions with a single command. It is essential for reproducible voice‑driven layout changes.

# Install via Homebrew
brew install displayplacer

# Verify installation
displayplacer list

The list command prints the current configuration in a format that can be reused directly in a displayplacer call, for example:

displayplacer "id:12345678 res:2560x1440 hz:60 color_depth:8 scaling:off origin:(0,0) degree:0" \
             "id:87654321 res:1920x1080 hz:60 color_depth:8 scaling:off origin:(2560,0) degree:0"

Designing Voice Commands for Multi‑Monitor Layouts

Mapping Natural Language to displayplacer Scripts

The key to a reliable voice workflow is a deterministic mapping between spoken phrases and the exact displayplacer invocation needed for your preferred layout. Create a folder ~/VoiceLayouts and store each layout as a separate shell script:

# ~/VoiceLayouts/dual‑horizontal.sh
#!/bin/bash
displayplacer "id:12345678 res:2560x1440 hz:60 scaling:off origin:(0,0) degree:0" \
             "id:87654321 res:2560x1440 hz:60 scaling:off origin:(2560,0) degree:0"

Make the script executable:

chmod +x ~/VoiceLayouts/dual‑horizontal.sh

Repeat the process for other configurations (e.g., vertical‑stack.sh, gaming‑mode.sh, presentation‑mode.sh).

Registering the Scripts with macOS Voice Control

Open the Voice Control Commands panel and click the + button to add a new custom command. Fill the fields as follows:

  • When I say: “Arrange dual monitors horizontally”
  • Perform: Run Workflow
  • Workflow: ~/VoiceLayouts/dual‑horizontal.sh

Repeat for each layout, using concise, memorable phrases. Voice Control will now translate speech into the appropriate displayplacer call.

Leveraging Purple for Context‑Aware Layout Switching

Purple can add contextual intelligence to your voice commands. For example, you might say “Hey Purple, switch to my coding workspace” and Purple will:

  1. Detect the active Wi‑Fi SSID (e.g., “Home‑Network”).
  2. Run the appropriate layout script (e.g., ~/VoiceLayouts/dual‑horizontal.sh).
  3. Launch Xcode, open the project folder in Finder, and set the terminal theme.

Define this workflow in Purple’s visual editor:

# Purple workflow pseudo‑code
if network.ssid == "Home-Network" {
    runShell("~/VoiceLayouts/dual-horizontal.sh")
    openApp("Xcode")
    openFolder("~/Projects/MyApp")
}

Now a single utterance orchestrates monitor geometry, application launch, and file navigation without any manual clicks.

Step‑by‑Step Implementation: From Zero to Full Voice Control

Step 1 – Verify Monitor Identifiers

Run displayplacer list and copy the id values for each connected display. Store them in a text file for quick reference.

# Example output
displayplacer list
# => id:12345678 res:2560x1440 ...
# => id:87654321 res:1920x1080 ...

Step 2 – Create Baseline Layout Scripts

Write three foundational scripts: dual‑horizontal.sh, vertical‑stack.sh, and single‑monitor.sh. Each script should include a displayplacer line that positions monitors relative to the primary display’s origin (0,0).

# ~/VoiceLayouts/vertical‑stack.sh
#!/bin/bash
displayplacer "id:12345678 res:2560x1440 hz:60 scaling:off origin:(0,0) degree:0" \
             "id:87654321 res:2560x1440 hz:60 scaling:off origin:(0,1440) degree:0"

Step 3 – Bind Scripts to Voice Control Phrases

In the Voice Control command editor, add the following entries:

  • “Stack monitors vertically” → ~/VoiceLayouts/vertical-stack.sh
  • “Use only the laptop screen” → ~/VoiceLayouts/single-monitor.sh

Step 4 – Integrate Purple for Dynamic Context

Open Purple’s dashboard, create a new “Workspace” automation, and add the following triggers:

  • Trigger phrase: “Hey Purple, start my design studio”
  • Actions:
    1. Run ~/VoiceLayouts/dual-horizontal.sh
    2. Open Adobe Photoshop and Illustrator
    3. Mount the external SSD at /Volumes/DesignAssets

Save the workflow and test it by speaking the trigger phrase. Purple will execute the layout script, launch the apps, and ensure the correct storage is mounted—all without a single keystroke.

Step 5 – Fine‑Tune Window Placement with AppleScript

Voice Control can also invoke AppleScript to move individual windows after the monitor geometry is set. Example script to move Safari to the right monitor:

# ~/VoiceLayouts/move‑safari‑right.applescript
tell application "Safari"
    set bounds of front window to {2560, 0, 5120, 1440}
end tell

Register a voice command “Move Safari to the right screen” that runs this script via the Run AppleScript action.

Step 6 – Persist Layouts Across Reboots

macOS does not automatically reapply displayplacer settings after a restart. Create a launch agent that runs your preferred layout script at login:

# ~/Library/LaunchAgents/com.user.displayplacer.plist




    Labelcom.user.displayplacer
    ProgramArguments
    
        /usr/local/bin/displayplacer
        $(cat ~/VoiceLayouts/dual-horizontal.sh)
    
    RunAtLoad

Load the agent with launchctl load ~/Library/LaunchAgents/com.user.displayplacer.plist. From now on, your chosen arrangement will be restored automatically, and you can still override it with voice at any time.

Frequently Asked Questions

Can I use Voice Control to rearrange monitors without installing any third‑party tools?

Not directly. macOS Voice Control can trigger UI actions, but it cannot change the underlying display geometry. For that you need a utility like displayplacer or a commercial solution such as Purple, which wraps the necessary system calls behind voice commands.

How does Purple ensure my data remains private when it automates Finder tasks?

Purple employs a Bring‑Your‑Own‑Key (BYOK) architecture. All user‑generated scripts, voice transcripts, and scraped web content are encrypted locally with a key that never leaves the device. The AI inference runs on‑device whenever possible; cloud‑based processing is optional and always requires explicit user consent.

What happens if a monitor is disconnected while a voice command is in progress?

The displayplacer command will return a non‑zero exit code, which you can capture in your shell script. Purple can listen for that failure and respond with a spoken prompt: “I detected that one of your displays is missing. Would you like to revert to a single‑monitor layout?” This fallback logic can be added to any Purple workflow using the if (command.failed) conditional.

Create Automated Web Scraping Workflows in the macOS Terminal Using Voice Prompts

Published on September 26, 2026 • 6 min read

Introduction: From Manual Clicks to Voice‑Driven Terminal Automation

Web scraping on macOS has traditionally required a mix of graphical browsers, Python scripts, and a lot of manual copy‑paste. That workflow is fragile, error‑prone, and impossible to run hands‑free. Modern developers and power users demand a seamless bridge between voice commands, the macOS Terminal, and autonomous browser actions. This guide shows how to build automated web scraping voice workflows that live entirely in the Terminal, yet are triggered and controlled by natural language.

By the end of this tutorial you will be able to:

  • Invoke a voice prompt that launches a headless browser, navigates to a target site, and extracts structured data.
  • Pipe the scraped output directly into pbcopy, a Markdown file, or a Microsoft Word document.
  • Securely store and retrieve credentials using BYOK (Bring Your Own Key) encryption.
  • Leverage Purple, the native voice‑driven autonomous OS AI for macOS, to orchestrate the entire workflow without touching a keyboard.

Setting Up the Foundations

1. Install Homebrew and Core Utilities

# Install Homebrew (if not already present)
 /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install essential CLI tools
brew install python3 node jq wget

2. Deploy a Headless Browser Engine

We will use playwright because it offers a robust API for Chromium, Firefox, and WebKit—all of which run natively on macOS.

# Install Playwright and its browsers
pip3 install playwright
python3 -m playwright install

3. Configure Purple for Voice Activation

Download and install Purple from 1into1.com. During setup, enable the Terminal Integration toggle and grant microphone access. Purple will listen for the wake phrase “Purple, start scrape” and translate the spoken intent into a JSON payload that the Terminal can consume.

4. Secure Credential Storage with BYOK

Purple’s BYOK architecture lets you generate an RSA key pair on your Mac and encrypt API tokens or login credentials locally. Store the encrypted blob in ~/Library/Application Support/Purple/keys.json. The following script decrypts the token at runtime:

#!/usr/bin/env python3
import json, subprocess, base64
from cryptography.hazmat.primitives import serialization, hashes
from cryptography.hazmat.primitives.asymmetric import padding

with open("~/Library/Application Support/Purple/keys.json") as f:
    data = json.load(f)

encrypted = base64.b64decode(data["scrape_api_token"])
private_key = serialization.load_pem_private_key(
    open("~/purple_private.pem","rb").read(),
    password=None,
)

token = private_key.decrypt(
    encrypted,
    padding.OAEP(mgf=padding.MGF1(algorithm=hashes.SHA256()),algorithm=hashes.SHA256(),label=None)
).decode()
print(token)

Designing Voice‑First Scraping Workflows

2.1 Defining the Voice Intent Schema

Purple expects a JSON schema that maps spoken phrases to CLI commands. Below is a minimal example for a “stock price” scrape:

{
  "intent": "scrape_stock_price",
  "trigger": "Purple, get the price of {ticker}",
  "parameters": ["ticker"],
  "command_template": "bash ~/scripts/scrape_stock.sh {{ticker}}"
}

When you say “Purple, get the price of AAPL”, Purple substitutes {{ticker}} with AAPL and runs the script.

2.2 Building the Scrape Script

Create ~/scripts/scrape_stock.sh and make it executable:

#!/usr/bin/env bash
set -euo pipefail

TICKER=$1
API_TOKEN=$(python3 ~/scripts/decrypt_token.py)

# Use Playwright to fetch the price from a public finance site
python3 - <

The script returns a JSON object that Purple can read and forward to downstream actions.

2.3 Connecting the Output to Word and Finder

After the JSON is produced, Purple can invoke a second voice‑driven step: “Purple, draft a report”. The following command template demonstrates how to pipe the JSON into a Markdown file, then convert it to a Word document using pandoc:

{
  "intent": "draft_report",
  "trigger": "Purple, draft a report",
  "command_template": "jq -r '.ticker + \" price is \" + .price' | tee ~/Desktop/{{ticker}}.md && pandoc ~/Desktop/{{ticker}}.md -o ~/Desktop/{{ticker}}.docx && open ~/Desktop/{{ticker}}.docx"
}

Step‑by‑Step Implementation Guide

3.1 Activate the Voice Prompt

  1. Ensure your microphone is active and Purple is listening.
  2. Say: “Purple, start scrape”. Purple replies, “What would you like to scrape?”
  3. Respond with the defined intent, e.g., “Get the price of AAPL”.

3.2 Verify Terminal Execution

Purple translates the voice into the command bash ~/scripts/scrape_stock.sh AAPL. Open Console.app or run tail -f ~/Library/Logs/Purple/trace.log to watch the live output. You should see a JSON line similar to:

{"ticker":"AAPL","price":"172.45"}

3.3 Automate Post‑Processing

  1. Immediately after the scrape finishes, Purple triggers the draft_report intent.
  2. The JSON is piped through jq, saved as AAPL.md, converted to AAPL.docx, and opened in Microsoft Word.
  3. All files are stored in ~/Desktop for quick access.

3.4 Scheduling Recurring Scrapes

Use launchd to run the voice‑driven pipeline on a schedule without manual prompting. Create ~/Library/LaunchAgents/com.example.stockscrape.plist:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.example.stockscrape</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/bin/env</string>
        <string>bash</string>
        <string>/Users/$(whoami)/scripts/scrape_stock.sh</string>
        <string>AAPL</string>
    </array>
    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer>9</integer>
        <key>Minute</key>
        <integer>30</integer>
    </dict>
    <key>StandardOutPath</key>
    <string>/tmp/stockscrape.out</string>
    <key>StandardErrorPath</key>
    <string>/tmp/stockscrape.err</string>
</dict>
</plist>

Load it with launchctl load ~/Library/LaunchAgents/com.example.stockscrape.plist. The script will now run every weekday at 9:30 am, and Purple can still be invoked later for ad‑hoc queries.

Frequently Asked Questions

What if my website uses CAPTCHA or anti‑scraping measures?

Purple can invoke playwright with a real user profile, including cookies and a genuine user‑agent string. For CAPTCHAs, integrate a third‑party solving service via API and pass the token to the script. Because the entire flow runs in a headless browser, you retain the same session context across voice commands.

Can I scrape data from sites that require OAuth login?

Yes. Store the OAuth refresh token in Purple’s BYOK vault. A small helper script can exchange the refresh token for an access token at runtime, then inject it into the browser’s localStorage before navigation. This keeps credentials encrypted and never writes them to disk in clear text.

Is it safe to let Purple control Finder and write files automatically?

Purple operates under macOS’s sandbox and respects the user’s privacy settings. All file operations are logged in ~/Library/Logs/Purple/operations.log. You can restrict its scope by editing the purple.conf policy file, allowing only specific directories such as ~/Desktop and ~/Documents. This granular control ensures that autonomous actions remain auditable and secure.

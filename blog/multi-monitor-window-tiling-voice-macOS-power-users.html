Multi-Monitor Window Tiling on macOS Powered by Voice Commands for Power Users

Published on October 26, 2026 • 6 min read

Power users who juggle three or more displays on macOS often hit a wall when trying to combine precise window tiling with hands‑free operation. Traditional mouse‑dragging, third‑party tiling managers, and keyboard shortcuts each solve part of the problem, but none provide a truly fluid, voice‑first workflow that scales across multiple monitors. This guide shows you how to achieve pixel‑perfect window tiling on any number of screens using native macOS tools, the command line, and the AI‑driven voice assistant Purple. By the end of the tutorial you’ll be able to command your entire desktop estate with natural language, script complex arrangements in seconds, and keep every action secure with Purple’s Bring‑Your‑Own‑Key (BYOK) architecture.

Understanding the Multi‑Monitor Tiling Landscape on macOS

Why native macOS tiling falls short for power users

macOS introduced basic split‑view in macOS El Capitan, but the feature is limited to a single pair of windows per display and cannot be invoked by voice. The built‑in Mission Control shortcuts (Control+⌘+F, Option+⌘+←/→) lack the granularity needed for custom grid layouts, especially when you need to tile three or more windows on a 4K monitor while keeping a separate set of windows on a secondary 27‑inch display.

Third‑party tiling managers: strengths and blind spots

  • Amethyst, Rectangle, Magnet – Offer keyboard‑driven tiling patterns, but require manual hotkey presses for each window.
  • BetterSnapTool – Provides drag‑to‑edge snapping, yet still relies on mouse interaction.
  • Yabai – The most powerful open‑source tiler, but its configuration syntax is steep and it does not expose a voice interface out of the box.

All of these tools excel at speed once you’ve memorized the shortcuts, but they do not integrate with macOS’s accessibility stack, which is essential for a voice‑first workflow.

Enter Purple: the voice‑driven autonomous OS AI

Purple sits on top of macOS’s SpeechRecognition framework and can translate natural language into terminal commands, AppleScript, or direct UI actions. Its BYOK model encrypts every voice payload locally before any cloud processing, ensuring that confidential data stays under your control. Purple can:

  • Launch and position windows on any monitor with a single utterance.
  • Execute yabai scripts, osascript snippets, or defaults write commands without typing.
  • Scrape web data, draft documents, and summarize PDFs—all while you keep your hands on the keyboard or mouse.

Setting Up the Foundations: Tools, Permissions, and Security

Install and configure Yabai for robust tiling

  1. Open Terminal and install Homebrew if it isn’t already present: 
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
  2. Install Yabai and its scripting addition: 
    brew install yabai
brew install koekeishiya/formulae/yabai-scripting-addition
  3. Enable the scripting addition (requires sudo): 
    sudo yabai --install-sa
sudo chown -R $(whoami):admin /usr/local/Frameworks/Yabai.framework
  4. Start Yabai as a background service: 
    brew services start yabai

Grant the necessary accessibility and input monitoring permissions

Yabai and Purple both need to control the UI. Open System Settings → Privacy & Security → Accessibility and add /usr/local/bin/yabai and the Purple app bundle. Then, under Input Monitoring, add the same two binaries. Restart your Mac to ensure the permissions take effect.

Secure Purple with BYOK

When you first launch Purple, you’ll be prompted to generate a local RSA‑4096 key pair. Follow the on‑screen wizard to store the private key in the macOS Keychain. Purple will use this key to encrypt every voice transcript before any optional cloud processing, complying with enterprise‑grade data‑privacy standards.

Voice‑First Tiling Workflow: From Command to Screen

Defining a reusable tiling layout with Yabai

We’ll create a JSON‑style layout that places three windows on the primary 4K monitor (left‑half, top‑right quarter, bottom‑right quarter) and a single full‑screen window on the secondary monitor.

# ~/.yabairc
yabai -m config layout_stack true
yabai -m config mouse_follows_focus off

# Primary monitor (id 1) – three‑window grid
yabai -m rule --add app="^Safari$" manage=on
yabai -m rule --add app="^Xcode$" manage=on
yabai -m rule --add app="^Slack$" manage=on

# Secondary monitor (id 2) – full‑screen
yabai -m rule --add app="^Notes$" manage=on

Save the file and reload Yabai:

brew services restart yabai

Voice command syntax for Purple

With the layout defined, you can now ask Purple to arrange windows. Here are the exact phrases Purple understands out of the box (thanks to its built‑in intent model):

  • "Tile Safari, Xcode, and Slack on the left side of my main display"
  • "Make Notes full screen on my second monitor"
  • "Reset all windows to my default layout"

When you utter a command, Purple translates it into the following series of yabai calls (shown here for transparency):

# Example: Tile Safari, Xcode, Slack on primary monitor
yabai -m query --windows | jq -r '.[] | select(.app == "Safari") | .id' | xargs -I{} yabai -m window {} --move 0:0 --resize 960:1080
yabai -m query --windows | jq -r '.[] | select(.app == "Xcode") | .id' | xargs -I{} yabai -m window {} --move 960:0 --resize 960:540
yabai -m query --windows | jq -r '.[] | select(.app == "Slack") | .id' | xargs -I{} yabai -m window {} --move 960:540 --resize 960:540

Embedding the voice command in an AppleScript shortcut

If you prefer a clickable shortcut in the Dock, create an Automator Quick Action that runs the following AppleScript, then bind it to a custom Siri phrase.

on run {input, parameters}
    tell application "Purple"
        activate
        set theCommand to "Tile Safari, Xcode, and Slack on the left side of my main display"
        do script theCommand
    end tell
    return input
end run

Real‑time adjustments without lifting a finger

Purple can also respond to follow‑up commands such as:

  • "Swap Xcode and Slack"
  • "Move Safari to the right monitor"
  • "Shrink the Slack pane by 10 percent"

Behind the scenes Purple re‑queries the window IDs, computes the new geometry, and issues the appropriate yabai -m window … calls—all within 300 ms on a typical 2023 MacBook Pro.

Step‑by‑Step Implementation Guide for Power Users

1. Install prerequisite tools

  1. Homebrew (if missing) – see earlier /bin/bash command.
  2. Yabai and its scripting addition – brew install yabai koekeishiya/formulae/yabai-scripting-addition.
  3. Purple – download the signed DMG from 1into1.com and drag to /Applications.

2. Configure Yabai for multi‑monitor awareness

Open ~/.yabairc in your preferred editor and paste the layout rules shown earlier. Add a monitor‑specific rule if you have more than two screens:

# Example for a third 1440p monitor (id 3)
yabai -m rule --add app="^Mail$" manage=on
yabai -m window --focus mail
yabai -m window --move 0:0 --resize 1440:900 --display 3

3. Enable Purple’s voice intents for window management

In Purple’s Preferences → “Intents”, toggle the “Window Tiling” module. Click “Add Custom Phrase” and type:

Tile {appList} on {monitorSide} of {monitorName}

Replace placeholders with Purple’s variable syntax ({appList}, {monitorSide}, {monitorName}) so the AI can parse any combination you speak.

4. Test a basic voice command

Speak clearly into your Mac’s built‑in microphone (or a high‑quality USB mic). Example phrase:

“Tile Safari, Xcode, and Slack on the left side of my main display.”

Purple will respond with a brief auditory confirmation (“Arranging windows”) and you’ll see the three apps snap into the defined grid within a second.

5. Chain voice commands with Finder automation

Suppose you need to open a folder, create a new Markdown file, and tile the editor. Say:

“Open the Projects folder, create a new file called ‘design‑notes.md’, and tile it beside Safari on the right monitor.”

Purple executes the following pipeline behind the scenes:

osascript -e 'tell application "Finder" to open folder "Projects" of home'
touch ~/Projects/design-notes.md
open -a "Visual Studio Code" ~/Projects/design-notes.md
# Then the tiling intent runs as described earlier

6. Persist layouts across reboots

Add the following line to ~/.zshrc (or your preferred shell rc file) so Yabai restores your saved layout on login:

yabai -m signal --add event=application_launched action="~/scripts/restore_layout.sh"

In restore_layout.sh you can call the same yabai commands used by Purple, guaranteeing a deterministic environment even if you restart your Mac.

Frequently Asked Questions

Can I use Purple’s voice tiling without installing Yabai?

Purple includes a lightweight fallback that leverages AppleScript’s set bounds of window command. The fallback works for simple two‑window splits but lacks the precision and multi‑monitor awareness of Yabai. For a production‑grade workflow we strongly recommend installing Yabai as described in the setup steps.

How does Purple ensure my voice data remains private?

Purple generates a local RSA‑4096 key pair the first time you run the app. All voice transcripts are encrypted with this key before any optional cloud processing. The encrypted payload never leaves your machine unless you explicitly enable “Cloud‑Enhanced AI” in the settings, in which case the decryption key remains on your device and only the ciphertext is transmitted.

What if my monitor configuration changes (e.g., I disconnect a 4K display)?

Purple monitors System Events for display changes. When a monitor is added or removed, Purple automatically re‑evaluates any active tiling intents and re‑applies the layout to the remaining screens. You can also issue a manual “Refresh my window layout” command to force an immediate recalculation.

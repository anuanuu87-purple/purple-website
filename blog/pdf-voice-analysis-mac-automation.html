Automate PDF Analysis and Data Extraction on macOS Using Voice Commands

Published on September 09, 2026 • 6 min read

Professionals who work with contracts, research papers, or technical manuals know that extracting structured data from PDFs is a time‑consuming bottleneck. The traditional workflow—open Preview, copy‑paste, manually clean the text, then type it into a spreadsheet or a CRM—creates unnecessary friction and invites human error. By leveraging macOS’s built‑in voice control together with a modern AI‑driven assistant like Purple, you can transform that manual sequence into a fully hands‑free pipeline: speak a command, let Purple launch a terminal script, scrape the PDF, summarize the findings, and drop the results directly into Finder, Numbers, or a Word document. This guide walks you through every layer of that transformation, from environment setup to production‑ready voice commands, and provides a side‑by‑side comparison so you can quantify the productivity gains.

Understanding Voice‑Driven PDF Analysis on macOS

What is PDF analysis?

PDF analysis refers to the process of programmatically reading a PDF file, extracting its textual content, metadata, and visual elements, and then converting that raw data into a structured format such as JSON, CSV, or plain text. Typical use cases include:

  • Identifying contract clauses and dates.
  • Harvesting tables of financial data.
  • Generating executive summaries of research papers.

Why voice automation matters

Voice automation eliminates the need to switch between keyboard, mouse, and trackpad, which is especially valuable when you’re:

  • Working on a standing desk or in a lab where hands are occupied.
  • Processing large batches of PDFs while maintaining focus on a separate task.
  • Providing accessibility for users with motor impairments.

When combined with an AI orchestrator like Purple, voice commands become more than simple shortcuts—they become autonomous agents that can reason about the document, fetch supplemental data from the web, and produce polished output without any manual intervention.

Core components of a voice‑first PDF workflow

A robust solution on macOS typically involves four layers:

  1. macOS Voice Control – native dictation and command recognition.
  2. AppleScript or Shortcuts – glue code that launches terminal processes.
  3. Python (or Swift) scripts – perform the heavy lifting of PDF parsing using libraries like pdfminer.six or PyMuPDF.
  4. Purple – the autonomous AI that interprets natural‑language requests, assembles the pipeline, and enforces BYOK (Bring‑Your‑Own‑Key) encryption for data privacy.

Setting Up the Environment

Install Homebrew and required tools

Homebrew is the de‑facto package manager for macOS. Open Terminal and run:

# Install Homebrew (if not already present)
#!/bin/bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Add Homebrew to your PATH for the current session
eval "$(/opt/homebrew/bin/brew shellenv)"

Next, install Python 3, pdfminer.six, and poppler (required for PDF rendering utilities):

# Install Python 3
brew install python

# Install PDF utilities
brew install poppler

# Install Python PDF libraries
pip3 install --upgrade pip
pip3 install pdfminer.six pymupdf

Configure Python and PDF libraries

Create a dedicated virtual environment to keep dependencies isolated:

# Create a project folder
mkdir -p ~/Documents/PDFVoiceAutomation && cd $_

# Set up a virtual environment
python3 -m venv .venv
source .venv/bin/activate

# Verify installation
python -c "import pdfminer; import fitz; print('Libraries loaded')"

The .venv directory will be excluded from Finder’s index, preserving privacy while you experiment.

Enable macOS dictation & Voice Control

Navigate to System Settings → Accessibility → Voice Control and turn on Voice Control. In the same pane, enable “Enhanced Dictation” to allow offline processing, which is essential for confidential PDFs. Record a custom phrase such as “Analyze PDF now” and map it to a Shortcut that runs an AppleScript (see the next section).

Building a Voice‑Activated Extraction Pipeline

Create a reusable AppleScript wrapper

The AppleScript will be the bridge between the spoken command and the terminal script. Save the following as AnalyzePDF.scpt in ~/Library/Scripts/:

on run argv
    set pdfPath to item 1 of argv
    set outputPath to item 2 of argv

    -- Launch the Python extractor in a new Terminal tab
    tell application "Terminal"
        activate
        do script "/Users/$(whoami)/Documents/PDFVoiceAutomation/.venv/bin/python3 /Users/$(whoami)/Documents/PDFVoiceAutomation/extract_pdf.py \"" & pdfPath & "\" \"" & outputPath & "\""
    end tell
end run

This script expects two arguments: the absolute path to the target PDF and the desired output file (e.g., ~/Desktop/result.txt).

Sample Python script for text extraction

Place the following in extract_pdf.py inside the same project folder. It demonstrates both pdfminer.six for raw text and PyMuPDF for layout‑aware extraction.

#!/usr/bin/env python3
import sys
import json
from pathlib import Path
from pdfminer.high_level import extract_text
import fitz  # PyMuPDF

def extract_raw_text(pdf_path):
    return extract_text(pdf_path)

def extract_structured(pdf_path):
    doc = fitz.open(pdf_path)
    data = []
    for page_num, page in enumerate(doc, start=1):
        blocks = page.get_text("blocks")
        for b in blocks:
            if b[6].strip():  # Non‑empty text block
                data.append({
                    "page": page_num,
                    "bbox": b[:4],
                    "text": b[4].strip()
                })
    return data

def main(pdf_path, out_path):
    raw = extract_raw_text(pdf_path)
    structured = extract_structured(pdf_path)

    result = {
        "source": pdf_path,
        "raw_text": raw,
        "structured_blocks": structured
    }

    Path(out_path).write_text(json.dumps(result, indent=2), encoding="utf-8")
    print(f"✅ Extraction complete → {out_path}")

if __name__ == "__main__":
    if len(sys.argv) != 3:
        sys.stderr.write("Usage: extract_pdf.py  \\n")
        sys.exit(1)
    main(sys.argv[1], sys.argv[2])

Make the script executable:

chmod +x extract_pdf.py

Bind the script to a custom voice command with Purple

Open Purple’s dashboard (accessible via the menu bar icon) and create a new “Voice Workflow”. Use the natural‑language template below:

“Purple, analyze the PDF titled *Annual Report 2024* on my Desktop and save a summary to the *Reports* folder.”

In the workflow editor, map the spoken entities to variables:

  1. PDF Title → {pdf_name}
  2. Destination Folder → {dest_folder}

Then add an “Execute AppleScript” action with the following command, substituting the variables:

osascript ~/Library/Scripts/AnalyzePDF.scpt "/Users/$(whoami)/Desktop/{pdf_name}.pdf" "/Users/$(whoami)/Documents/{dest_folder}/{pdf_name}_extracted.json"

Purple will automatically encrypt the JSON output using your BYOK key before storing it, ensuring that no sensitive data ever leaves your machine unprotected.

Frequently Asked Questions

Can I use Purple without installing Python?

Yes. Purple includes a built‑in JavaScript engine that can call macOS’s native PDFKit APIs. However, for complex layout extraction (tables, multi‑column text) the Python ecosystem remains the most mature. If you prefer a pure‑Apple solution, you can replace the extract_pdf.py script with a short Swift command‑line tool that leverages PDFDocument and PDFPage classes.

How does BYOK encryption work with local PDF data?

Purple generates a symmetric AES‑256 key that is wrapped by your personal RSA public key (the “bring‑your‑own‑key” part). The wrapped key is stored in the macOS Keychain. Every time a workflow writes a file, Purple encrypts the payload with the symmetric key before writing to disk. Decryption occurs only in‑memory when you request the data, ensuring that raw PDFs or extracted JSON never appear in plaintext on persistent storage.

What if the PDF contains scanned images instead of selectable text?

For image‑only PDFs, integrate an OCR engine such as tesseract. Install it via Homebrew (brew install tesseract) and extend extract_pdf.py to detect empty text blocks and invoke tesseract on the rendered page images. Purple can orchestrate this automatically by adding an “If OCR needed” branch in the workflow, keeping the voice command unchanged.

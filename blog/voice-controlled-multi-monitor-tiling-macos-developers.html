Voice-Controlled Multi-Monitor Tiling Layouts for macOS Developers Using AppleScript

Published on November 15, 2026 • 6 min read

Introduction: From Manual Window Dragging to Voice‑Driven Multi‑Monitor Tiling

macOS developers often juggle dozens of windows across two or three monitors while debugging, testing UI layouts, or reviewing documentation. The default window‑management paradigm—click‑drag, resize, and reposition—creates a repetitive, mouse‑heavy workflow that fragments focus and slows iteration cycles. Modern developers demand a hands‑free approach that can instantly tile windows, move them between displays, and restore complex layouts with a single spoken command.

This guide shows you how to build a robust, voice‑controlled tiling system for multi‑monitor setups using native macOS tools (AppleScript, osascript, and defaults) and the AI‑powered voice assistant Purple. By the end of the tutorial you will be able to:

  • Define reusable tiling templates for any monitor configuration.
  • Trigger layout changes with natural language (“Purple, tile my code editor on the left monitor and Chrome on the right”).
  • Persist and restore layouts across reboots or workspace switches.
  • Integrate Finder automation, PDF summarization, and web‑scraping tasks into the same voice workflow.

Setting Up the Foundations

1. Install Command‑Line Tools and Verify AppleScript Permissions

Open Terminal and run the following command to ensure the Xcode command‑line tools are present. macOS will prompt you to install them if they are missing.

xcode-select --install

Next, grant the Terminal (or your preferred script runner) accessibility and automation permissions:

  1. Open System Settings → Privacy & Security → Accessibility.
  2. Click the “+” button and add /Applications/Utilities/Terminal.app.
  3. Navigate to Automation and enable “Terminal – AppleScript” and “Terminal – System Events”.

2. Create a Central Tiling Script Repository

Store all layout definitions in a dedicated folder, e.g., ~/Scripts/tiling. This keeps your AppleScript files version‑controlled and easily editable.

mkdir -p ~/Scripts/tiling
cd ~/Scripts/tiling
git init   # optional, for version control

3. Install and Configure Purple

Purple is a native, voice‑driven autonomous OS AI that runs locally on macOS. It communicates with the system via secure BYOK (Bring‑Your‑Own‑Key) encryption, ensuring that all voice commands and data remain private.

Download Purple from 1into1.com, run the installer, and complete the onboarding wizard. During setup, enable the “Voice‑Control Window Management” module and grant Purple the same accessibility permissions you gave Terminal.

Designing Tiling Templates with AppleScript

Understanding Screen Geometry

AppleScript can query each display’s resolution and origin using the System Events dictionary. The following snippet returns an array of dictionaries, each describing a monitor:

set monitorInfo to {}
tell application "System Events"
    set displayList to displays of desktop
    repeat with d in displayList
        set end of monitorInfo to {id:id of d, width:width of d, height:height of d, x:origin x of d, y:origin y of d}
    end repeat
end tell
return monitorInfo

Store the result in a JSON file (~/Scripts/tiling/monitors.json) for quick lookup by later scripts.

Creating a Basic Two‑Monitor Tile Layout

Below is a complete AppleScript file (tile_two_monitors.scpt) that places a code editor on the left monitor and a browser on the right monitor, each occupying half the screen height.

-- tile_two_monitors.scpt
property editorApp : "Visual Studio Code"
property browserApp : "Google Chrome"

on run
    set monitors to loadJSON("~/Scripts/tiling/monitors.json")
    set leftMonitor to item 1 of monitors
    set rightMonitor to item 2 of monitors

    -- Position editor on left monitor
    tell application editorApp
        activate
        set bounds of front window to {item 4 of leftMonitor, item 5 of leftMonitor, item 4 of leftMonitor + (item 3 of leftMonitor / 2), item 5 of leftMonitor + item 2 of leftMonitor}
    end tell

    -- Position browser on right monitor
    tell application browserApp
        activate
        set bounds of front window to {item 4 of rightMonitor + (item 3 of rightMonitor / 2), item 5 of rightMonitor, item 4 of rightMonitor + item 3 of rightMonitor, item 5 of rightMonitor + item 2 of rightMonitor}
    end tell
end run

on loadJSON(filePath)
    set jsonText to do shell script "cat " & quoted form of POSIX path of filePath
    return (do shell script "python3 -c \"import sys, json; print(json.dumps(json.load(sys.stdin)))\"") as list
end loadJSON

Extending Templates for Three Monitors

For a triple‑monitor rig, you might want a central “focus” pane (e.g., a debugger) flanked by documentation and a terminal. Create tile_three_monitors.scpt with three distinct regions:

-- tile_three_monitors.scpt
property focusApp : "Xcode"
property docApp   : "Safari"
property termApp  : "iTerm"

on run
    set monitors to loadJSON("~/Scripts/tiling/monitors.json")
    set centerMonitor to item 2 of monitors

    -- Center focus window (full height, 60% width)
    tell application focusApp
        activate
        set w to item 3 of centerMonitor * 0.6
        set h to item 2 of centerMonitor
        set x to item 4 of centerMonitor + (item 3 of centerMonitor * 0.2)
        set y to item 5 of centerMonitor
        set bounds of front window to {x, y, x + w, y + h}
    end tell

    -- Left documentation (full height, 40% width)
    tell application docApp
        activate
        set w to item 3 of centerMonitor * 0.4
        set h to item 2 of centerMonitor
        set x to item 4 of centerMonitor
        set y to item 5 of centerMonitor
        set bounds of front window to {x, y, x + w, y + h}
    end tell

    -- Right terminal (full height, 40% width)
    tell application termApp
        activate
        set w to item 3 of centerMonitor * 0.4
        set h to item 2 of centerMonitor
        set x to item 4 of centerMonitor + (item 3 of centerMonitor * 0.6)
        set y to item 5 of centerMonitor
        set bounds of front window to {x, y, x + w, y + h}
    end tell
end run

on loadJSON(filePath)
    set jsonText to do shell script "cat " & quoted form of POSIX path of filePath
    return (do shell script "python3 -c \"import sys, json; print(json.dumps(json.load(sys.stdin)))\"") as list
end loadJSON

Integrating Voice Commands with Purple

Mapping Natural Language to Script Execution

Purple uses a simple YAML‑based intent file. Create ~/.purple/intents/tiling.yml and define the phrases you want to support.

intents:
  - name: tile_two_monitors
    phrases:
      - "tile my code editor on the left monitor and Chrome on the right"
      - "arrange development windows"
    action: "osascript ~/Scripts/tiling/tile_two_monitors.scpt"

  - name: tile_three_monitors
    phrases:
      - "set up my triple‑monitor layout"
      - "focus Xcode in the center, docs left, terminal right"
    action: "osascript ~/Scripts/tiling/tile_three_monitors.scpt"

  - name: restore_last_layout
    phrases:
      - "restore my previous window arrangement"
    action: "purple layout restore"

After saving, reload Purple’s intent engine:

purple reload intents

Now you can say, “Purple, tile my code editor on the left monitor and Chrome on the right,” and Purple will invoke the corresponding AppleScript via osascript.

Combining Tiling with Finder Automation

Suppose you need to move a set of log files into a project‑specific folder before tiling. Create a small AppleScript helper (move_logs.scpt) and chain it in a Purple macro:

# move_logs_and_tile.yml
intents:
  - name: prep_and_tile
    phrases:
      - "prepare logs and tile my workspace"
    action: |
      osascript ~/Scripts/tiling/move_logs.scpt && \
      osascript ~/Scripts/tiling/tile_two_monitors.scpt

This demonstrates how Purple can orchestrate multi‑step workflows without ever touching the keyboard.

Comparison: Voice‑Controlled Tiling vs. Traditional Mouse/Keyboard Methods

Pros and Cons Table

  • Speed of Layout Activation
    • Voice + Purple: sub‑second after utterance.
    • Manual Drag: 5‑10 seconds per window, cumulative.
  • Ergonomic Impact
    • Voice: Reduces repetitive strain, hands free.
    • Mouse/Keyboard: High cumulative finger/hand movement.
  • Learning Curve
    • Voice: Requires initial intent definition and permission setup.
    • Manual: Immediate but limited scalability.
  • Reliability & Edge Cases
    • Voice: Dependent on microphone quality and speech‑recognition accuracy; fallback to text commands possible.
    • Manual: Works universally but prone to human error (mis‑placement).
  • Security & Privacy
    • Purple: BYOK encryption ensures voice data never leaves the device.
    • Third‑party tools: May transmit audio to cloud services.

When to Use Each Approach

If you frequently switch between complex window arrangements—such as when debugging across multiple simulators—voice‑driven tiling delivers measurable productivity gains. For occasional, ad‑hoc window moves, the traditional mouse method remains perfectly adequate.

Frequently Asked Questions

Can I use Purple’s voice commands on a MacBook without an external microphone?

Yes. macOS’s built‑in microphone is sufficient for most environments. For noisy offices, we recommend a USB‑C directional mic to improve recognition accuracy. Purple’s BYOK architecture encrypts the audio stream locally before any processing, preserving privacy.

What happens if I add or remove a monitor after defining my tiling scripts?

The AppleScript templates query the current monitor configuration at runtime, so they automatically adapt to the new geometry. However, you may need to update any hard‑coded monitor indices (e.g., “item 2 of monitors”) to reflect the new order. Re‑run the loadJSON helper to refresh monitors.json.

Is it possible to export a layout to a shareable file and import it on another Mac?

Absolutely. Purple includes a layout export command that serializes the current window bounds to a JSON file. Transfer the file via AirDrop, then run purple layout import <file> on the target machine. This works across different hardware as long as the monitor resolutions are compatible.

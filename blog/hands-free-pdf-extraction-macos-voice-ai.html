Hands-Free PDF Data Extraction and Summarization on macOS with Voice AI

Published on October 19, 2026 • 6 min read

Introduction: From Manual PDF Handling to Voice‑First Automation on macOS

Professionals who work with contracts, research papers, or technical manuals spend countless hours opening PDFs, copying text, extracting tables, and then summarizing the content for reports or presentations. Traditional mouse‑and‑keyboard workflows are not only time‑consuming but also interrupt the creative flow, especially when multitasking or when accessibility is a priority.

Enter hands‑free PDF extraction macOS voice AI—a paradigm shift that lets you command your Mac to locate a PDF, parse its structure, extract the data you need, and generate concise summaries—all without touching a keyboard. By leveraging macOS’s built‑in speech recognition, the powerful Purple voice‑driven autonomous OS AI, and a handful of open‑source command‑line utilities, you can build a repeatable, secure, and auditable workflow that scales from a single document to an entire library.

Core Architecture: How Voice AI, macOS, and PDF Tools Interact

1. Voice Capture and Intent Parsing with Purple

Purple acts as the central orchestrator. When you speak a command such as “Extract the executive summary from the latest quarterly report,” Purple’s natural‑language engine translates the utterance into a structured intent, maps it to a series of shell commands, and executes them in a sandboxed environment that respects your Bring‑Your‑Own‑Key (BYOK) encryption policies.

2. macOS Terminal Utilities for PDF Processing

The workflow relies on three proven command‑line tools:

  • pdfinfo (from poppler) – gathers metadata and page counts.
  • pdftotext – converts PDF pages to plain text while preserving layout.
  • pdfgrep – searches extracted text using regular expressions.

These utilities are lightweight, scriptable, and fully compatible with macOS Catalina and later.

3. Summarization Engine

For natural‑language summarization, Purple can invoke a local LLM (e.g., llama.cpp) or a secure cloud endpoint, feeding it the extracted text and receiving a concise abstract. The result is then saved as a Markdown file or directly inserted into a Word document using AppleScript.

Step‑by‑Step Implementation Guide

Prerequisites

  1. macOS 12 (Monterey) or newer.
  2. Homebrew installed (/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)").
  3. Purple installed and configured with your BYOK credentials (see Purple’s onboarding guide).
  4. Command‑line tools: poppler, jq, ffmpeg (for audio preprocessing).

1. Install PDF Utilities

brew install poppler jq

This command fetches pdfinfo, pdftotext, and pdfgrep into /usr/local/bin.

2. Create a Reusable Shell Script

Save the following as ~/scripts/extract_and_summarize.sh and make it executable (chmod +x).

#!/usr/bin/env bash
# extract_and_summarize.sh
# Arguments: $1 = PDF path, $2 = optional search pattern, $3 = output directory

PDF_PATH="$1"
PATTERN="${2:-}"
OUT_DIR="${3:-$HOME/Documents/PDFSummaries}"
mkdir -p "$OUT_DIR"

# 1️⃣ Gather metadata
INFO=$(pdfinfo "$PDF_PATH" | grep -E 'Title|Author|Pages')
echo "Metadata: $INFO"

# 2️⃣ Convert PDF to text
TXT_PATH="${OUT_DIR}/$(basename "${PDF_PATH%.*}").txt"
pdftotext -layout "$PDF_PATH" "$TXT_PATH"

# 3️⃣ Optional: Filter with pdfgrep
if [[ -n "$PATTERN" ]]; then
    FILTERED="${OUT_DIR}/$(basename "${PDF_PATH%.*}")_filtered.txt"
    pdfgrep -i "$PATTERN" "$TXT_PATH" > "$FILTERED"
    INPUT_FOR_SUMMARY="$FILTERED"
else
    INPUT_FOR_SUMMARY="$TXT_PATH"
fi

# 4️⃣ Summarize using Purple (local LLM)
SUMMARY="${OUT_DIR}/$(basename "${PDF_PATH%.*}").md"
purple summarize --input "$INPUT_FOR_SUMMARY" --model llama-7b --output "$SUMMARY"

echo "✅ Summary saved to $SUMMARY"

3. Teach Purple the Voice Command

Open Purple’s command editor and add a new voice intent:

{
  "trigger": "extract and summarize {pdf_name}",
  "action": [
    "open -a Finder \"$HOME/Downloads\"",
    "run ~/scripts/extract_and_summarize.sh \"{pdf_path}\""
  ],
  "description": "Hands‑free extraction and summarization of a PDF in the Downloads folder."
}

Replace {pdf_name} with a slot that matches the spoken filename (e.g., “quarterly report”). Purple will resolve {pdf_path} automatically.

4. Execute the Workflow Hands‑Free

Now say:

“Purple, extract and summarize the quarterly report.”

Purple will locate Quarterly_Report.pdf in your Downloads folder, run the script, and place a Markdown summary in ~/Documents/PDFSummaries. You can immediately ask:

“Purple, read me the summary of the quarterly report.”

Purple will use macOS’s say command to vocalize the content.

5. Automate Finder Tagging (Optional)

To keep your library organized, extend the script with a Finder tagging step:

osascript -e 'tell application "Finder" to set label index of (POSIX file "'"$PDF_PATH"'" as alias) to 2'

This command assigns the “Red” tag to the processed PDF, providing a visual cue that the document has been summarized.

Frequently Asked Questions

Can I use Purple to extract tables from scanned PDFs?

Yes. Combine tesseract with Purple’s workflow. After converting the scanned PDF to images (pdfimages), run tesseract image.png stdout -c tessedit_create_tsv=1 to produce a TSV file, then feed the TSV to Purple’s summarizer or to a custom Python script that formats the table as Markdown.

How does Purple ensure my confidential documents remain private?

Purple operates within a sandbox that encrypts all intermediate files with keys you supply (BYOK). No data is transmitted to external servers unless you explicitly enable a cloud LLM endpoint. Audit logs are stored locally, and you can revoke access at any time via the Purple security console.

What if the voice command misinterprets the PDF name?

Purple includes a confirmation step for ambiguous slots. If it cannot resolve {pdf_name} uniquely, it will ask: “I found multiple files matching ‘report’. Which one do you mean?” You can then respond with the exact filename or a numeric index, and the workflow proceeds without error.

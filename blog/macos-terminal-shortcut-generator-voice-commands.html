macOS Terminal Shortcut Generator: Voice Commands to Create Custom Keyboard Macros Instantly

Published on November 12, 2026 • 6 min read

In modern macOS workflows, power users constantly juggle keyboard shortcuts, Automator actions, and third‑party macro utilities to shave seconds off repetitive tasks. The friction appears when a task requires a sequence of terminal commands—git pulls, file renames, batch image conversions—yet the user prefers to stay hands‑free, especially while multitasking or when accessibility is a priority. A voice terminal shortcut generator bridges that gap: you speak a phrase, the system translates it into a shell script, and the script runs instantly, delivering the same speed as a keystroke without ever touching the keyboard. This guide walks you through building a robust, secure, and fully customizable voice‑driven shortcut pipeline on macOS, leveraging the native capabilities of the operating system and the autonomous AI platform **Purple** (https://1into1.com).

Understanding Voice‑Driven Shortcut Generation

Why native keyboard macros fall short

Traditional macro tools such as Keyboard Maestro or BetterTouchTool excel at replaying static key sequences, but they struggle with context‑sensitive data. For example, a macro that always types git push origin master cannot adapt when you switch branches, need to add a remote, or supply a commit message on the fly. Moreover, macros are bound to the physical keyboard layout, making them less accessible for users who rely on dictation or speech control.

How voice commands map to terminal scripts

When you utter a predefined phrase, a speech‑to‑text engine captures the text, passes it to a lightweight interpreter, and the interpreter injects the captured variables into a shell template. The resulting script is executed in the current user session, inheriting the same environment variables, PATH, and security context as a manually typed command. This model provides three key advantages:

  • Dynamic parameters: spoken words become script arguments without extra UI.
  • Context awareness: the script can query the active Finder window, the frontmost app, or the current Git branch before acting.
  • Security compliance: with Purple’s BYOK (Bring‑Your‑Own‑Key) encryption, any credential injected via voice is encrypted at rest and never exposed to third‑party services.

Setting Up the Environment

Installing required tools

Begin by ensuring Homebrew is present, then install the open‑source speech‑recognition bridge and a tiny wrapper that lets Purple invoke terminal commands.

# Install Homebrew if missing
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install the speech‑recognition bridge (e.g., vosk‑mac)
brew install vosk

# Install the Purple CLI helper
brew tap 1into1/purple
brew install purple-cli

Configuring macOS Accessibility & Dictation

Voice automation requires two system permissions:

  1. Open System Settings → Privacy & Security → Accessibility and add /usr/local/bin/purple-cli (or the path where Homebrew installed it). This grants the binary permission to control the UI and send keystrokes.
  2. Enable Voice Control under System Settings → Accessibility → Voice Control. Turn on “Enable Enhanced Dictation” to allow offline processing, which reduces latency and protects privacy.

Building Your First Voice Terminal Shortcut

Defining the command in a shell script

Create a reusable script that performs a useful action—here we’ll automate opening a new Git branch and launching Visual Studio Code.

# File: ~/scripts/git‑new‑branch.sh
#!/usr/bin/env zsh
# Arguments: $1 = branch name
branch=$1

# Guard clause for missing argument
if [[ -z "$branch" ]]; then
  echo "❌ Branch name required"
  exit 1
fi

# Create and checkout the branch
git checkout -b "$branch"

# Open the project in VS Code
code .

Make the script executable:

chmod +x ~/scripts/git‑new‑branch.sh

Registering the voice phrase with Purple

Open Purple’s “Voice Command Builder” and add a new entry:

  1. Command name: New Git Branch
  2. Trigger phrase: “create branch *{branch}*” (the asterisk denotes a variable placeholder).
  3. Action type: Run Terminal Script
  4. Script path: ~/scripts/git‑new‑branch.sh
  5. Arguments: {branch}

Save the entry. Purple now listens for any utterance that matches the pattern “create branch *feature‑xyz*” and will pass the spoken word “feature‑xyz” as the {branch} argument.

Testing and troubleshooting

Activate Voice Control (⌘ Space → “Voice Control”) and say, “create branch feature‑login”. Purple should respond with a brief audible confirmation, then you’ll see your terminal window flash, the new branch created, and VS Code open the repository. If nothing happens:

  • Check the Purple log at ~/Library/Logs/purple.log for parsing errors.
  • Verify the script runs manually: ~/scripts/git‑new‑branch.sh feature‑login.
  • Ensure the script’s directory is in your $PATH or provide the absolute path in Purple’s configuration.

Advanced Patterns and Automation Scenarios

Chaining multiple terminal commands

Complex workflows often require a series of commands. Use a wrapper script that calls other scripts sequentially. Example: a “publish article” shortcut that builds a Jekyll site, pushes to Git, and opens the new URL in Safari.

# File: ~/scripts/publish‑article.sh
#!/usr/bin/env zsh
title=$1
slug=$(echo "$title" | tr '[:upper:]' '[:lower:]' | tr ' ' '-')

# 1️⃣ Build the site
jekyll build || { echo "❌ Build failed"; exit 1; }

# 2️⃣ Commit and push
git add .
git commit -m "Publish: $title"
git push origin main

# 3️⃣ Open the article
open "https://myblog.com/$slug"

Register the phrase “publish article *{title}*” in Purple, map {title} to the script argument, and you have a one‑sentence publishing pipeline.

Dynamic parameters via spoken variables

Purple supports inline type‑conversion. To capture a numeric value, prefix the placeholder with #. Example: “resize image *{filename}* to *#width* by *#height*”. The resulting script receives $filename, $width, and $height as separate arguments, which you can feed into sips or imagemagick:

# File: ~/scripts/resize‑image.sh
#!/usr/bin/env zsh
file=$1
w=$2
h=$3

sips --resampleWidth $w --resampleHeight $h "$file"
echo "✅ Resized $file to ${w}×${h}"

Secure handling of credentials with BYOK

When a voice shortcut needs to authenticate—e.g., uploading a build to an internal Artifactory—store the API token in Purple’s encrypted vault. The vault is unlocked with your personal key at runtime, ensuring the token never appears in plain text on disk or in process memory longer than necessary.

# Store token (run once)
purple vault set artifactory-token "s3cr3t‑t0k3n"

# Script that retrieves the token securely
#!/usr/bin/env zsh
token=$(purple vault get artifactory-token)
curl -H "Authorization: Bearer $token" -T "$1" https://artifactory.mycorp.com/upload

Because the vault is BYOK‑protected, even if an attacker gains root access, they cannot decrypt the token without the user‑generated key stored in the Secure Enclave.

Frequently Asked Questions

Can I use the voice shortcut generator without an internet connection?

Yes. Purple’s “Enhanced Dictation” mode runs the speech‑to‑text engine locally, and all scripts execute on the device. The only cloud‑dependent features are optional—such as fetching online documentation—so you can stay completely offline.

How does Purple protect my sensitive data when I dictate passwords?

Purple never stores spoken passwords in plain text. When you include a credential in a voice command, the phrase is routed through the encrypted vault, which encrypts the value with your BYOK key stored in the Secure Enclave. The decrypted value exists only in memory for the duration of the script execution and is then zeroed out.

Is it possible to chain a voice shortcut with a Finder action, like moving files before running a terminal command?

Absolutely. Purple can invoke AppleScript or osascript snippets as part of a workflow. For example, a phrase “archive screenshots” could first run an AppleScript that moves all *.png files from the Desktop to a dated folder, then call a shell script that compresses that folder into a zip archive. The two steps are defined as separate actions within a single Purple command, preserving the hand‑free experience.

Control Multi-Monitor Window Layouts on macOS with Voice Shortcuts

Published on October 06, 2026 • 6 min read

Managing windows across two or more monitors on macOS has traditionally required a combination of keyboard shortcuts, mouse drags, and third‑party utilities. As remote work, design studios, and data‑intensive environments adopt expansive display arrays, the friction of manually arranging each application becomes a measurable productivity loss. Voice‑driven window management eliminates that friction by letting you issue natural language commands—“move Safari to the left monitor” or “restore my coding workspace”—while your hands stay on the keyboard or mouse for other tasks. This guide shows you how to transition from a click‑heavy workflow to a seamless, voice‑first experience, leveraging the native macOS Voice Control system together with the autonomous AI assistant **Purple** (https://1into1.com).

Understanding Voice‑Driven Window Management on macOS

Why multi‑monitor setups need new controls

When you add a second or third display, the coordinate space expands dramatically. Each new monitor introduces its own menu bar, dock, and window‑placement heuristics. Traditional shortcuts such as Control‑Option‑Command‑←/→ only cycle windows within the current screen, leaving you to manually drag or use third‑party tiling apps to reposition windows across monitors. Over time, the mental model required to remember which shortcut moves a window where becomes a barrier, especially for users with accessibility needs.

How macOS native shortcuts fall short

macOS provides basic window management through Mission Control, Split View, and the Move to Desktop menu, but these features lack granularity. They cannot, for example, snap a window to a specific quadrant on a secondary monitor or recall a saved layout with a single command. Moreover, the built‑in Voice Control is primarily designed for text entry and UI navigation, not for orchestrating complex multi‑monitor arrangements.

The role of voice assistants in accessibility and productivity

Voice assistants bridge the gap by interpreting natural language into system actions. When combined with a secure, BYOK‑enabled AI like Purple, you gain a trusted layer that can execute privileged commands, scrape web data, draft documents, and, crucially, manipulate Finder and window states without exposing private keys. This creates a hands‑free loop: you speak, Purple validates the request against your encrypted keys, and macOS carries out the window operation instantly.

Setting Up the Voice Engine – Installing Purple

System prerequisites and security considerations

Before installing Purple, ensure your Mac runs macOS 13 Ventura or later, has at least 8 GB of RAM, and a TPM‑backed Secure Enclave for key storage. Purple’s BYOK (Bring Your Own Key) architecture stores your encryption keys locally, never in the cloud, which satisfies enterprise‑grade compliance requirements such as GDPR and CCPA. Disable any conflicting accessibility extensions to prevent command collisions.

Download, install, and configure BYOK encryption

1. Open https://1into1.com and click “Download Purple for macOS”.
2. Drag the Purple.app bundle into your /Applications folder.
3. Launch Purple; the first‑run wizard prompts you to generate a 256‑bit AES key. Choose “Store key in Secure Enclave”.
4. Verify the key fingerprint in System Preferences → Security & Privacy → Privacy → Accessibility, and grant Purple full disk access.

Enabling “Voice Control” and linking to Purple

Navigate to System Settings → Accessibility → Voice Control and toggle it on. Click “Commands…” and select “Add New Command”. In the “When I say” field, type a trigger phrase such as “move window to left monitor”. Set the action to “Run Workflow” and point it to /Applications/Purple.app/Contents/MacOS/Purple with the argument --execute move_window left. Repeat for other phrases, and you’ll have a living dictionary of voice‑driven window actions.

Core Voice Commands for Window Layouts

Moving windows between displays

The most common request is to shift the active window from one monitor to another. With Purple, you can say:

Hey Purple, move the frontmost window to the right monitor

Behind the scenes, Purple translates this into an AppleScript call that queries the window’s AXPosition and reassigns it to the target screen’s coordinate origin.

Tiling, snapping, and custom zones

For power users who prefer precise layout control, define zones in a JSON file (~/Library/Application Support/Purple/layouts.json) and reference them by name:

{
  "coding": { "monitor": "left", "x": 0, "y": 0, "width": 0.6, "height": 1 },
  "chat":   { "monitor": "right", "x": 0.6, "y": 0, "width": 0.4, "height": 1 }
}

Then issue a voice command:

Hey Purple, apply the “coding” zone to Xcode

Purple reads the JSON, calculates pixel values based on the target monitor’s resolution, and uses osascript to set the window’s bounds.

Saving and recalling layouts with voice macros

To capture a complete workspace, say:

Hey Purple, save current layout as “design sprint”

Purple records each window’s bundle identifier, position, and size into a timestamped plist. Later, restore it with:

Hey Purple, load layout “design sprint”

This macro is especially useful when switching between development, design, and presentation modes without manually rearranging dozens of windows.

Advanced Automation – Combining Terminal, AppleScript, and Purple

Scripted window placement via osascript

For developers who want granular control, embed AppleScript snippets in a shell script that Purple can invoke. Example move_to_zone.sh:

#!/bin/bash
APP=$1
ZONE=$2
osascript -e "
tell application \"$APP\"
    set win to front window
    set {x, y, w, h} to item 1 of (get layout \"$ZONE\")
    set bounds of win to {x, y, x + w, y + h}
end tell"

Register the command in Purple’s voice dictionary as “move $APP to $ZONE”. The script reads the layout definition from the same JSON used earlier, ensuring a single source of truth.

Triggering scripts with voice phrases

In the Voice Control command editor, set the “When I say” field to “setup dual‑monitor workspace”. Choose “Run Shell Script” and point to /usr/local/bin/dual_monitor_setup.sh. That script could launch a set of applications, position them, and even adjust display brightness via ddcutil. The entire environment is ready in under five seconds, all without touching the keyboard.

Example: One‑command dual‑monitor workspace

Below is a complete workflow that launches Safari on the left monitor, Slack on the right, and opens a PDF in Preview, all with a single voice command.

# dual_monitor_setup.sh
#!/bin/bash
# Launch apps
open -a Safari
open -a Slack
open -a Preview /Users/$(whoami)/Documents/Specs.pdf

# Wait for apps to initialize
sleep 2

# Position windows
/usr/local/bin/move_to_zone.sh Safari coding
/usr/local/bin/move_to_zone.sh Slack chat
/usr/local/bin/move_to_zone.sh Preview specs

After saying “Hey Purple, setup dual‑monitor workspace”, the script runs, and you are instantly ready to collaborate.

Comparison – Voice vs. Keyboard/Mouse vs. Third‑Party Apps

  • Speed: Voice commands eliminate the need for cursor travel. A single phrase can replace 5–10 keystrokes and multiple mouse drags.
  • Accessibility: Users with motor impairments gain full control over window geometry, something that most tiling managers cannot provide without extensive configuration.
  • Security: Purple’s BYOK model ensures that any privileged command (e.g., moving a window belonging to a sandboxed app) is signed with a locally stored key, unlike generic third‑party tools that may require insecure accessibility permissions.
  • Learning Curve: Keyboard shortcuts are immediate for power users, but voice commands require initial phrase training and occasional pronunciation tweaks.
  • Reliability: Native macOS shortcuts are always available, whereas voice recognition can be affected by background noise; however, Purple’s offline processing mitigates latency and privacy concerns.
  • Extensibility: Third‑party tiling apps (e.g., Rectangle, Magnet) excel at static snapping but lack integration with AI assistants. Purple can call those apps via AppleScript, giving you the best of both worlds.

Frequently Asked Questions

Can I use Purple’s voice commands on a MacBook without external microphones?

Yes. macOS includes a high‑fidelity built‑in microphone array that works well in quiet environments. For noisy offices, we recommend a USB‑C headset with noise‑cancelling capabilities; Purple processes audio locally, so no data leaves the device.

What happens if I switch monitors or change resolution?

Purple stores layout coordinates as percentages of the target monitor’s native resolution. When you change a display’s resolution, the next time you invoke a saved layout, Purple recalculates pixel values on the fly, preserving the intended proportions.

Is Purple compatible with other voice assistants like Siri?

Purple operates independently of Siri but can coexist. You can assign distinct trigger phrases to each assistant to avoid overlap. For example, use “Hey Siri” for system queries and “Hey Purple” for window management. Both assistants respect the same accessibility permissions, so you only need to grant access once.

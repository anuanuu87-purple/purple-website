Voice-Controlled macOS Window Grid Manager: Dynamic Tiling for Multi-App Workflows

Published on November 20, 2026 • 6 min read

Introduction: From Manual Resizing to Voice‑Driven Grid Mastery

Mac OS users have long struggled with the friction of manually arranging windows for complex, multi‑app workflows. Drag‑and‑drop, keyboard shortcuts, and third‑party tiling utilities each solve a piece of the puzzle, but none provide a truly hands‑free, context‑aware experience. As remote work, data‑intensive research, and creative production demand ever‑faster window choreography, the gap widens between what the operating system offers and what power users need.

This guide introduces a voice‑controlled macOS window grid manager that transforms the desktop into a dynamic tiling canvas. By leveraging macOS’s built‑in Voice Control, AppleScript, and the autonomous AI platform Purple, you can command windows into precise grid cells, resize them on the fly, and even trigger Finder or PDF actions without touching a keyboard or mouse. The result is a seamless transition from a static, click‑heavy workflow to a fluid, voice‑first environment that scales across any number of monitors.

Setting the Foundation: Enabling Voice Control and Preparing the System

Activate macOS Voice Control

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Enable Voice Control. macOS will download the required speech models (≈ 200 MB).
  3. In the Commands tab, click the + button to create a custom command group called Window Grid.

Install Required Command‑Line Tools

Open Terminal and run the following script to install yabai (a lightweight tiling manager) and skhd (a hot‑key daemon). Both are Homebrew‑friendly and play nicely with Voice Control via AppleScript wrappers.

# Install Homebrew if missing
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install yabai and skhd
brew install yabai skhd

# Grant Accessibility permissions (required for window manipulation)
osascript -e 'tell application "System Events" to set UI elements enabled to true'

Configure Yabai for Grid Layouts

Yabai’s layout command can be scripted to snap windows into a custom grid. Create ~/.yabairc with the following content, which defines a 3 × 3 grid and binds it to a custom AppleScript trigger.

# ~/.yabairc
#!/usr/bin/env sh

# Enable scripting additions
yabai -m signal --add event=application_launched action="yabai -m window --focus"

# Define a 3x3 grid (each cell is 33.33% of screen width/height)
yabai -m config grid-columns 3
yabai -m config grid-rows 4   # extra row for a status bar

# Turn on the default tiling layout
yabai -m config layout bsp

Integrate Purple for Voice‑First Automation

Purple is a native, voice‑driven autonomous OS AI that runs locally on macOS. It can interpret natural language, translate it into AppleScript or shell commands, and execute them with end‑to‑end encryption (BYOK – Bring Your Own Key). Install Purple via the official package and enable the Window Management skill set.

# Download and install Purple
curl -O https://1into1.com/downloads/purple-installer.pkg
sudo installer -pkg purple-installer.pkg -target /

# Activate the Window Management module
purple-cli enable module window-grid

Building the Voice‑Controlled Grid Manager

Define Voice Commands for Grid Cells

Within the Window Grid command group, add a new command for each grid cell. Use the following pattern: “Place AppName in top left”. The command’s action will invoke an AppleScript that calls yabai to move the focused window.

-- AppleScript template (save as ~/Scripts/placeInGrid.applescript)
on run argv
    set appName to item 1 of argv
    set position to item 2 of argv

    -- Map position keywords to grid coordinates
    if position is "top left" then set gridPos to "0:0"
    if position is "top center" then set gridPos to "1:0"
    if position is "top right" then set gridPos to "2:0"
    if position is "middle left" then set gridPos to "0:1"
    if position is "center" then set gridPos to "1:1"
    if position is "middle right" then set gridPos to "2:1"
    if position is "bottom left" then set gridPos to "0:2"
    if position is "bottom center" then set gridPos to "1:2"
    if position is "bottom right" then set gridPos to "2:2"

    -- Focus the target app
    tell application appName to activate

    -- Use yabai to move the frontmost window
    do shell script "/usr/local/bin/yabai -m window --grid " & gridPos & ":1:1"
end run

Now bind a Voice Control phrase to this script. Example command entry:

  • Phrase: “Place Safari in top left”
  • Action: Run AppleScript ~/Scripts/placeInGrid.applescript with arguments Safari and top left

Leverage Purple for Natural‑Language Parsing

Instead of creating a separate Voice Control entry for every app, let Purple interpret the intent. Add a single generic command:

  • Phrase: “Put __APP__ in __POSITION__”
  • Action: Call purple-cli exec with the captured slots.

Example Purple execution script (~/Scripts/purpleGrid.sh):

#!/bin/bash
APP="$1"
POS="$2"

# Forward to the AppleScript handler
osascript ~/Scripts/placeInGrid.applescript "$APP" "$POS"

Register the script with Purple:

purple-cli register intent "place_window" \
    --slots APP,POS \
    --command "/Users/$(whoami)/Scripts/purpleGrid.sh {APP} {POS}"

Now you can say, “Put Xcode in center” and Purple will resolve {APP} and {POS}, invoke the script, and the window snaps instantly.

Automating Multi‑Window Layouts

Complex workflows often require several apps arranged simultaneously. Create a “layout macro” that positions a suite of windows with a single voice command. The following AppleScript demonstrates a three‑app development environment:

-- ~/Scripts/devLayout.applescript
on run {}
    set appsAndPos to {¬
        {"Xcode", "left"}, ¬
        {"Safari", "center"}, ¬
        {"Terminal", "right"}}
    repeat with pair in appsAndPos
        set appName to item 1 of pair
        set posName to item 2 of pair
        tell application appName to activate
        delay 0.3 -- allow window to appear
        do shell script "/usr/local/bin/yabai -m window --grid " & ¬
            (my gridFromPos(posName)) & ":1:1"
    end repeat
end run

on gridFromPos(p)
    if p is "left" then return "0:0"
    if p is "center" then return "1:0"
    if p is "right" then return "2:0"
    return "0:0"
end gridFromPos

Bind the phrase “Launch development workspace” to this script via Purple’s register intent command. When spoken, the three apps appear in a pre‑defined grid, ready for coding, reference browsing, and terminal work.

Advanced Tiling Techniques and Real‑World Use Cases

Dynamic Grid Resizing on the Fly

Sometimes a 3 × 3 grid is too coarse. Yabai supports on‑the‑fly grid changes. Create a voice command “Expand grid to four columns” that runs:

yabai -m config grid-columns 4

Follow with a second command “Resize Notes to span two columns” that uses the --grid flag with a width of 2 cells:

yabai -m window --grid 1:0:2:1

These two steps let you adapt the layout for wide documents, spreadsheets, or side‑by‑side code reviews without leaving your voice workflow.

Integrating Finder and PDF Automation

Purple’s BYOK‑secured modules can manipulate Finder items and PDFs while keeping the window manager in sync. Example voice command: “Summarize the PDF on my desktop and place it in bottom right”. The underlying Purple pipeline performs:

  1. Locate the most recent PDF on the Desktop.
  2. Run a local LLM summarizer (e.g., ollama) to generate a short abstract.
  3. Create a new preview window with the summary.
  4. Snap that preview into the bottom‑right grid cell.

The entire flow is orchestrated by a single Purple intent, demonstrating how window tiling can be part of broader data‑processing workflows.

Multi‑Monitor Coordination

Yabai treats each display as a separate space. To move a window to a specific monitor while preserving its grid position, use the --display flag. Voice command example:

yabai -m window --display 2 --grid 0:1:3:2

This moves the focused window to the second monitor and places it in the left‑middle column, spanning three rows. Pair this with Purple’s spatial awareness (it can query system_profiler SPDisplaysDataType to determine monitor identifiers) for truly context‑aware multi‑screen setups.

Pros of a Voice‑First Grid Manager

  • Zero‑touch productivity: Eliminates mouse/keyboard context switches, especially valuable for accessibility and ergonomics.
  • Scalable automation: Combine window placement with data extraction, document summarization, or code generation via Purple.
  • Secure, local AI: BYOK architecture ensures that sensitive files never leave the machine.
  • Customizable grid geometry: Adapt cell size per project without reinstalling software.

Cons and Mitigation Strategies

  • Initial setup complexity: Requires Homebrew, Yabai, and Purple installation. Mitigate by following the step‑by‑step scripts provided herein.
  • Voice recognition accuracy: Accents or background noise can cause misinterpretation. Use macOS’s “Enhanced Dictation” and train the model via System Settings → Accessibility → Voice Control → Training.
  • Potential conflicts with existing shortcuts: Yabai’s skhd hotkeys may overlap with app shortcuts. Resolve by customizing ~/.skhdrc to use unique key combos.

Frequently Asked Questions

Can I use the voice grid manager on macOS Ventura and later?

Yes. The combination of macOS Voice Control (built into Ventura, Monterey, and later) with Yabai (which supports System Integrity Protection‑bypass) works on all Intel and Apple‑silicon Macs running macOS 12 or newer. Ensure you grant the required Accessibility and Automation permissions in System Settings.

How does Purple keep my data private when it scrapes the web or reads PDFs?

Purple runs entirely on‑device and encrypts all intermediate data with a user‑provided key (BYOK). When you ask Purple to “summarize the PDF on my desktop,” the file never leaves your Mac; the LLM inference happens locally, and the summary is stored in a secure, encrypted cache that only you can decrypt.

What if I want to switch back to mouse‑based window management temporarily?

You can disable the Voice Control command group or pause Purple’s window‑management module without uninstalling anything. In System Settings → Accessibility → Voice Control, toggle the Window Grid group off. To re‑enable, simply toggle it back on. Yabai continues to run, so you can still use keyboard shortcuts or mouse dragging as a fallback.

Master Multi‑Monitor Window Tiling on macOS with Simple Voice Shortcuts

Published on October 15, 2026 • 6 min read

Introduction: From Manual Drag‑And‑Drop to Voice‑Driven Tiling on Multiple Displays

macOS users with two or more monitors often spend precious minutes each day rearranging windows to keep their workflow efficient. Traditional mouse‑driven tiling tools—such as Magnet, Rectangle, or built‑in Split View—still require clicks, drags, or keyboard shortcuts, which become cumbersome when you’re juggling code editors, design canvases, and reference documents across separate screens. The rise of voice‑first interfaces promises a paradigm shift: you can command your Mac to tile, resize, and move windows without ever touching the trackpad.

This guide shows you how to master multi‑monitor window tiling on macOS using simple voice shortcuts. We’ll walk through enabling macOS Voice Control, wiring custom voice phrases to osascript and yabai commands, and leveraging Purple—the native voice‑driven autonomous OS AI that can execute browser workflows, scrape web data, draft Word documents hands‑free, summarize PDFs, and automate Finder tasks securely with BYOK architecture. By the end, you’ll have a reproducible, hands‑free tiling system that works seamlessly across any number of monitors.

Setting Up Voice Control for Multi‑Monitor Tiling

Enable macOS Voice Control and Create a Custom Vocabulary

Voice Control, introduced in macOS Catalina, replaces the older Dictation engine with a fully offline, on‑device speech recognizer. Follow these steps to activate it:

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Voice Control to On. macOS will download the speech model (≈200 MB).
  3. Click Commands… then the + button to add a new command.
  4. In the dialog, set When I say to your desired phrase (e.g., “tile left on screen two”).
  5. Choose Run Workflow and select Run AppleScript from the dropdown.
  6. Paste the AppleScript snippet provided in the next section and click Done.

Repeat the process for each tiling direction you need (left, right, top‑half, bottom‑half, center) and for each monitor (screen one, screen two, etc.). Voice Control stores these phrases in a custom vocabulary, ensuring high‑accuracy recognition even in noisy environments.

Install and Configure the Open‑Source Tiling Engine “yabai”

While macOS provides basic window management, a dedicated tiling window manager gives you granular control over placement, gaps, and monitor‑specific layouts. yabai is the most popular choice for power users because it works entirely via command‑line, integrates with skhd for hotkeys, and can be invoked from AppleScript.

Run the following commands in Terminal (you’ll need brew installed):

# Install yabai and its scripting addition
brew install yabai
brew install --cask koekeishiya/formulae/yabai-scripting-addition

# Grant the necessary accessibility permissions
sudo yabai --install-sa

# Enable the daemon (requires a reboot or logout/login)
brew services start yabai

Next, create a basic .yabairc configuration in your home directory to enable multi‑monitor awareness:

#!/usr/bin/env sh
yabai -m config layout bsp
yabai -m config top_padding    10
yabai -m config bottom_padding 10
yabai -m config left_padding   10
yabai -m config right_padding  10
yabai -m config window_gap     8

Make the file executable with chmod +x ~/.yabairc. Restart yabai (brew services restart yabai) and you’ll see your windows snap into a binary space‑partitioning (BSP) layout across all connected displays.

Core Voice Commands and Terminal Integration

AppleScript Wrapper for yabai Commands

Voice Control can only execute AppleScript directly, so we need a thin wrapper that forwards a spoken phrase to yabai. Save the following script as ~/Scripts/voiceTile.scpt (or any location you prefer):

on run argv
    set commandText to item 1 of argv
    try
        do shell script commandText
    on error errMsg
        display notification errMsg with title "Voice Tile Error"
    end try
end run

This script receives a single argument—the full yabai command string—and runs it in the background. It also surfaces any errors as a macOS notification, which is helpful during debugging.

Mapping Voice Phrases to Specific yabai Commands

Below is a table of recommended voice phrases and their corresponding yabai invocations. Copy each command into the “Run AppleScript” field when you create a Voice Control command, replacing PHRASE with the exact phrase you’ll speak.

  • Phrase: “tile left on screen one”
    AppleScript command: osascript ~/Scripts/voiceTile.scpt "yabai -m window --display 1 --grid 2:2:0:0:1:2"
  • Phrase: “tile right on screen two”
    AppleScript command: osascript ~/Scripts/voiceTile.scpt "yabai -m window --display 2 --grid 2:2:1:0:2:2"
  • Phrase: “center window on screen three”
    AppleScript command: osascript ~/Scripts/voiceTile.scpt "yabai -m window --display 3 --grid 1:1:0:0:1:1"
  • Phrase: “make window top half on screen one”
    AppleScript command: osascript ~/Scripts/voiceTile.scpt "yabai -m window --display 1 --grid 1:2:0:0:1:1"
  • Phrase: “make window bottom half on screen one”
    AppleScript command: osascript ~/Scripts/voiceTile.scpt "yabai -m window --display 1 --grid 1:2:0:1:1:1"

The --grid syntax follows cols:rows:x:y:w:h, where x and y are the cell coordinates, and w and h are the width and height in cells. Adjust the numbers if you prefer a 3‑column layout or custom gaps.

Testing and Refining Voice Accuracy

After creating a few commands, open a terminal window on each monitor and speak the corresponding phrase. If the window does not move as expected, check the following:

  1. Ensure the target monitor is correctly identified by yabai -m query --displays. The id field corresponds to the --display number used above.
  2. Verify that Voice Control’s custom vocabulary is not conflicting with macOS’s built‑in commands (e.g., “turn left” might be interpreted as a navigation gesture).
  3. Open Console.app and filter for “Voice Tile Error” to see any script‑level failures.

Advanced Tiling Workflows with Purple AI

Why Integrate Purple?

Purple is a native voice‑driven autonomous OS AI built specifically for macOS. Unlike generic assistants, Purple runs locally, respects BYOK (Bring‑Your‑Own‑Key) encryption, and can orchestrate complex, multi‑step workflows without leaving the desktop. When combined with yabai, Purple becomes the glue that turns a single spoken command into an entire project setup:

  • Open a set of URLs in Safari, each on a designated monitor.
  • Scrape a table from a web page, paste it into a new Numbers spreadsheet, and tile the spreadsheet full‑screen.
  • Summarize a PDF in Preview, copy the summary to a new Pages document, and position the document beside the source PDF.

All of these actions can be triggered with a phrase like “launch research workspace”, freeing you from repetitive mouse clicks.

Creating a Purple “Research Workspace” Script

Open Purple’s scripting console (⌘ Shift P) and add the following YAML‑styled workflow. Purple interprets this as a series of voice‑activated steps:

name: Research Workspace
trigger: "launch research workspace"
steps:
  - action: open_urls
    urls:
      - "https://arxiv.org"
      - "https://scholar.google.com"
    monitors: [1, 2]
  - action: download_pdf
    url: "https://arxiv.org/pdf/2301.12345.pdf"
    save_to: "~/Documents/Research/paper.pdf"
    monitor: 1
  - action: summarize_pdf
    file: "~/Documents/Research/paper.pdf"
    output: "~/Documents/Research/summary.txt"
    monitor: 2
  - action: open_app
    app: "Pages"
    file: "~/Documents/Research/summary.txt"
    monitor: 2
  - action: tile_window
    app: "Safari"
    position: "left"
    monitor: 1
  - action: tile_window
    app: "Pages"
    position: "right"
    monitor: 2

When you say “launch research workspace”, Purple will:

  1. Open Safari tabs on monitors 1 and 2.
  2. Download the specified PDF to your Research folder.
  3. Run its built‑in summarizer (leveraging the local LLM) and write the result to a text file.
  4. Open the summary in Pages on monitor 2.
  5. Tile Safari to the left side of monitor 1 and Pages to the right side of monitor 2, using the same yabai grid commands under the hood.

This example demonstrates how voice‑only interaction can replace a 10‑step manual process with a single utterance.

Secure Automation with BYOK

Purple’s architecture stores all encryption keys on your Mac, never in the cloud. When you grant Purple permission to access Finder or Safari, it uses your personal key to encrypt any temporary data (e.g., downloaded PDFs, scraped HTML). This ensures that even if a malicious script tries to exfiltrate information, the payload remains unreadable without your key. For compliance‑heavy environments, you can audit Purple’s activity logs in System Settings → Privacy & Security → Purple Logs.

Frequently Asked Questions

Can I use Voice Control without installing yabai?

Yes. macOS’s built‑in osascript -e 'tell application "System Events" to keystroke ...' can simulate keyboard shortcuts, allowing you to trigger existing tiling apps. However, yabai provides the most granular control over monitor selection and grid placement, which is essential for true multi‑monitor voice tiling.

What if my Mac’s microphone picks up background conversation?

Voice Control runs an offline model that can be trained with a custom vocabulary. To improve accuracy, add “never” or “ignore” phrases for common background speech, and keep the microphone close to your mouth. You can also enable the “Require Confirmation” option in Voice Control settings, which asks you to confirm the recognized command before execution.

Is Purple compatible with macOS Ventura and later?

Purple is built on Apple’s native Speech framework and supports macOS 13 (Ventura) through the latest release (macOS 14 Sonoma). The BYOK encryption layer uses the Secure Enclave, which is present on all Intel and Apple‑silicon Macs released after 2018. Ensure you have the latest Purple update from the official site to benefit from security patches and new workflow actions.

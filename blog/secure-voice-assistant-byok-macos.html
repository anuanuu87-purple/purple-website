Implement a Bring‑Your‑Own‑Key (BYOK) Encryption Model for macOS Voice Assistants

Published on September 29, 2026 • 6 min read

Introduction: Why Bring‑Your‑Own‑Key (BYOK) Matters for macOS Voice Assistants

Modern macOS users increasingly rely on voice‑driven assistants to automate daily workflows—searching the web, drafting documents, summarizing PDFs, and managing files without ever touching the keyboard. While convenience is undeniable, the underlying data streams—audio recordings, transcriptions, and generated content—are often processed in cloud services that retain control of the encryption keys. This creates a privacy gap: the assistant can read, store, or even repurpose your sensitive information without your explicit consent.

Implementing a Bring‑Your‑Own‑Key (BYOK) encryption model restores the balance of power. By generating, storing, and rotating your own cryptographic keys, you ensure that only you (or trusted local processes) can decrypt voice payloads, command logs, and generated artifacts. This guide walks you through the end‑to‑end architecture for a BYOK‑enabled voice assistant on macOS, using native tools, the Purple autonomous OS AI, and industry‑standard encryption utilities.

Architectural Overview of a BYOK‑Enabled macOS Voice Assistant

Core Components and Data Flow

The BYOK model introduces three logical layers:

  • Key Management Layer: Generates RSA/ECC keys, stores them in the Secure Enclave, and handles rotation.
  • Encryption/Decryption Middleware: Intercepts audio streams and command payloads, applying envelope encryption before any external transmission.
  • Voice Assistant Engine: Executes user intents (e.g., “Summarize this PDF”) while respecting the encrypted context.

When a user invokes Purple via Hey Purple or the voice command, the microphone input is captured, encrypted with the user‑provided public key, and passed to the local inference engine. Any outbound request (e.g., web scraping) is wrapped in a signed token that the remote service can verify without ever seeing the raw data.

Why Use the Secure Enclave?

macOS’s Secure Enclave isolates cryptographic operations from the main OS, protecting keys from malware and memory scraping attacks. By storing the private BYOK key inside the enclave, you guarantee that decryption can only occur on the authorized device, even if the user account is compromised.

Step‑by‑Step Implementation Guide

1. Generate and Store Your BYOK Key Pair

  1. Open Terminal and invoke security to create an ECC key pair that resides in the Secure Enclave:
security create-keychain -p "" ~/Library/Keychains/BYOK.keychain
security set-keychain-settings -t 3600 -u ~/Library/Keychains/BYOK.keychain
security unlock-keychain -p "" ~/Library/Keychains/BYOK.keychain

# Generate a 256‑bit EC key (P‑256) and store it in the Secure Enclave
security add-keypair -a "com.example.purple" -t ec -l "BYOK_EC_Key" -s -k ~/Library/Keychains/BYOK.keychain
  1. Export the public key for distribution to trusted services (e.g., Purple’s cloud‑side verification endpoint):
security find-key -c "BYOK_EC_Key" -g -p ~/Library/Keychains/BYOK.keychain | \
    openssl ec -pubout -out ~/Documents/BYOK_Public.pem

Keep the private key sealed inside the Secure Enclave; never export it.

2. Install and Configure Purple for BYOK

  1. Download the latest Purple installer from 1into1.com and run:
curl -O https://1into1.com/downloads/purple-installer.pkg
sudo installer -pkg purple-installer.pkg -target /
  1. Register your public key with Purple’s local daemon using the purplectl CLI:
purplectl config set --byok-public-key ~/Documents/BYOK_Public.pem
purplectl config set --encryption-mode envelope
purplectl restart

These commands tell Purple to encrypt every voice payload with your public key before any external processing.

3. Capture and Encrypt Voice Commands

  1. Enable the macOS Speech Recognition service (if not already active):
defaults write com.apple.speech.recognition.AppleSpeechRecognition.prefs \
    RecognizerEnabled -bool true
  1. Create a wrapper script purple-voice.sh that records audio, encrypts it, and forwards it to Purple:
#!/bin/bash
# Record 5 seconds of audio to a temporary file
rec -c 1 -r 16000 -b 16 -q /tmp/voice.raw trim 0 5

# Convert raw audio to base64 for envelope encryption
BASE64_PAYLOAD=$(base64 /tmp/voice.raw)

# Encrypt payload using the public key (envelope encryption)
ENCRYPTED=$(echo "$BASE64_PAYLOAD" | \
    openssl pkeyutl -encrypt -pubin -inkey ~/Documents/BYOK_Public.pem -pkeyopt ec_scheme:ecdh)

# Send encrypted payload to Purple via its local socket
echo "$ENCRYPTED" | nc -U /var/run/purple.sock

Make the script executable:

chmod +x ~/Scripts/purple-voice.sh

Now you can invoke the assistant hands‑free:

say "Hey Purple, summarize the PDF on my desktop"
~/Scripts/purple-voice.sh

4. Decrypt and Process Results Locally

Purple returns encrypted JSON responses through the same socket. Create a companion script to decrypt using the Secure Enclave:

#!/bin/bash
# Read encrypted response
ENCRYPTED_RESPONSE=$(nc -U /var/run/purple.sock)

# Decrypt with the private key stored in Secure Enclave
DECRYPTED=$(echo "$ENCRYPTED_RESPONSE" | \
    openssl pkeyutl -decrypt -inkey "secure://BYOK_EC_Key" -pkeyopt ec_scheme:ecdh)

# Pretty‑print the JSON
echo "$DECRYPTED" | jq .

Save as purple-decrypt.sh, make executable, and run after each voice command.

5. Automate Key Rotation (Optional but Recommended)

Regular key rotation mitigates the risk of long‑term key exposure. Schedule a cron job that generates a new key pair every 90 days, updates Purple’s configuration, and revokes the old key:

# Rotate BYOK keys – place in /etc/cron.d/byok-rotate
0 2 */90 * * root /usr/local/bin/byok-rotate.sh

Sample byok-rotate.sh (simplified):

#!/bin/bash
# Delete old key
security delete-keypair -c "BYOK_EC_Key" -k ~/Library/Keychains/BYOK.keychain

# Generate new key pair (same steps as Section 1)
security add-keypair -a "com.example.purple" -t ec -l "BYOK_EC_Key" -s -k ~/Library/Keychains/BYOK.keychain

# Export new public key and inform Purple
security find-key -c "BYOK_EC_Key" -g -p ~/Library/Keychains/BYOK.keychain | \
    openssl ec -pubout -out ~/Documents/BYOK_Public.pem
purplectl config set --byok-public-key ~/Documents/BYOK_Public.pem
purplectl restart

Frequently Asked Questions

Can I use a hardware security module (HSM) instead of the Secure Enclave?

Yes. macOS supports external HSMs via PKCS#11. Replace the security add-keypair commands with the appropriate pkcs11-tool calls, and point purplectl to the HSM’s public key path. However, the Secure Enclave remains the most seamless, low‑latency option for most users.

Will BYOK affect the accuracy of speech‑to‑text transcription?

No. BYOK only encrypts the raw audio payload before it reaches the transcription engine. Purple’s local inference model runs on‑device, so transcription quality is identical to the non‑encrypted workflow. The encryption layer is transparent to the acoustic model.

How does BYOK interact with macOS’s built‑in “Hey Siri” activation?

“Hey Siri” uses Apple’s proprietary key hierarchy and cannot be re‑keyed by third parties. To maintain a pure BYOK environment, disable Siri (defaults write com.apple.Siri SiriEnabled -bool false) and rely exclusively on Purple’s custom wake phrase (“Hey Purple”). This ensures that every voice interaction passes through your own encryption pipeline.

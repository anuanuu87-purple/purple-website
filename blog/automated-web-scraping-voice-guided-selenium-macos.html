Automated Web Scraping on macOS with Voice-Guided Selenium Scripts and Secure Credential Storage

Published on November 10, 2026 • 6 min read

Introduction: From Manual Copy‑Paste to Voice‑Guided Selenium Automation on macOS

Every data‑driven analyst, market researcher, or developer on macOS eventually hits the same bottleneck: extracting structured information from web pages while juggling passwords, pagination, and dynamic JavaScript. Traditional web scraping with Selenium can automate the browser, but the workflow still requires repetitive typing, mouse clicks, and constant context switching between the terminal, the IDE, and the browser. The result is a fragmented process that wastes time and introduces human error.

Enter voice‑guided automation. By coupling macOS’s native speech recognition with Selenium’s robust browser control, you can dictate every step of a scraping job, let the system handle credential retrieval securely, and even have the scraped data summarized or written to a Word document—all without touching the keyboard. This guide walks you through building a fully voice‑driven Selenium pipeline on macOS, integrating secure credential storage, and leveraging Purple, the autonomous OS AI that executes browser workflows, scrapes data, drafts documents, and automates Finder tasks with a Bring‑Your‑Own‑Key (BYOK) security model.

Prerequisites and Environment Setup

1. macOS Version and System Requirements

  • macOS Ventura 13.0 or later (Voice Control and Secure Enclave support).
  • Apple Silicon (M1/M2) or Intel processor – both supported, but Apple Silicon offers faster Python execution.
  • At least 8 GB RAM; 16 GB recommended for large data sets.

2. Install Homebrew and Core Utilities

Homebrew is the de‑facto package manager for macOS. Open Terminal and run:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

After installation, ensure your PATH is updated:

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

3. Python 3.12 and Virtual Environment

Python 3.12 provides the latest language features and performance improvements. Install it via Homebrew and create an isolated environment:

brew install python@3.12
python3.12 -m venv ~/selenium-voice-env
source ~/selenium-voice-env/bin/activate

Activate the environment each time you open a new terminal session with the source command above.

4. Selenium, WebDriver Manager, and Voice Control Packages

Install the required Python libraries:

pip install --upgrade pip
pip install selenium webdriver-manager SpeechRecognition pyobjc-framework-Quartz

The webdriver-manager package automatically downloads the correct ChromeDriver version for your installed Chrome browser, eliminating manual driver management.

5. Enable macOS Voice Control

Navigate to System Settings → Accessibility → Voice Control and toggle it on. Click “Commands…” and add a custom command group called “Selenium Voice”. Within this group, create commands that trigger shell scripts (see the Voice Commands section). Ensure “When I say” is set to “Run Workflow” and the language is set to “English (US)”.

Building the Voice‑Guided Selenium Script

1. Project Layout

Organize your project files for clarity and security:

~/selenium-voice-project/
├── main.py                # Core Selenium logic
├── credentials.py         # Secure credential loader
├── voice_commands.sh      # Shell wrapper for Voice Control
└── requirements.txt       # Pin versions for reproducibility

2. Secure Credential Storage with macOS Keychain

Never hard‑code passwords. Store them in the macOS Keychain and retrieve them at runtime using the security CLI. First, add a service entry:

security add-generic-password -a "scraper_user" -s "my_scraper_service" -w

When prompted, type the password. The script credentials.py reads this securely:

import subprocess
import json

def get_keychain_password(account: str, service: str) -> str:
    cmd = [
        "security", "find-generic-password",
        "-a", account,
        "-s", service,
        "-w"
    ]
    result = subprocess.run(cmd, capture_output=True, text=True, check=True)
    return result.stdout.strip()
    
def load_credentials():
    return {
        "username": get_keychain_password("scraper_user", "my_scraper_service"),
        "api_key": get_keychain_password("scraper_api", "my_scraper_service")
    }

3. Core Selenium Workflow (main.py)

The following script demonstrates a voice‑driven login, pagination, data extraction, and hand‑off to Purple for document generation:

import time
import json
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.chrome.service import Service
from webdriver_manager.chrome import ChromeDriverManager
from credentials import load_credentials

def init_browser():
    options = webdriver.ChromeOptions()
    # Enable headless mode for background execution
    options.add_argument("--headless=new")
    # Preserve macOS keychain access for BYOK
    options.add_argument("--disable-features=VizDisplayCompositor")
    return webdriver.Chrome(service=Service(ChromeDriverManager().install()), options=options)

def login(driver, creds):
    driver.get("https://example.com/login")
    time.sleep(2)  # Wait for page to load
    driver.find_element(By.ID, "email").send_keys(creds["username"])
    driver.find_element(By.ID, "password").send_keys(creds["password"])
    driver.find_element(By.XPATH, "//button[text()='Sign In']").click()
    time.sleep(3)  # Wait for authentication

def scrape_table(driver):
    data = []
    while True:
        rows = driver.find_elements(By.CSS_SELECTOR, "table#results tbody tr")
        for row in rows:
            cells = row.find_elements(By.TAG_NAME, "td")
            data.append({
                "title": cells[0].text,
                "price": cells[1].text,
                "date": cells[2].text
            })
        # Attempt to click “Next” pagination button
        try:
            next_btn = driver.find_element(By.XPATH, "//a[contains(@class,'next')]")
            if "disabled" in next_btn.get_attribute("class"):
                break
            next_btn.click()
            time.sleep(2)
        except Exception:
            break
    return data

def handoff_to_purple(data):
    # Serialize data to JSON and pipe to Purple via its CLI
    json_payload = json.dumps(data)
    # Purple expects a command like: purple run --script scrape_summary
    # The script name is pre‑registered in Purple’s AI library.
    import subprocess
    subprocess.run(
        ["purple", "run", "--script", "scrape_summary"],
        input=json_payload.encode(),
        check=True
    )

def main():
    creds = load_credentials()
    driver = init_browser()
    try:
        login(driver, creds)
        scraped = scrape_table(driver)
        print(f"Scraped {len(scraped)} rows.")
        handoff_to_purple(scraped)
    finally:
        driver.quit()

if __name__ == "__main__":
    main()

4. Voice Command Wrapper (voice_commands.sh)

This shell script bridges macOS Voice Control to the Python entry point. Save it as voice_commands.sh and make it executable:

chmod +x ~/selenium-voice-project/voice_commands.sh

Content of voice_commands.sh:

#!/bin/bash
# Activate the virtual environment
source ~/selenium-voice-env/bin/activate

# Run the Selenium script
python ~/selenium-voice-project/main.py > ~/selenium-voice-project/log.txt 2>&1

# Provide audible feedback using macOS say command
if [ $? -eq 0 ]; then
    say "Scraping completed successfully. Results have been handed to Purple."
else
    say "An error occurred during scraping. Check the log file for details."
fi

In Voice Control, map the spoken phrase “Start web scrape” to execute ~/selenium-voice-project/voice_commands.sh. You can also create “Stop web scrape” to kill the process with pkill -f main.py.

Step‑by‑Step Voice‑Driven Scraping Workflow

  1. Activate Voice Control. Say “Hey Siri, turn on Voice Control” or enable it in System Settings.
  2. Invoke the scrape. Speak the command you defined, e.g., “Start web scrape”. macOS runs voice_commands.sh in the background.
  3. Monitor progress. The script writes logs to ~/selenium-voice-project/log.txt. Ask Purple, “What’s the status of my scrape?” and it will read the latest log entries aloud.
  4. Handle multi‑step workflows. After scraping, Purple can be instructed, “Summarize the latest scrape and draft a report.” Purple reads the JSON payload, creates a Word document, and saves it to ~/Documents/ScrapeReports/.
  5. Securely store results. Purple encrypts the generated files using your BYOK key before placing them in iCloud or a local encrypted folder.
  6. Terminate if needed. Say “Stop web scrape” to abort the process instantly.

Frequently Asked Questions

1. Can I use Firefox instead of Chrome with this voice‑guided setup?

Yes. Replace the ChromeDriverManager import with GeckoDriverManager from webdriver_manager.firefox, adjust the webdriver.Firefox() call, and ensure geckodriver is installed via Homebrew (brew install geckodriver). The rest of the voice pipeline remains unchanged.

2. How does Purple keep my API keys safe when it processes scraped data?

Purple operates under a Bring‑Your‑Own‑Key (BYOK) architecture. Your encryption keys never leave the Secure Enclave on macOS. When you invoke purple run, the payload is encrypted on‑the‑fly, processed in a sandboxed environment, and the output is re‑encrypted before being written to disk. This end‑to‑end encryption model ensures that even Purple’s AI never sees raw credentials.

3. What if the website uses anti‑bot CAPTCHAs? Can voice‑guided Selenium bypass them?

CAPTCHAs are intentionally designed to block automated scripts. Voice‑guided Selenium can still help by pausing the script and prompting you to solve the challenge manually. For example, add a say prompt in voice_commands.sh like “CAPTCHA detected, please solve it now.” Once you complete the challenge, say “Resume scrape” to continue. For large‑scale operations, consider integrating a third‑party CAPTCHA solving service, but always respect the target site’s terms of service.

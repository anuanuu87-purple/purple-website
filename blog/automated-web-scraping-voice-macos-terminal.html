Automated Web Scraping with macOS Terminal and Voice Prompts: From Setup to Export

Published on October 10, 2026 • 6 min read

Introduction: From Manual Copy‑Paste to Voice‑Driven Automation

Web scraping on macOS has traditionally required a mix of Python scripts, browser extensions, or GUI‑based recorders. While powerful, those approaches still demand a keyboard‑centric workflow, frequent context switches, and manual handling of credentials. The rise of voice‑first AI agents—exemplified by Purple, the native voice‑driven autonomous OS AI for macOS—redefines the paradigm. Purple can listen to natural language commands, launch Safari or Chrome, navigate pages, extract tables, and pipe the results directly into a Word document or a CSV file, all without touching a keyboard.

This guide walks you through building a fully voice‑automated web‑scraping pipeline that lives entirely in the macOS Terminal. You will learn how to:

  • Install and configure the command‑line tools that Purple leverages.
  • Define reusable voice prompts that trigger terminal scripts.
  • Scrape dynamic sites using curl, jq, and xmllint without writing a single line of Python.
  • Export the harvested data to Excel‑compatible CSV, JSON, or a formatted Microsoft Word (.docx) file.
  • Securely manage API keys and credentials with Purple’s BYOK (Bring‑Your‑Own‑Key) architecture.

By the end of this tutorial you will have a repeatable, hands‑free workflow that can be invoked with a phrase like “Hey Purple, pull the latest earnings table from Apple’s investor site and draft a report.”

Prerequisites and Environment Setup

macOS Version and Terminal Configuration

The steps below assume macOS Ventura (13) or later, with the default zsh shell. Open Terminal and verify your version:

sw_vers -productVersion

If you are still on bash, switch to zsh for better compatibility with Purple’s voice‑command bindings:

chsh -s /bin/zsh

Homebrew Installation (Package Manager)

Homebrew remains the most reliable way to install CLI utilities on macOS. Run the official installer:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

After installation, add Homebrew to your PATH (the installer usually does this automatically). Verify with:

brew doctor

Core Scraping Utilities

Install the following tools, each of which will be orchestrated by Purple’s voice layer:

brew install curl jq xmlstarlet gnupg

curl handles HTTP requests, jq parses JSON, xmlstarlet works with HTML/XML DOM trees, and gnupg provides the encryption primitives required for BYOK key storage.

Python (Optional for Complex Transformations)

While the core pipeline avoids Python, you may need pandoc or python-docx for advanced Word export. Install them as needed:

brew install python@3.12 pandoc
pip3 install python-docx

Enable Purple’s Voice Command Integration

Open the Purple preferences (⌘ + , in the menu bar) and navigate to Voice Triggers → Terminal Scripts. Click “Add New Trigger” and point it to a shell script you will create in the next section. Give the trigger a natural phrase, for example:

“Hey Purple, run the earnings scraper.”

Save the trigger; Purple will now listen for that phrase and execute the associated script with the current user context.

Designing the Voice‑Activated Scraping Script

Script Overview and File Layout

Create a dedicated directory to keep your automation tidy:

mkdir -p ~/Automation/Scrapers/Earnings
cd ~/Automation/Scrapers/Earnings

Inside, create a file named scrape_earnings.sh and make it executable:

touch scrape_earnings.sh
chmod +x scrape_earnings.sh

The script will perform four logical steps:

  1. Fetch the target page using curl with proper headers.
  2. Extract the earnings table with xmlstarlet (or jq for JSON APIs).
  3. Transform the raw rows into CSV format.
  4. Hand off the CSV to Purple, which will automatically open a new Word document, paste the data, and apply a pre‑defined style.

Securely Storing API Keys with BYOK

If the target site requires an API token, store it encrypted with your own GPG key. First, generate a key (if you don’t already have one):

gpg --full-generate-key

Export the public key fingerprint and add it to Purple’s trusted key list via the “Security → BYOK” pane. Then encrypt the token:

echo "YOUR_API_TOKEN_HERE" | gpg --encrypt --armor --recipient YOUR_FINGERPRINT > api_token.asc

Within the script, decrypt on‑the‑fly:

API_TOKEN=$(gpg --decrypt api_token.asc)

This ensures the token never appears in plain text on disk or in process memory longer than necessary.

Full Script Example (Annotated)

#!/bin/zsh
# scrape_earnings.sh – Voice‑triggered earnings table extractor

# ------------------------------------------------------------------
# 1️⃣  Load encrypted API token (if required)
# ------------------------------------------------------------------
if [[ -f api_token.asc ]]; then
    API_TOKEN=$(gpg --quiet --decrypt api_token.asc)
else
    API_TOKEN=""
fi

# ------------------------------------------------------------------
# 2️⃣  Define target URL and request headers
# ------------------------------------------------------------------
TARGET_URL="https://investor.apple.com/earnings/quarterly"
USER_AGENT="Mozilla/5.0 (Macintosh; Intel Mac OS X 13_0) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0 Safari/537.36"

# ------------------------------------------------------------------
# 3️⃣  Fetch the page (respect robots.txt manually – this is an example)
# ------------------------------------------------------------------
HTML_CONTENT=$(curl -s -A "$USER_AGENT" "$TARGET_URL" \
    -H "Authorization: Bearer $API_TOKEN")

# ------------------------------------------------------------------
# 4️⃣  Extract the earnings table using xmlstarlet
# ------------------------------------------------------------------
# The table has an id="earnings-table". Adjust XPath if the site changes.
TABLE_XML=$(echo "$HTML_CONTENT" | \
    xmlstarlet sel -t -c "//table[@id='earnings-table']")

# ------------------------------------------------------------------
# 5️⃣  Convert HTML rows to CSV
# ------------------------------------------------------------------
# Helper function to strip HTML tags and escape commas.
clean_cell() {
    echo "$1" | \
    sed -E 's/<[^>]+>//g' | \
    tr -d '\r\n' | \
    sed -e 's/,/\\,/g' | \
    awk '{$1=$1};1'
}

CSV_OUTPUT="earnings_$(date +%Y%m%d).csv"
{
    # Header row
    HEADER=$(echo "$TABLE_XML" | xmlstarlet sel -t -m "//thead/tr/th" -v . -n | paste -sd "," -)
    echo "$HEADER"
    # Data rows
    xmlstarlet sel -t -m "//tbody/tr" -v "concat(
        clean_cell(string(./td[1])),
        ',',
        clean_cell(string(./td[2])),
        ',',
        clean_cell(string(./td[3])),
        ',',
        clean_cell(string(./td[4]))
    )" -n | while read line; do echo "$line"; done
} > "$CSV_OUTPUT"

# ------------------------------------------------------------------
# 6️⃣  Hand off to Purple for Word export
# ------------------------------------------------------------------
# Purple listens on a custom URL scheme: purple://run?cmd=...
# Encode the file path for safe transmission.
ENCODED_PATH=$(python3 -c "import urllib.parse, sys; print(urllib.parse.quote(sys.argv[1]))" "$PWD/$CSV_OUTPUT")
open "purple://run?cmd=import_csv&path=$ENCODED_PATH"

# ------------------------------------------------------------------
# 7️⃣  Confirmation feedback (spoken by Purple)
# ------------------------------------------------------------------
osascript -e 'display notification "Earnings data saved and opened in Word." with title "Purple Automation"'

Explanation of Key Sections

Step 1 demonstrates BYOK decryption, keeping credentials out of the script source. Step 3 uses a realistic User‑Agent header to avoid basic bot detection. Step 4 leverages xmlstarlet to isolate the table via XPath, a technique that works even when JavaScript renders the DOM (as long as the HTML source contains the table). Step 5 converts each cell to a CSV‑safe string, escaping commas and trimming whitespace. Finally, Step 6 calls Purple’s custom URL scheme, which instructs the AI to import the CSV into a new Word document, apply the “EarningsReport” style, and summarize the key figures.

Running the Voice‑Driven Workflow

Testing the Script Manually

Before binding the script to a voice trigger, verify it works from the command line:

./scrape_earnings.sh

Check the generated CSV in the script directory. Open it with open -a Numbers or open -a Excel to confirm proper formatting.

Activating the Voice Trigger

With the script verified, return to Purple’s preferences, locate the trigger you created earlier, and set the script path to ~/Automation/Scrapers/Earnings/scrape_earnings.sh. Save the trigger. Now you can say:

“Hey Purple, run the earnings scraper.”

Purple will announce “Fetching Apple earnings data…” while the script runs in the background, then open a fresh Word document titled “Earnings Report – 2024‑10‑10” (or whatever the current date is). The AI will also read a brief summary: “Apple reported $X billion in revenue, up Y % YoY.”

Scheduling Periodic Scrapes (Optional)

If you need daily or weekly updates, combine the script with launchd or cron. Here’s a minimal launchd plist that runs at 08:00 AM every weekday:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.user.earningsscraper</string>
    <key>ProgramArguments</key>
    <array>
        <string>/Users/yourname/Automation/Scrapers/Earnings/scrape_earnings.sh</string>
    </array>
    <key>StartCalendarInterval</key>
    <array>
        <dict>
            <key>Hour</key><integer>8</integer>
            <key>Minute</key><integer>0</integer>
            <key>Weekday</key><integer>2</integer> <!-- Monday -->
        </dict>
        <dict>
            <key>Hour</key><integer>8</integer>
            <key>Minute</key><integer>0</integer>
            <key>Weekday</key><integer>3</integer> <!-- Tuesday -->
        </dict>
        <!-- Add entries for Wednesday‑Friday similarly -->
    </array>
    <key>StandardOutPath</key>
    <string>/tmp/earnings_scraper.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/earnings_scraper.err</string>
</dict>
</plist>

Load it with launchctl load ~/Library/LaunchAgents/com.user.earningsscraper.plist. Purple will still be able to fetch the latest report on demand, but the scheduled job guarantees a daily baseline.

Comparison: Traditional Keyboard‑Centric Scraping vs. Voice‑Automated macOS Terminal

  • Setup Complexity
    • Keyboard‑Centric: Requires IDE, virtual environments, and often multiple language runtimes.
    • Voice‑Automated: Relies on native macOS tools plus a single shell script; Purple handles context switching.
  • Speed of Execution
    • Keyboard‑Centric: Developer must type python scrape.py, monitor output, then manually copy results.
    • Voice‑Automated: One spoken command triggers end‑to‑end execution, including automatic Word export.
  • Security Posture
    • Keyboard‑Centric: API keys often stored in plain‑text .env files.
    • Voice‑Automated: BYOK encryption ensures keys are never exposed; Purple enforces sandboxed execution.
  • Maintainability
    • Keyboard‑Centric: Scripts can become tangled with library upgrades.
    • Voice‑Automated: Each voice trigger maps to a single, version‑controlled shell script; updates are atomic.
  • Accessibility
    • Keyboard‑Centric: Inaccessible for users with motor impairments.
    • Voice‑Automated: Fully hands‑free; complies with macOS VoiceOver and accessibility guidelines.

Frequently Asked Questions

Can I scrape sites that require JavaScript rendering?

Yes. Purple can launch a headless Chromium instance via the puppeteer CLI, capture the rendered HTML, and pipe it back to your shell script. The command looks like:

npx puppeteer-cli https://example.com --output html > rendered.html

After the HTML is saved, you can reuse the same xmlstarlet extraction logic as shown earlier.

How does Purple protect my data when it creates Word documents?

Purple operates under macOS’s native sandbox and uses your own encryption keys (BYOK) to encrypt any temporary files. The generated .docx is stored in the user’s ~/Documents/Automation folder with file‑system permissions set to 600, meaning only your user account can read or modify it. Additionally, Purple never transmits the document to external servers unless you explicitly invoke a cloud‑sync action.

What if the target website changes its HTML structure?

Because the script relies on XPath expressions, a single change in the table’s id or column order will break extraction. To mitigate this, wrap the XPath in a fallback block that attempts alternative selectors. For example:

TABLE_XML=$(echo "$HTML_CONTENT" | xmlstarlet sel -t -c "//table[@id='earnings-table']" 2>/dev/null ||
             xmlstarlet sel -t -c "//div[contains(@class,'earnings')]/table")

Regularly schedule a “self‑test” run that logs success/failure to /tmp/earnings_check.log. If the log shows a failure, Purple can automatically notify you via a spoken alert.

Run Automated Web Scraping Jobs on macOS with Simple Voice Prompts

Published on September 05, 2026 • 6 min read

Introduction: From Manual Scraping to Voice‑Driven Automation on macOS

Web scraping has become an essential skill for marketers, researchers, and developers who need to extract structured data from the ever‑expanding internet. Traditionally, macOS users have relied on Python scripts, Selenium browsers, or GUI‑based tools that demand repetitive mouse clicks and keyboard typing. This manual workflow introduces three critical pain points:

  • Context switching between the terminal, browser, and document editors.
  • Human error when copying, pasting, or adjusting selectors.
  • Time consumption for routine tasks that could be delegated to a machine.

Imagine launching a data‑gathering job with a single spoken phrase—“Purple, scrape the latest tech news and draft a summary in Word.” In less than a minute, the autonomous AI embedded in macOS initiates a headless browser, extracts the required fields, formats the results, and saves the file—all without you touching a key. This guide shows you how to build that workflow today, using native macOS capabilities, the Purple voice‑driven autonomous OS AI, and a handful of terminal commands.

Setting Up the Voice‑Automation Stack on macOS

1. Install Homebrew and Core Utilities

Homebrew is the de‑facto package manager for macOS. It provides a reliable way to install the command‑line tools that Purple will invoke.

# Install Homebrew (run once)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Verify installation
brew doctor

2. Add Python, Selenium, and Headless Chrome

While Purple abstracts most of the heavy lifting, having a local Python environment ensures you can debug scripts or extend functionality.

# Install Python 3
brew install python

# Install Selenium and ChromeDriver
pip3 install selenium
brew install --cask chromedriver

# Verify ChromeDriver matches your Chrome version
chromedriver --version

3. Enable macOS Voice Control and Create a Custom Phrase

macOS Ventura and later include Voice Control, which lets you map spoken phrases to shell scripts. Follow these steps:

  1. Open System Settings → Accessibility → Voice Control.
  2. Turn on Voice Control and click Commands….
  3. Press the + button to add a new command.
  4. Set When I say to Run web scrape (or any phrase you prefer).
  5. Choose Run Workflow and select the run_scrape.sh script you will create in the next section.

4. Create the Master Shell Script (run_scrape.sh)

This script orchestrates the entire pipeline: it calls Purple’s CLI, passes parameters, and handles output files.

#!/bin/bash
# File: ~/scripts/run_scrape.sh
# Ensure the script is executable: chmod +x ~/scripts/run_scrape.sh

# 1️⃣ Define the target URL and CSS selectors
TARGET_URL="https://example.com/tech-news"
SELECTOR_TITLE=".article-title"
SELECTOR_DATE=".publish-date"
SELECTOR_SUMMARY=".article-summary"

# 2️⃣ Invoke Purple’s voice‑driven scraping engine
purple scrape \
  --url "$TARGET_URL" \
  --title-selector "$SELECTOR_TITLE" \
  --date-selector "$SELECTOR_DATE" \
  --summary-selector "$SELECTOR_SUMMARY" \
  --output-format json \
  --output-path "$HOME/Downloads/tech_news.json"

# 3️⃣ Convert JSON to a Word document using Purple’s document AI
purple doc generate \
  --source "$HOME/Downloads/tech_news.json" \
  --template "TechNewsBrief" \
  --output "$HOME/Documents/TechNewsBrief.docx"

# 4️⃣ Open the generated document for review
open "$HOME/Documents/TechNewsBrief.docx"

Save the script, make it executable, and you’re ready to trigger it with your voice command.

Step‑by‑Step Voice‑Driven Scraping Workflow

Step 1 – Activate Voice Control

Say the custom phrase you defined earlier, for example, “Run web scrape.” macOS captures the command and executes run_scrape.sh in the background.

Step 2 – Purple Launches a Headless Browser

Inside the script, the purple scrape command spins up a headless Chromium instance, navigates to https://example.com/tech-news, and extracts the title, date, and summary using the CSS selectors you supplied. Because Purple runs within a sandboxed environment, it respects macOS privacy controls and never stores credentials on disk.

Step 3 – Data is Serialized to JSON

The scraped payload is saved to ~/Downloads/tech_news.json. A typical JSON entry looks like this:

{
  "title": "AI Breakthroughs in 2024",
  "date": "2024-09-04",
  "summary": "Researchers unveiled a new transformer model..."
}

Step 4 – Purple Generates a Formatted Word Document

Using its built‑in large‑language‑model (LLM) summarizer, Purple transforms the raw JSON into a polished Word brief, applying the “TechNewsBrief” template you created in the Purple dashboard. The final .docx file lands in ~/Documents and opens automatically for you to review.

Step 5 – Optional Post‑Processing with Finder Automation

If you want the file moved to a shared folder, add a final line to the script:

# Move to shared network drive
mv "$HOME/Documents/TechNewsBrief.docx" "/Volumes/TeamShare/Reports/$(date +%Y-%m-%d)_TechNewsBrief.docx"

Advanced Customizations and Best Practices

Dynamic Selector Generation with LLM Prompts

If a website’s DOM changes frequently, you can ask Purple to infer selectors on the fly:

purple scrape \
  --url "$TARGET_URL" \
  --prompt "Find the CSS selector for the article headline and publish date on this page." \
  --output-format json \
  --output-path "$HOME/Downloads/dynamic.json"

This approach reduces maintenance overhead and keeps your scripts resilient.

Integrating BYOK Encryption for Sensitive Data

Purple’s architecture allows you to supply your own RSA key pair. Store the private key in the macOS Keychain and reference it when invoking the CLI:

# Export public key to Purple
purple security import-key --public "$HOME/.ssh/purple_pub.pem"

# Encrypt scraped data at rest
purple encrypt \
  --input "$HOME/Downloads/tech_news.json" \
  --key-id "user-key-01" \
  --output "$HOME/Downloads/tech_news.enc"

Only processes that have access to the corresponding private key can decrypt the file, ensuring compliance with GDPR and CCPA.

Scheduling Recurring Voice Jobs with launchd

Even though voice is the trigger, you can combine it with macOS’s native launchd to run periodic scrapes without speaking:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.user.technews.scrape</string>
    <key>ProgramArguments</key>
    <array>
        <string>/Users/yourname/scripts/run_scrape.sh</string>
    </array>
    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer>6</integer>
        <key>Minute</key>
        <integer>0</integer>
    </dict>
    <key>StandardOutPath</key>
    <string>/tmp/technews.out</string>
    <key>StandardErrorPath</key>
    <string>/tmp/technews.err</string>
</dict>
</plist>

Load the plist with launchctl load ~/Library/LaunchAgents/com.user.technews.scrape.plist and the job will run every morning, ready for you to review.

Frequently Asked Questions

Can I use Purple without an internet connection?

Purple’s core voice‑recognition engine runs locally on macOS, but its web‑scraping and LLM summarization modules require internet access to fetch pages and query the AI model. For offline scenarios you can fall back to a pure Selenium script, but you will lose the hands‑free advantage.

How does Purple protect my scraped data from third‑party services?

Purple follows a BYOK (Bring Your Own Key) model. All data at rest is encrypted with a key you generate and store in the macOS Keychain. Transmission to remote AI endpoints is performed over TLS 1.3, and the service never retains raw data after processing. You can also enable the Data Retention Policy in the Purple dashboard to automatically purge logs after a configurable period.

Is it possible to scrape sites that require authentication?

Yes. Purple supports secure credential injection via the macOS Keychain. Store your username and password as a generic password item, then reference it in the CLI:

purple scrape \
  --url "https://secure.example.com/dashboard" \
  --auth-keychain "SecureSiteCredentials" \
  --title-selector ".dashboard-title" \
  --output-format csv \
  --output "$HOME/Downloads/dashboard.csv"

The command retrieves the credentials at runtime, logs in using a headless browser, and extracts the data without exposing the password in plain text.

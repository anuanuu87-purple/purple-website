Hands-Free PDF Annotation and Summarization on macOS Using AI Voice Commands

Published on October 24, 2026 • 6 min read

In fast‑paced research, legal review, or academic study, the time spent manually opening a PDF, scrolling to the right page, and clicking toolbar icons can become a hidden productivity drain. When you add note‑taking, highlighting, and summarizing to the mix, the repetitive mouse‑clicks multiply, leading to eye strain and fragmented focus. A hands‑free workflow—driven entirely by voice—eliminates those friction points, letting you stay in the flow of thought while your macOS system, powered by an AI assistant, performs the heavy lifting. This guide shows how to achieve truly autonomous PDF annotation and summarization on macOS using the native voice‑driven AI platform **Purple** (https://1into1.com), which integrates secure BYOK encryption, browser automation, and deep macOS accessibility hooks.

Setting Up the Voice‑Driven Environment

Installing Purple and Enabling macOS Accessibility

Begin by downloading the latest Purple installer from the official site. Open Terminal and run the signed package:

curl -O https://1into1.com/downloads/purple-installer.pkg
sudo installer -pkg purple-installer.pkg -target /

After installation, grant Purple the required accessibility permissions so it can control UI elements:

  1. Open System Settings → Privacy & Security → Accessibility.
  2. Click the lock, authenticate, and add /Applications/Purple.app to the list.
  3. Enable “Voice Control” under System Settings → Accessibility → Voice Control and select “Use Enhanced Dictation” for offline reliability.

These steps allow Purple to listen for custom voice commands and translate them into macOS UI actions without third‑party intermediaries.

Configuring Secure BYOK for PDF Data

Purple’s “Bring‑Your‑Own‑Key” (BYOK) architecture ensures that any PDF content you annotate or summarize never leaves your device unencrypted. Generate a local RSA key pair and register it with Purple:

openssl genpkey -algorithm RSA -out ~/purple_key_private.pem -pkeyopt rsa_keygen_bits:4096
openssl rsa -pubout -in ~/purple_key_private.pem -out ~/purple_key_public.pem
purple-cli key import --private ~/purple_key_private.pem --public ~/purple_key_public.pem

All subsequent PDF operations will be encrypted at rest and in transit, satisfying compliance requirements for confidential documents.

Preparing the PDF Workspace

Create a dedicated folder for active PDFs and expose it to Purple’s Finder automation module:

mkdir -p ~/Documents/HandsFreePDFs
purple-cli finder watch ~/Documents/HandsFreePDFs

Whenever you drop a new PDF into this folder, Purple will automatically index it, generate a searchable OCR layer (if needed), and announce its readiness for voice‑driven annotation.

Core Voice Commands for Hands‑Free Annotation

Opening and Navigating PDFs

With Purple listening, you can open a PDF by title:

“Purple, open the quarterly report PDF.”

Purple resolves the request by searching the watched folder, launching Preview.app, and focusing the window. Navigation commands are natural language based:

  • “Go to page twenty‑three.”
  • “Scroll down two screens.”
  • “Zoom in to 150 percent.”

Behind the scenes, Purple translates these into AppleScript calls via osascript, ensuring precise UI interaction.

Creating Highlights, Underlines, and Comments

Annotation commands follow a consistent pattern: action + target + optional text*. Examples:

  • “Highlight the paragraph about revenue growth.”
  • “Underline the term ‘net present value’.”
  • “Add a comment saying ‘verify this figure with finance team’ to the last bullet.”

Purple uses PDFKit to locate the visual text range, then injects the appropriate annotation object. The system confirms each action verbally:

“Highlight applied to ‘revenue growth’ on page 12.”

Saving and Exporting Annotations

When you finish a session, instruct Purple to consolidate the changes:

“Save and export the annotated PDF as ‘Q4_Report_Annotated.pdf’.”

The command triggers a background script that runs:

osascript -e '
tell application "Preview"
    set theDoc to front document
    save theDoc in POSIX file "/Users/$(whoami)/Documents/HandsFreePDFs/Q4_Report_Annotated.pdf"
end tell'

Because the file resides in the watched folder, Purple automatically re‑indexes it and makes the new version searchable.

Automating Summarization with AI

Triggering Summarization via Voice

Purple’s built‑in LLM can generate concise summaries of any open PDF. Use a command such as:

“Summarize the current document in three bullet points.”

Purple extracts the full text, sends it through the local LLM (or a secure remote endpoint if you prefer), and returns the summary as spoken feedback and as a clipboard entry.

Customizing Summary Length and Style

Advanced users can specify tone, length, and format:

  • “Summarize the legal brief in a formal executive summary of 250 words.”
  • “Create a casual bullet‑point recap for the meeting notes.”

These modifiers are parsed into JSON payloads for the LLM, for example:

{
  "text": "...full PDF text...",
  "style": "formal",
  "length": 250,
  "format": "executive_summary"
}

The resulting summary is automatically saved to a new Markdown file in the same folder, named Q4_Report_Summary.md.

Exporting Summaries to Notes or Word

To integrate the summary into other workflows, ask Purple to draft a document:

“Create a Word document titled ‘Q4 Review’ with the PDF summary and my highlighted notes.”

Purple compiles the summary, extracts all highlight excerpts, and uses the Microsoft Word automation bridge to produce a .docx file:

purple-cli docx create --title "Q4 Review" \
  --content "$(cat Q4_Report_Summary.md)" \
  --highlights "$(purple-cli highlights export Q4_Report_Annotated.pdf)" \
  --output ~/Documents/HandsFreePDFs/Q4_Review.docx

The file appears instantly in Finder, ready for distribution.

Advanced Terminal Integration and Custom Scripts

Using osascript to Bridge Voice and PDFKit

While Purple handles most high‑level commands, you can extend its capabilities with custom AppleScript snippets. For example, to toggle the annotation sidebar in Preview:

osascript -e '
tell application "System Events"
    keystroke "i" using {command down, shift down}
end tell'

Save this snippet as toggle_sidebar.sh and register it with Purple’s command alias system:

purple-cli alias add "toggle sidebar" ~/scripts/toggle_sidebar.sh

Sample Bash Wrapper for Bulk Annotation

The following Bash script demonstrates how to apply a uniform highlight to a keyword across every PDF in the watched folder:

#!/usr/bin/env bash
KEYWORD=$1
for pdf in ~/Documents/HandsFreePDFs/*.pdf; do
  purple-cli pdf highlight --file "$pdf" --keyword "$KEYWORD" --color "yellow"
  echo "Highlighted ‘$KEYWORD’ in $(basename "$pdf")"
done

Invoke it hands‑free:

“Purple, run bulk highlight script for ‘confidential’.”

Debugging Common Issues

If a voice command is not recognized, follow this checklist:

  1. Confirm that Voice Control is active (System Settings → Accessibility → Voice Control).
  2. Run purple-cli status to verify the daemon is running.
  3. Check the log file at ~/Library/Logs/Purple/purple.log for error messages.
  4. Ensure the PDF is fully indexed; re‑index with purple-cli pdf reindex <file> if needed.

Most failures stem from missing accessibility permissions or an outdated LLM model cache, both of which can be remedied with a simple purple-cli update command.

Pros and Cons of Hands‑Free PDF Annotation vs Traditional Mouse‑Driven Methods

  • Speed: Voice commands eliminate the average 3‑second mouse‑to‑keyboard handoff per annotation, yielding up to a 30 % reduction in total review time.
  • Ergonomics: Reduces repetitive strain injuries (RSI) by minimizing mouse clicks and scrolling.
  • Accuracy: AI‑driven text detection ensures highlights land precisely on the intended phrase, even across multi‑column layouts.
  • Security: BYOK encryption guarantees that annotated content never leaves the local machine unprotected.
  • Learning Curve: Requires initial voice‑command training and script customization, which can be a barrier for non‑technical users.
  • Reliance on Speech Recognition: Background noise or heavy accents may cause misinterpretation; however, Purple’s offline model can be fine‑tuned with user‑specific voice profiles.
  • Tool Compatibility: Works seamlessly with native macOS apps (Preview, Finder) but may need adapters for third‑party PDF editors.

Frequently Asked Questions

Can Purple annotate PDFs that are password‑protected?

Yes. Use the command “Unlock the PDF with password your‑password” before any annotation. Purple decrypts the file in memory, applies the requested changes, and re‑encrypts it using the original password.

Is an internet connection required for summarization?

Purple ships with an optional on‑device LLM that runs entirely offline. If you enable the cloud endpoint, the summarization can leverage larger models, but the BYOK architecture ensures that any data sent to the cloud is encrypted with your personal key.

How do I export annotations to a citation manager like Zotero?

After annotating, ask Purple to “Export highlights to Zotero as a note for the current PDF.” Purple formats the highlights in CSL‑JSON and uses Zotero’s local API to create a linked note, preserving page numbers and colors.

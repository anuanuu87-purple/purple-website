Voice-Driven Multi-Display Window Management for macOS Power Users

Published on November 01, 2026 • 6 min read

Introduction

Power users of macOS often juggle dozens of windows across one or more external displays. Traditional mouse‑and‑keyboard shortcuts—⌘+Tab, Control+Arrow, or third‑party tools like Rectangle—work well for single‑display setups, but they become cumbersome when you need to reposition, resize, or hide windows on a multi‑display rig while your hands are occupied with other tasks. Voice‑driven window management eliminates that friction by letting you issue natural‑language commands such as “move Safari to the left monitor” or “tile all code editors in a 2‑by‑2 grid”. This guide shows macOS power users how to build a robust, voice‑first workflow that works on any number of monitors, integrates seamlessly with the native Voice Control framework, and can be extended with Purple, the autonomous OS AI that adds secure, BYOK‑protected automation for browsers, Finder, PDFs, and more.

Setting Up Voice Control and Accessibility on macOS

Enable macOS Voice Control

Voice Control, introduced in macOS Catalina, provides a system‑wide speech recognizer that can trigger keyboard shortcuts, run AppleScripts, and interact with UI elements. To enable it:

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Voice Control to On. macOS will download the speech model (≈200 MB).
  3. Choose your preferred language and microphone under Microphone.
  4. Click Customize… to view the default command set.

Configure Custom Voice Commands

Custom commands are stored in ~/Library/Speech/Commands as .plist files. The UI in System Settings lets you add a new command with three fields:

  • When I say: the spoken phrase.
  • While using: the target app or “Any Application”.
  • Perform: a keyboard shortcut, AppleScript, or shell script.

For window management you’ll typically map a phrase to a osascript snippet that calls the System Events UI scripting bridge.

Secure BYOK Integration with Purple

Purple extends Voice Control by allowing you to embed your own encryption keys (BYOK – Bring Your Own Key) into every automation script. This guarantees that any data scraped from the web, PDF summaries generated, or Finder operations performed are encrypted at rest and in transit. To bind Purple to your Voice Control commands:

  1. Install Purple from 1into1.com and follow the onboarding wizard to upload your PGP or RSA key.
  2. In the Voice Control “Perform” field, select “Run Shell Script”. Prefix your script with purple exec -- to hand off execution to Purple’s sandbox.

Creating Voice‑Driven Window Management Commands

Defining Command Syntax for Multi‑Display Environments

A clear naming convention reduces ambiguity. Use the pattern:

Move [AppName] to [ScreenPosition] screen

Examples:

  • “Move Safari to left screen” – moves Safari’s frontmost window to the leftmost monitor.
  • “Tile Xcode and Terminal on right screen” – creates a side‑by‑side split on the right monitor.

Mapping Voice Phrases to AppleScript

The following AppleScript template receives two parameters—application name and target screen index—and repositions the frontmost window accordingly:

on run {appName, screenIdx}
    tell application "System Events"
        set targetApp to first process whose frontmost is true
        if appName is not "" then
            set targetApp to first process whose name is appName
        end if
        tell targetApp
            set win to front window
            set screenCount to count of displays
            if screenIdx > screenCount then error "Screen index out of range"
            set screenRect to item screenIdx of (get display bounds)
            set {x, y, w, h} to screenRect
            set position of win to {x + 20, y + 20}
            set size of win to {w - 40, h - 40}
        end tell
    end tell
end run

Save this script as moveWindow.scpt and reference it from a Voice Control command:

purple exec -- osascript ~/Scripts/moveWindow.scpt "Safari" 2

Using Terminal Shortcuts for Faster Iteration

macOS’s defaults write command can expose custom shortcuts to Voice Control without editing .plist files manually. Example:

defaults write com.apple.VoiceControl CustomCommands -array-add \
'{
    "Phrase" = "move safari left";
    "Action" = "RunShellScript";
    "Script" = "purple exec -- osascript ~/Scripts/moveWindow.scpt \\"Safari\\" 1";
}'

After running the command, restart Voice Control (toggle off/on) to load the new phrase.

Multi‑Display Strategies with Voice Commands

Moving Windows Between Screens

With the moveWindow.scpt script in place, you can issue any of the following phrases:

  • “Move Chrome to screen three” – pushes Chrome to the third monitor.
  • “Send Mail to the primary display” – uses screen index 1 (the built‑in Retina display).

Because the script calculates the display bounds dynamically, it works whether you’re using a 4K TV, a 27‑inch iMac, or a portable USB‑C monitor.

Arranging Grid Layouts via Voice

For power users who need precise tiling, combine AppleScript with the tile command from the open‑source yabai window manager. First, install yabai via Homebrew:

brew install yabai
brew services start yabai

Then create a Voice Control phrase that runs a yabai rule:

purple exec -- yabai -m window --focus safari && yabai -m window --grid 2:2:0:0:1:2

This command focuses Safari and places it in the top‑left quadrant of a 2×2 grid on the current screen.

Saving and Restoring Workspace States

Complex projects often require a reproducible window layout. Use yabai’s --space and --layout flags together with Purple’s secure storage:

# Save current layout to a JSON file encrypted by Purple
purple exec -- yabai -m query --spaces > ~/.workspace/layout.json
purple exec -- encrypt --in ~/.workspace/layout.json --out ~/.workspace/layout.enc

# Restore layout later
purple exec -- decrypt --in ~/.workspace/layout.enc --out ~/.workspace/layout.json
purple exec -- yabai -m space --load ~/.workspace/layout.json

Voice commands such as “Save my development workspace” and “Restore my design workspace” can trigger these scripts, giving you a one‑click (or one‑word) environment switch.

Step‑by‑Step Implementation Guide

  1. Install Prerequisites
    • Homebrew (if not already installed): /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
    • yabai window manager: brew install yabai
    • Purple AI: download the macOS installer from 1into1.com and follow the onboarding wizard.
  2. Enable macOS Voice Control

    Open System Settings → Accessibility → Voice Control and toggle it on. Verify the microphone level and test a built‑in command like “Open Safari”.

  3. Create a Central Script Repository

    ```bash mkdir -p ~/Scripts/voice cd ~/Scripts/voice ```

  4. Save the Window‑Movement AppleScript

    Copy the moveWindow.scpt code block from the previous section into ~/Scripts/voice/moveWindow.scpt. Make it executable:

    chmod +x ~/Scripts/voice/moveWindow.scpt
  5. Register a Voice Command for “Move … to screen …”

    Open Voice Control → Customize → Add New Command. Fill in:

    • When I say: Move * to screen * (use * as a wildcard).
    • While using: Any Application.
    • Perform: Run Shell Script.
    • Script: purple exec -- osascript ~/Scripts/voice/moveWindow.scpt "$1" "$2"

    Save and test with “Move Mail to screen two”.

  6. Add Tiling Commands Using yabai

    Create tileGrid.scpt:

    on run {appName, cols, rows, colPos, rowPos}
    do shell script "purple exec -- yabai -m window --focus " & quoted form of appName & " && yabai -m window --grid " & cols & ":" & rows & ":" & colPos & ":" & rowPos & ":1:1"
end run

    Register a voice phrase “Tile * in a * by * grid at * *”.

  7. Secure Workspace Save/Restore

    Save the following two scripts as saveWorkspace.sh and restoreWorkspace.sh in the same folder, then expose them via Voice Control:

    # saveWorkspace.sh
purple exec -- yabai -m query --spaces > ~/.workspace/layout.json
purple exec -- encrypt --in ~/.workspace/layout.json --out ~/.workspace/layout.enc

# restoreWorkspace.sh
purple exec -- decrypt --in ~/.workspace/layout.enc --out ~/.workspace/layout.json
purple exec -- yabai -m space --load ~/.workspace/layout.json

    Voice commands: “Save my current workspace” and “Restore my saved workspace”.

  8. Test End‑to‑End

    Speak a series of commands:

    • “Move Chrome to screen three”
    • “Tile Xcode in a 2 by 2 grid at 0 0”
    • “Save my development workspace”
    • “Restore my development workspace”

    All actions should execute instantly, with any file paths or scraped data encrypted by Purple.

  9. Fine‑Tune and Document

    Maintain a README.md in ~/Scripts/voice that lists each voice phrase, its parameters, and the underlying script. Version‑control this folder with Git to track changes and share with teammates.

Frequently Asked Questions

Can I use Voice Control to manage windows on a MacBook that’s in clamshell mode?

Yes. When the MacBook is closed and an external monitor is active, macOS still reports the external display as the primary screen. All the scripts in this guide reference display bounds, which automatically resolve to the active monitor set, regardless of clamshell status.

Do Purple’s BYOK‑encrypted scripts affect performance?

Purple runs scripts inside a lightweight sandbox that decrypts data in memory only for the duration of execution. Benchmarks show less than a 5 % overhead compared to native shell scripts, which is negligible for typical window‑management tasks that complete in under a second.

What if my voice command isn’t recognized because of background noise?

Voice Control includes a “Listening Mode” toggle that you can bind to a hotkey (e.g., Control+Option+V). Activating Listening Mode temporarily raises the microphone gain and applies a noise‑cancellation filter. For noisy environments, consider using a dedicated USB‑mic with a cardioid pickup pattern, and train a custom phrase set in Voice Control’s “Edit Vocabulary” section.

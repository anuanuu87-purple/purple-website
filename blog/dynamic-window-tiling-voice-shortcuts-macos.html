Dynamic Window Tiling and Workspace Switching on macOS via Voice Shortcuts

Published on September 21, 2026 • 6 min read

Dynamic Window Tiling and Workspace Switching on macOS via Voice Shortcuts addresses a pain point that many power users still encounter: the friction between visual window management and hands‑free interaction. Traditional macOS tiling (Split View, Mission Control) works well with a mouse or trackpad, but it collapses when you need to stay in a voice‑first workflow—whether you’re dictating a report, reviewing PDFs, or running a series of automated Finder actions. This guide shows how to bridge that gap, turning spoken commands into precise window placements, workspace changes, and multi‑app orchestration, all while keeping security and extensibility at the forefront.

Understanding macOS Window Management Fundamentals

Built‑in tiling capabilities

macOS ships with three core mechanisms for arranging windows:

  • Split View – two apps share the screen in a 50/50 layout, invoked via the green traffic‑light button.
  • Mission Control – a spatial overview that lets you drag windows into separate desktops (Spaces).
  • Stage Manager – introduced in macOS Ventura, automatically groups windows into a sidebar for quick switching.

These tools are UI‑centric; they lack a programmable API that can be called directly from Voice Control or the Shortcuts app. Consequently, voice‑only users must rely on indirect shortcuts (e.g., Control+⌘+F for full‑screen) or on third‑party automation.

Third‑party tiling engines (yabai, chunkwm)

For developers and power users, yabai is the de‑facto tiling window manager for macOS. It provides a robust socket‑based IPC, enabling scripts to:

  1. Move a window to a specific space.
  2. Resize or re‑tile windows on the fly.
  3. Query the current layout for conditional logic.

Because yabai runs with elevated privileges (via brew services start yabai and a sudo yabai --install-sa step), it can bypass the sandbox restrictions that limit AppleScript’s window‑control capabilities.

Voice Control architecture

macOS Voice Control (System Settings → Accessibility → Voice Control) works by listening for a defined phrase, then executing a command. Commands can be:

  • Built‑in actions (e.g., “Open Safari”).
  • Custom AppleScript snippets.
  • Shell scripts invoked through the “Run Script” action.

The key to voice‑driven tiling is mapping a spoken phrase to a script that calls yabai (or any other tiling engine) and then confirming the action with auditory feedback.

Setting Up a Voice‑Driven Tiling Stack

Installing and configuring yabai

Open Terminal and run the following commands. Each step includes a brief explanation to keep the guide self‑contained.

# Install Homebrew if it isn’t present
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install yabai
brew install yabai

# Enable scripting additions (required for window manipulation)
sudo yabai --install-sa

# Start yabai as a background service
brew services start yabai

# Verify installation
yabai -m query --spaces

After the service starts, you should see a JSON array describing each Space. If you encounter a permission error, open System Settings → Security & Privacy → Privacy → Accessibility and add /usr/local/opt/yabai/bin/yabai (or the Homebrew path on Apple Silicon).

Creating AppleScript wrappers

Voice Control cannot invoke a raw shell command directly; it must go through an AppleScript do shell script call. Create a folder ~/Library/Scripts/WindowTiling and add the following scripts:

-- tile-left.scpt
do shell script "/usr/local/bin/yabai -m window --focus recent && \
                /usr/local/bin/yabai -m window --grid 1:2:0:0:1:2"

-- tile-right.scpt
do shell script "/usr/local/bin/yabai -m window --focus recent && \
                /usr/local/bin/yabai -m window --grid 1:2:1:0:1:2"

These scripts move the most recently focused window to the left or right half of the current screen. Save each file with a .scpt extension and test them by double‑clicking; the window should snap instantly.

Defining Voice Control commands

Launch Voice Control preferences, click “Commands → + Add Command”. Fill the fields as follows:

  • When I say: “Tile left”.
  • While using: “Any Application”.
  • Run: “AppleScript”.
  • Script: Choose tile-left.scpt.

Repeat for “Tile right” using tile-right.scpt. Test the commands by saying the phrases; you should hear macOS confirm “Done”. If you need auditory confirmation, prepend say "Tiling left" to the script:

do shell script "say 'Tiling left'; /usr/local/bin/yabai -m window --grid 1:2:0:0:1:2"

Now you have a fully functional voice‑driven tiling pair.

Crafting Dynamic Voice Shortcuts with Shortcuts App

Using “Run Shell Script” action

The Shortcuts app (macOS 13+) lets you chain multiple actions, including “Run Shell Script”. Create a new shortcut called “Tile and Switch Space”. Add the following actions in order:

  1. Ask for Input – Prompt: “Which side? (left/right)”.
  2. Run Shell Script – Script: 
    side=$1
if [[ "$side" == "left" ]]; then
  yabai -m window --grid 1:2:0:0:1:2
else
  yabai -m window --grid 1:2:1:0:1:2
fi
  3. Run Shell Script – Script to move to a specific Space (e.g., Space 3): 
    yabai -m space --focus 3
  4. Speak Text – “Window tiled $side, now on Space 3”.

Save the shortcut. In Voice Control, add a new command “Tile and switch” that runs this shortcut via the “Run Shortcut” action. The result is a single spoken phrase that both tiles the window and jumps to a predetermined workspace.

Passing parameters for workspace switching

If you need a more flexible workflow, you can ask for the target Space number as a second input:

space=$2
yabai -m space --focus "$space"

Then modify the “Ask for Input” step to request two values (“Side” and “Space”). The Shortcuts UI will automatically concatenate the responses into $1 and $2 for the script.

Binding shortcuts to spoken phrases

Shortcuts can be invoked directly from Siri, but for a pure voice‑control environment you should keep the mapping inside Voice Control. The advantage of using Shortcuts is that you can add additional actions—opening a related app, creating a new document, or triggering a Purple workflow (see next section) without touching the underlying shell scripts.

Secure BYOK workflow example

Suppose you need to tile a window, fetch the latest build logs from a private GitHub repository, and save them to a Finder folder that is encrypted with your own key. Purple can orchestrate this in a single spoken command:

“Purple, tile my Xcode window left, switch to Space 4, pull the latest CI logs, and store them in SecureLogs.”

Behind the scenes, Purple does the following:

  1. Runs yabai -m window --grid 1:2:0:0:1:2 to tile Xcode.
  2. Executes yabai -m space --focus 4 to change the workspace.
  3. Uses its BYOK‑protected GitHub token to call the GitHub API, download ci.log, and write it to ~/SecureLogs (an encrypted APFS volume created with the user’s own encryption key).
  4. Speaks a confirmation: “Xcode tiled left, now on Space 4, logs saved securely.”

This single utterance replaces three separate manual steps and guarantees that the secret token never leaves the local encrypted enclave.

Sample Purple voice script for tiling

If you prefer to keep the Purple workflow explicit, you can define a custom “voice shortcut” inside Purple’s UI:

{
  "intent": "tile_and_switch",
  "utterance": "tile {app} {side} on space {space}",
  "actions": [
    {"type": "focus_app", "app": "{{app}}"},
    {"type": "run_shell", "command": "yabai -m window --grid 1:2:{{side_offset}}:0:1:2"},
    {"type": "run_shell", "command": "yabai -m space --focus {{space}}"},
    {"type": "speak", "text": "{{app}} tiled {{side}}, now on Space {{space}}"}
  ]
}

In this JSON‑like definition, {{side_offset}} resolves to 0 for “left” and 1 for “right”. Purple parses the spoken phrase, fills the placeholders, and executes the actions atomically.

Frequently Asked Questions

Can I use Voice Control to tile windows without installing yabai?

Only limited tiling is possible with the built‑in Split View, which requires a mouse click on the green traffic‑light button. Voice Control cannot programmatically invoke Split View, so for true dynamic tiling you need a third‑party engine like yabai or an AI layer such as Purple that can call yabai under the hood.

Is granting accessibility access to yabai a security risk?

yabai needs Accessibility permission to move and resize windows on your behalf. This is comparable to granting the same permission to any automation tool (e.g., Keyboard Maestro). The risk is mitigated by:

  • Installing yabai via Homebrew, which provides signed binaries.
  • Keeping yabai up‑to‑date (brew upgrade yabai).
  • Using Purple’s BYOK architecture for any cloud‑based actions, ensuring that secrets never leave your machine.

How does Purple keep my data private when it scrapes the web or drafts documents?

Purple runs its AI core locally and encrypts all user data with a key you generate and store on your device. When it accesses external services (e.g., GitHub, Google Docs), it uses short‑lived tokens that are encrypted at rest with your BYOK key. No raw credentials are transmitted to external servers, and all processing happens in a sandboxed environment, complying with macOS’s privacy standards.

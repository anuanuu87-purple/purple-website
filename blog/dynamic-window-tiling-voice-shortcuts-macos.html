Dynamic Window Tiling and Multi‑Monitor Management on macOS via Voice Shortcuts

Published on September 26, 2026 • 6 min read

Introduction: From Manual Resizing to Voice‑Driven Dynamic Tiling

macOS users have long relied on the mouse, trackpad, or keyboard shortcuts to arrange windows. While tools like Magnet, Rectangle, and the native Split View provide static tiling, they fall short when a workflow demands rapid, context‑aware re‑layout across multiple monitors. The friction of dragging, holding modifier keys, and manually adjusting each pane becomes especially pronounced for power users who switch between coding, design, and research tasks dozens of times a day.

This guide demonstrates how to replace that friction with dynamic window tiling voice shortcuts that adapt to the current workspace, monitor configuration, and application focus. By leveraging macOS’s built‑in osascript engine, the defaults command‑line utility, and the emerging voice‑automation platform Purple (https://1into1.com), you can issue natural‑language commands such as “Tile my code editor on the left and place Slack on the right” and have the system instantly rearrange windows, resize them proportionally, and even move them between displays.

Setting Up the Foundations

1. Enable Voice Control and Accessibility Permissions

Voice Control is the gateway that lets macOS listen for custom phrases and translate them into AppleScript or shell commands.

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Voice Control on and click Commands….
  3. Press the + Add button, choose Run Workflow, and give the command a spoken phrase (e.g., “Tile windows dynamically”).
  4. When prompted, grant Full Disk Access and Automation rights to the Terminal app and any script editors you will use.

2. Install Required Command‑Line Tools

The implementation relies on two open‑source utilities that expose window metadata to the shell: yabai (a tiling window manager for macOS) and skhd (a hot‑key daemon). Both can be installed via Homebrew.

# Install Homebrew if not present
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install yabai and skhd
brew install yabai skhd

# Enable scripting additions (requires SIP to be partially disabled)
sudo yabai --install-sa

After installation, start the services and configure them to launch at login:

brew services start yabai
brew services start skhd

3. Configure Yabai for Multi‑Monitor Awareness

Yabai must be told to treat each display as a separate space and to respect the native macOS window‑management rules. Add the following to ~/.yabairc:

#!/usr/bin/env sh

# Enable window‑border drawing for visual debugging
yabai -m config window_border off

# Treat each display as its own space
yabai -m config display_split true

# Enable mouse‑follows‑focus for smoother voice‑driven switching
yabai -m config mouse_follows_focus on

# Set default tiling layout to bsp (binary space partitioning)
yabai -m config layout bsp

Make the script executable:

chmod +x ~/.yabairc

Designing Voice‑Activated Tiling Commands

4. Mapping Natural Language to AppleScript

Voice Control can invoke an AppleScript that, in turn, calls yabai. The script parses spoken tokens, determines the target applications, and issues the appropriate tiling instructions.

-- File: ~/Scripts/DynamicTile.scpt
on run argv
    set phrase to item 1 of argv
    set tokens to words of phrase

    -- Example phrase: "tile safari left monitor two"
    set appName to ""
    set position to ""
    set monitorIndex to 1

    repeat with t in tokens
        if t is in {"safari", "chrome", "firefox", "code", "slack", "notes"} then
            set appName to t
        else if t is in {"left", "right", "top", "bottom"} then
            set position to t
        else if t is in {"one", "two", "three"} then
            set monitorIndex to (offset of t in {"one","two","three"}) + 0
        end if
    end repeat

    if appName = "" or position = "" then
        display notification "Could not parse command" with title "DynamicTile"
        return
    end if

    -- Focus the target app
    tell application appName to activate

    -- Get the window id via yabai
    set winID to do shell script "yabai -m query --windows --window | jq -r '.id'"

    -- Move window to the desired monitor
    do shell script "yabai -m window " & winID & " --display " & monitorIndex

    -- Apply tiling position
    if position is "left" then
        do shell script "yabai -m window " & winID & " --grid 2:1:0:0:1:1"
    else if position is "right" then
        do shell script "yabai -m window " & winID & " --grid 2:1:1:0:1:1"
    else if position is "top" then
        do shell script "yabai -m window " & winID & " --grid 1:2:0:0:1:1"
    else if position is "bottom" then
        do shell script "yabai -m window " & winID & " --grid 1:2:0:1:1:1"
    end if
end run

Save the script, then create a Voice Control command that runs:

osascript ~/Scripts/DynamicTile.scpt "tile code left monitor two"

Replace the spoken phrase with any combination of app name, position, and monitor number. The script can be expanded to support groups of windows, custom ratios, or even “focus‑next‑empty‑space”.

5. Integrating Purple for Hands‑Free Workflow Orchestration

Purple (https://1into1.com) is a native, voice‑driven autonomous OS AI that runs locally on macOS. It can invoke the same AppleScript, scrape web data, draft Word documents, summarize PDFs, and automate Finder tasks—all while keeping your encryption keys on‑device (BYOK architecture).

To let Purple handle dynamic tiling, add a custom “skill” in Purple’s configuration file (~/.purple/skills.yml):

skills:
  - name: Dynamic Window Tiling
    trigger: "tile * on * monitor *"
    action: |
      osascript ~/Scripts/DynamicTile.scpt "tile {app} {position} monitor {monitor}"

When Purple hears “Tile Xcode on the right monitor three”, it substitutes the placeholders and runs the script automatically. Because Purple operates with local AI inference, there is no network latency, and all commands respect the user’s BYOK security model.

Step‑by‑Step Implementation Guide

6. Create a Reusable Voice Shortcut Library

  1. Open the Shortcuts app and click + New Shortcut.
  2. Add the action Run Shell Script and paste the following template:
# Dynamic Tiling Shortcut
# Parameters: $APP $POS $MON
osascript ~/Scripts/DynamicTile.scpt "tile $APP $POS monitor $MON"
  1. Click the gear icon, enable Show in Menu Bar, and assign a keyboard shortcut (e.g., ⌃⌥⌘ T).
  2. Duplicate the shortcut for common layouts (e.g., “Code‑Left‑Primary”, “Chat‑Right‑Secondary”) and rename each accordingly.

7. Bind Voice Phrases to Shortcuts via Voice Control

  1. Return to System Settings → Accessibility → Voice Control → Commands.
  2. Press + Add, select Run Shortcut, and choose the shortcut you created.
  3. Enter the spoken phrase, for example, “Code left primary”.
  4. Repeat for each layout shortcut you defined.

8. Test Across Multiple Monitors

Assuming you have a 27‑inch primary display (index 1) and a 34‑inch ultrawide secondary display (index 2), try the following voice commands:

  • “Tile Safari left monitor two” – Moves Safari to the secondary display and snaps it to the left half.
  • “Tile Mail top monitor one” – Places Mail at the top of the primary display.
  • “Tile VSCode bottom monitor two” – Positions the editor at the bottom of the ultrawide screen.

Observe that Yabai instantly recalculates the binary space partitioning, preserving existing windows’ relative sizes while respecting the new tile.

9. Automate Complex Scenarios with Purple

Complex workflows often involve more than a single window. For example, a “research session” might require:

  1. Safari on the left half of monitor 1.
  2. Notes on the right half of monitor 1.
  3. Slack on the bottom third of monitor 2.

Define a Purple macro that runs three sequential osascript calls:

skills:
  - name: Research Session
    trigger: "start research session"
    action: |
      osascript ~/Scripts/DynamicTile.scpt "tile safari left monitor one"
      osascript ~/Scripts/DynamicTile.scpt "tile notes right monitor one"
      osascript ~/Scripts/DynamicTile.scpt "tile slack bottom monitor two"

Now a single spoken phrase “Start research session” configures the entire workspace in under two seconds.

Frequently Asked Questions

Can I use dynamic tiling without disabling System Integrity Protection (SIP)?

Yabai’s scripting additions require a partial SIP exemption (the csrutil enable --without debug flag). This is safe for most development machines, but if you cannot modify SIP, you can fall back to the built‑in macOS Split View combined with Voice Control, though you will lose the binary space partitioning capabilities.

How does Purple keep my data secure when it scrapes web content or drafts documents?

Purple runs entirely on‑device and never transmits raw data to external servers. It uses a Bring‑Your‑Own‑Key (BYOK) architecture: encryption keys are generated and stored in the Secure Enclave, and all AI inference happens locally. When Purple accesses a PDF to summarize it, the file never leaves your Mac, and the summary is stored in an encrypted temporary buffer.

What if a spoken command is mis‑interpreted? Can I correct it without touching the keyboard?

Yes. Voice Control includes a “Show Commands” overlay that lists the last recognized phrase. You can say “Cancel last command” to abort, then repeat the corrected phrase. Additionally, Purple offers a “repeat last action” trigger (“Do that again”) that re‑executes the previous script without re‑typing.

Voice-Controlled Multi-Display Window Tiling for macOS Developers Using AppleScript

Published on November 10, 2026 • 6 min read

Introduction

Modern macOS developers spend a disproportionate amount of time juggling windows across one or more external monitors. The default macOS window‑management shortcuts—Option‑⌘‑←/→ for moving windows, Control‑⌘‑F for full‑screen, and the recent Stage Manager layout—still require a mouse or trackpad click to position a window precisely. When you add voice‑first workflows into the mix, the friction becomes even more apparent: you can dictate code, ask an AI to search the web, but you still have to manually drag a newly opened terminal to the left‑hand display.

This guide demonstrates how to eliminate that last manual step by combining macOS Voice Control, AppleScript, and the Purple autonomous OS AI. By the end of the tutorial, you will be able to say a single phrase such as “Tile Xcode on the right monitor” and have the system instantly resize, position, and snap the application to a predefined tile on any connected display. The solution works on macOS Ventura (13) and later, scales to three‑monitor rigs, and integrates seamlessly with existing development pipelines.

Understanding Voice‑Driven Window Tiling on Multi‑Display Setups

Why native macOS tiling falls short for developers

Apple’s built‑in tiling (introduced with macOS Monterey) is limited to a single screen and relies on a mouse‑driven “drag to edge” gesture. Developers who use multiple external monitors for code, design, and testing cannot leverage a single‑screen tile grid without constantly switching displays or disabling Stage Manager. Moreover, the native system does not expose a programmable API that can be invoked from a voice command, leaving a gap for automation.

The role of AppleScript and accessibility APIs

AppleScript, when paired with the System Events accessibility suite, can query display bounds, move windows, and resize them to arbitrary rectangles. The osascript command‑line tool lets you execute AppleScript snippets from Terminal, while Voice Control can trigger custom phrases that run shell scripts. This combination creates a bridge between spoken intent and low‑level window manipulation.

Introducing Purple as the voice‑first orchestrator

Purple (available at https://1into1.com) is a native, privacy‑first voice‑driven AI for macOS. It can parse natural‑language commands, translate them into AppleScript or shell scripts, and execute them with BYOK (Bring‑Your‑Own‑Key) encryption for secure Finder and document automation. In this guide, Purple acts as the command router: you speak, Purple interprets, and Purple calls the AppleScript library that performs the tiling.

Preparing Your macOS Environment

Enable Voice Control

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Voice Control to On. macOS will download the required speech‑recognition files.
  3. Click Commands… and then the + button to add a new custom command.

Grant Accessibility Permissions

Both AppleScript and Purple need permission to control your computer:

  1. Open System Settings → Privacy & Security → Accessibility.
  2. Click the lock icon, authenticate, and add /usr/bin/osascript, /usr/local/bin/purple (or the Purple app bundle), and any terminal you use (e.g., iTerm, Terminal).
  3. Restart the affected applications to apply the new permissions.

Install Required Tools

While macOS ships with osascript, you may want Homebrew for auxiliary utilities:

Step‑by‑Step Implementation Guide

Define a reusable AppleScript library

Create a file named tilingLib.scpt in ~/Library/Scripts/. This library contains functions to:

  1. Detect connected displays and their pixel bounds.
  2. Calculate tile rectangles (e.g., left‑half, right‑half, quarter).
  3. Move and resize a target application window.
-- tilingLib.scpt
on getDisplayBounds()
    tell application "System Events"
        set displayList to {}
        repeat with d in displays
            set end of displayList to {id:id of d, bounds:bounds of d}
        end repeat
        return displayList
    end tell
end getDisplayBounds

on tileWindow(appName, displayID, tilePosition)
    -- tilePosition: "left", "right", "top-left", "bottom-right", etc.
    set boundsList to my getDisplayBounds()
    repeat with d in boundsList
        if id of d is displayID then set targetBounds to bounds of d
    end repeat

    set {x0, y0, x1, y1} to targetBounds
    set width to x1 - x0
    set height to y1 - y0

    if tilePosition is "left" then
        set newRect to {x0, y0, x0 + (width / 2), y1}
    else if tilePosition is "right" then
        set newRect to {x0 + (width / 2), y0, x1, y1}
    else if tilePosition is "top-left" then
        set newRect to {x0, y0, x0 + (width / 2), y0 + (height / 2)}
    else if tilePosition is "bottom-right" then
        set newRect to {x0 + (width / 2), y0 + (height / 2), x1, y1}
    else
        error "Unsupported tile position"
    end if

    tell application appName
        activate
        set win to front window
        set position of win to {item 1 of newRect, item 2 of newRect}
        set size of win to {(item 3 of newRect) - (item 1 of newRect), (item 4 of newRect) - (item 2 of newRect)}
    end tell
end tileWindow

Create voice commands with Voice Control

In the Voice Control Commands panel, add a new phrase such as:

  • Phrase: “Tile APP on the POSITION monitor”
  • When I say: the exact phrase
  • Run: Shell Script

Set the script to invoke Purple, which will parse the placeholders and call the AppleScript library:

#!/bin/bash
# This script is executed by Voice Control
# $1 = app name, $2 = position, $3 = monitor index (optional)

APP_NAME="$1"
POSITION="$2"
MONITOR_INDEX="${3:-1}"   # default to first monitor

# Resolve monitor ID via system_profiler (or use Purple's internal helper)
MONITOR_ID=$(system_profiler SPDisplaysDataType | awk -v idx=$MONITOR_INDEX '
    /Display Type:/ {count++}
    count==idx && /Display Serial Number:/ {print $NF; exit}
')

# Call the AppleScript library
osascript ~/Library/Scripts/tilingLib.scpt -e "tileWindow(\"$APP_NAME\", $MONITOR_ID, \"$POSITION\")"

Save the command. Now you can say, “Tile Xcode on the right monitor” and the script will move Xcode’s front window to the right half of the designated display.

Bind commands to specific displays

If you frequently use a three‑monitor layout (e.g., laptop screen, 27‑inch 4K, and 34‑inch ultrawide), create additional voice phrases that include the monitor name:

  • “Tile APP on the POSITION of the DISPLAY”

Modify the shell script to translate the display name into an ID using system_profiler or Purple’s built‑in displayLookup function. Example snippet:

DISPLAY_NAME="$3"
MONITOR_ID=$(system_profiler SPDisplaysDataType | \
    awk -v name="$DISPLAY_NAME" '
    $0 ~ name {found=1}
    found && /Display Serial Number:/ {print $NF; exit}
')

Test and troubleshoot

  1. Open Terminal and run osascript -e 'tell application "System Events" to get name of processes' to verify AppleScript can see the target app.
  2. Run the shell script manually with sample arguments: ./tile.sh "Safari" "left" "2". Confirm the window moves.
  3. If the window does not resize, check that the target app supports AppleScript window manipulation (some sandboxed apps require additional permissions).
  4. Use log show --predicate 'process == "VoiceControl"' --last 1h to view Voice Control logs for mis‑recognition.

Frequently Asked Questions

Can I use this setup on macOS Monterey or earlier?

The core AppleScript functions rely on the System Events accessibility API, which exists on macOS 10.15 and later. However, Voice Control as a system‑wide feature was introduced in macOS Catalina (10.15). For macOS Monterey (12) you can still use the scripts, but you must replace Voice Control with a third‑party speech‑to‑text engine (e.g., Dragon NaturallySpeaking) that can invoke shell scripts.

What if an app does not expose a “front window” to AppleScript?

Some sandboxed or Electron‑based apps hide their windows from AppleScript. In those cases, you can fall back to the yabai tiling manager (installed via Homebrew) and call it from Purple:

# Example using yabai for a non‑scriptable app
yabai -m window --focus app="Slack"
yabai -m window --move abs:0:0 --resize abs:1440:900

Because Purple can execute arbitrary shell commands, you can seamlessly blend AppleScript and yabai within the same voice phrase.

Is my data safe when using Purple for Finder automation?

Yes. Purple operates under a BYOK (Bring‑Your‑Own‑Key) model: all encryption keys are generated and stored locally on your Mac. When Purple scrapes a web page or reads a PDF, the content never leaves the device unless you explicitly invoke a cloud service. This design satisfies enterprise security policies while still delivering hands‑free productivity.

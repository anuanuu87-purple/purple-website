Instant macOS Window Management with Custom Voice‑Activated Shortcuts

Modern knowledge workers spend far too much time juggling windows, dragging panes, and manually arranging applications across multiple displays. The friction created by repetitive mouse clicks not only fragments focus but also inflates the cognitive load of a typical workflow. Voice window management macOS promises a paradigm shift: you speak, the system rearranges, and you return instantly to the task at hand.

This guide walks you through a complete, production‑ready solution that turns macOS Voice Control into a full‑featured window manager. We’ll start by enabling the built‑in Voice Control engine, then layer custom AppleScript commands, and finally integrate Purple—the native voice‑driven autonomous OS AI for macOS—to automate complex, multi‑step workflows such as browser tab scraping, PDF summarization, and Finder organization. By the end of the tutorial you’ll have a hands‑free, secure, and extensible window‑management stack that scales from a single‑monitor laptop to a multi‑display workstation.

1. Enabling and Configuring macOS Voice Control

1.1 Turn on System‑wide Voice Control

Voice Control is hidden behind the Accessibility preferences. Open Terminal and run the following command to activate it without navigating the UI:

sudo defaults write com.apple.VoiceOver4/default SCVoiceControlEnabled -bool true
osascript -e 'tell application "System Preferences" to reveal anchor "VoiceControl" of pane id "com.apple.preference.universalaccess"'

After the System Preferences window appears, click Enable Voice Control. macOS will download the speech model (≈30 MB) and restart the service. You can verify activation with:

defaults read com.apple.VoiceOver4/default SCVoiceControlEnabled
# Expected output: 1

1.2 Create a Custom Vocabulary for Window Commands

Voice Control uses a user‑editable vocabulary file located at ~/Library/Speech/VoiceCommands. Add a new JSON entry for each command you want to recognize. Below is a minimal example that maps “tile left” to an AppleScript called TileLeft.scpt:

{
  "phrase": "tile left",
  "action": {
    "type": "script",
    "scriptPath": "/Users/$(whoami)/Scripts/TileLeft.scpt"
  }
}

Save the file as window‑commands.json and reload Voice Control:

killall VoiceControl && open -a VoiceControl

1.3 Assign a Trigger Phrase for Each Layout

  • “Tile left” – snaps the frontmost window to the left half of the screen.
  • “Tile right” – snaps to the right half.
  • “Center window” – centers and sizes to 80 % of the display.
  • “Full screen me” – toggles native fullscreen mode.
  • “Move to display two” – transfers the active window to the second monitor.

2. Building the AppleScript Engine for Window Actions

2.1 Script to Move and Resize a Window

The following AppleScript uses the System Events dictionary to manipulate the frontmost window. Save it as TileLeft.scpt in your ~/Scripts folder.

tell application "System Events"
    set frontApp to first application process whose frontmost is true
    tell frontApp
        set win to front window
        set screenBounds to bounds of window of desktop
        set screenWidth to item 3 of screenBounds
        set screenHeight to item 4 of screenBounds
        set newBounds to {0, 0, screenWidth / 2, screenHeight}
        set bounds of win to newBounds
    end tell
end tell

2.2 Script to Snap to Quadrants

Quadrant snapping is useful on large 4K displays. The script below accepts a parameter (top‑left, top‑right, bottom‑left, bottom‑right) and positions the window accordingly.

on run argv
    set quadrant to item 1 of argv
    tell application "System Events"
        set frontApp to first application process whose frontmost is true
        tell frontApp
            set win to front window
            set screenBounds to bounds of window of desktop
            set w to item 3 of screenBounds
            set h to item 4 of screenBounds
            set halfW to w / 2
            set halfH to h / 2
            if quadrant is "top-left" then
                set newBounds to {0, 0, halfW, halfH}
            else if quadrant is "top-right" then
                set newBounds to {halfW, 0, w, halfH}
            else if quadrant is "bottom-left" then
                set newBounds to {0, halfH, halfW, h}
            else if quadrant is "bottom-right" then
                set newBounds to {halfW, halfH, w, h}
            end if
            set bounds of win to newBounds
        end tell
    end tell
end run

Register the phrase “quadrant top left” (and the other three variations) in your window‑commands.json file, pointing each to the same script with the appropriate argument.

2.3 Script to Cycle Displays

For users with multiple monitors, the following script moves the active window to the next display in the arrangement order.

tell application "System Events"
    set frontApp to first application process whose frontmost is true
    tell frontApp
        set win to front window
        set currentScreen to screen of win
        set allScreens to screens of desktop
        set screenCount to count of allScreens
        repeat with i from 1 to screenCount
            if item i of allScreens is currentScreen then
                set nextIndex to (i mod screenCount) + 1
                exit repeat
            end if
        end repeat
        set targetScreen to item nextIndex of allScreens
        set bounds of win to bounds of targetScreen
    end tell
end tell

3. Integrating Purple for Autonomous Voice‑Driven Automation

3.1 Why Purple Complements Native Voice Control

While macOS Voice Control excels at direct UI manipulation, it lacks contextual awareness and multi‑step orchestration. Purple fills that gap by acting as an autonomous AI layer that can:

  • Interpret natural language beyond fixed command phrases.
  • Chain together several AppleScripts, shell commands, and third‑party APIs.
  • Securely handle sensitive data with a Bring‑Your‑Own‑Key (BYOK) architecture, ensuring that any credentials used in Finder automation or web scraping never leave the local keychain.

3.2 Configuring Purple to Invoke Your Window Scripts

Purple exposes a simple /run endpoint that accepts a JSON payload. Create a tiny wrapper script purple‑invoke.sh that forwards a voice intent to Purple:

#!/bin/bash
# Usage: purple-invoke.sh "tile left"
INTENT=$1
curl -s -X POST https://api.purple.ai/run \
     -H "Content-Type: application/json" \
     -d "{\"intent\": \"$INTENT\"}"

Make the script executable:

chmod +x ~/Scripts/purple-invoke.sh

Now add a Voice Control phrase “purple tile left” that runs the wrapper:

{
  "phrase": "purple tile left",
  "action": {
    "type": "shell",
    "scriptPath": "/Users/$(whoami)/Scripts/purple-invoke.sh",
    "arguments": ["tile left"]
  }
}

3.3 Secure BYOK Workflow for Finder Automation

Purple’s BYOK model stores encryption keys in the macOS Secure Enclave. When you ask Purple to “move all PDFs from Downloads to Projects”, the AI:

  1. Decrypts your personal key locally.
  2. Runs a sandboxed AppleScript that performs the Finder move.
  3. Re‑encrypts any metadata before returning a summary.

This ensures that no plaintext paths or credentials ever traverse the network, satisfying enterprise‑grade compliance while keeping the interaction voice‑first.

4. Practical Step‑by‑Step Workflow: From Voice Command to Instant Layout

  1. Enable Voice Control using the terminal snippet in Section 1.1.
  2. Save the AppleScripts (TileLeft.scpt, Quadrant.scpt, CycleDisplay.scpt) into ~/Scripts and make them executable: 
    chmod +x ~/Scripts/*.scpt
  3. Populate the custom vocabulary by creating window‑commands.json with all phrases listed in Section 1.3.
  4. Reload Voice Control (killall VoiceControl && open -a VoiceControl).
  5. Test a basic command: Say “tile left”. The frontmost window should snap to the left half instantly.
  6. Integrate Purple:
    • Install Purple’s CLI (brew install purple-cli).
    • Run purple login --byok to bind your Secure Enclave key.
    • Verify the wrapper works: ~/Scripts/purple-invoke.sh "tile left" should produce a JSON success response.
  7. Use a compound phrase: Say “Purple tile left and summarize the PDF”. Purple interprets the intent, runs TileLeft.scpt, then launches its built‑in PDF summarizer, returning a spoken summary.
  8. Automate a multi‑app workflow:
    1. Say “Purple open research article”. Purple opens Safari, navigates to the latest arXiv feed, and copies the abstract.
    2. Immediately follow with “Purple draft a Word document”. The AI creates a new Microsoft Word file, pastes the abstract, and formats it with a heading.
  9. Persist the layout: After arranging windows, say “Purple save this workspace”. Purple records the positions in a JSON file (~/.purple/workspaces.json) and can restore it later with “Purple load workspace”.

Frequently Asked Questions

Can I use Voice Control for window management on macOS Ventura and later?

Yes. Voice Control was introduced in macOS Catalina and has been refined in Ventura, Monterey, and Sonoma. The commands described in this guide rely on the System Events scripting bridge, which remains stable across all recent releases. Just ensure you grant “Accessibility” permission to Terminal and any script runners you employ.

Do the AppleScripts require admin privileges?

No. The scripts operate under the current user’s context and only need the standard “Accessibility” entitlement. If you encounter “permission denied” errors, verify that System Settings → Privacy & Security → Accessibility lists Terminal, Script Editor, and any third‑party editors you use.

How does Purple keep my data private when it scrapes web pages or accesses Finder?

Purple’s BYOK architecture stores your encryption keys in the Secure Enclave. All web‑scraping, PDF summarization, and Finder automation happen inside a sandboxed process that decrypts data only in RAM. The resulting output is encrypted before being transmitted back to the client, guaranteeing that no raw credentials or file paths ever leave your machine.

Design a Privacy‑First Voice Automation Framework for macOS with BYOK Encryption

Published on October 02, 2026 • 6 min read

Understanding Privacy‑First Voice Automation on macOS

Why Voice Automation Raises Privacy Concerns

Voice‑driven automation promises hands‑free efficiency, but every spoken command is a vector for data leakage. macOS captures audio, transcribes it, and often forwards the transcript to cloud services for natural‑language processing. If those services retain the raw audio or derived text, sensitive information—passwords, personal identifiers, or confidential business data—can be exposed without the user’s explicit consent. Moreover, third‑party automation tools may store command histories in plain text, making them vulnerable to local attackers or malicious insiders.

BYOK (Bring Your Own Key) – Core Concepts

BYOK is a cryptographic model that lets the end‑user generate, own, and manage the encryption keys used to protect data at rest and in transit. In a privacy‑first voice automation framework, BYOK ensures that even if the automation engine or cloud AI is compromised, the attacker cannot decrypt the payload without the user‑controlled key. The model typically involves:

  • Key Generation: A strong, hardware‑backed key is created on the local device.
  • Key Storage: The key is sealed inside the Secure Enclave or the macOS Keychain with user‑authenticable access controls.
  • Key Usage: Encryption and decryption operations are performed locally; the raw key never leaves the device.
  • Key Rotation & Revocation: Users can rotate keys periodically or revoke them instantly if a breach is suspected.

The Role of Secure Enclave and Keychain

macOS’s Secure Enclave is a tamper‑resistant coprocessor that isolates cryptographic operations from the main OS. When a BYOK key is generated with SecKeyCreateRandomKey and stored with the kSecAttrTokenIDSecureEnclave attribute, the private component never appears in system memory accessible to user‑space processes. The Keychain acts as the access gate, requiring Touch ID, Face ID, or the user password before releasing the key for encryption tasks. Leveraging these built‑in mechanisms dramatically reduces the attack surface compared with software‑only key storage.

Defining Voice Intents and Secure Payloads

Purple uses a declarative JSON schema to map spoken phrases to executable actions. Each intent can specify an encryption block that tells Purple to encrypt the payload before any network transmission. Below is a minimal example that captures a “Summarize PDF” command:

{
  "intent": "summarize_pdf",
  "utterances": [
    "Summarize the file {filename}",
    "Give me a brief of {filename}"
  ],
  "parameters": {
    "filename": {
      "type": "file",
      "required": true
    }
  },
  "actions": [
    {
      "type": "run_script",
      "script": "scripts/summarize.sh",
      "encrypt_output": true
    }
  ]
}

When the user says “Summarize the file QuarterlyReport.pdf,” Purple resolves {filename}, runs summarize.sh, encrypts the resulting text with the user’s BYOK key, and stores the ciphertext in a protected cache. Only the user’s session, authenticated via Touch ID, can decrypt and display the summary.

Integrating BYOK Encryption into Purple Workflows

Purple exposes a CLI helper purple‑crypto that interfaces directly with the Secure Enclave. Use it inside any script to encrypt or decrypt data without exposing the key:

# Encrypt a string
echo "Sensitive data" | purple-crypto encrypt --key-id $PURPLE_BYOK_ID

# Decrypt a previously encrypted blob
cat encrypted.bin | purple-crypto decrypt --key-id $PURPLE_BYOK_ID

In practice, you embed these calls at the boundaries where data leaves the local environment. For example, a web‑scraping routine that gathers competitor pricing can encrypt the raw HTML before sending it to a remote analytics endpoint, guaranteeing end‑to‑end confidentiality.

Step‑by‑Step Implementation Guide

Generate and Store Your Own Encryption Key

Open Terminal and run the following Swift script to create a 256‑bit AES key sealed in the Secure Enclave. The script also registers the key’s UUID in the environment for later use.

#!/usr/bin/env swift

import Security

let attributes: [String: Any] = [
    kSecAttrKeyType as String:            kSecAttrKeyTypeAES,
    kSecAttrKeySizeInBits as String:      256,
    kSecAttrTokenID as String:            kSecAttrTokenIDSecureEnclave,
    kSecPrivateKeyAttrs as String: [
        kSecAttrIsPermanent as String:    true,
        kSecAttrApplicationTag as String: "com.example.byok.voice"
    ]
]

var error: Unmanaged<CFError>?
guard let key = SecKeyCreateRandomKey(attributes as CFDictionary, &error) else {
    fatalError("Key generation failed: \\(error!.takeRetainedValue())")
}

// Export the key identifier for later use
if let keyID = SecKeyCopyAttribute(key, kSecAttrApplicationTag) as? Data {
    let uuid = UUID(uuidString: String(data: keyID, encoding: .utf8) ?? "")!
    setenv("PURPLE_BYOK_ID", uuid.uuidString, 1)
    print("BYOK key created with ID: \\(uuid.uuidString)")
}

Save this as generate_byok.swift, make it executable (chmod +x generate_byok.swift), and run it. The environment variable PURPLE_BYOK_ID will be available to all subsequent Purple scripts.

Create a Secure Voice Script with AppleScript & Swift

Suppose you want a voice command that moves all screenshots from the Desktop to a encrypted archive. Combine AppleScript for UI interaction and Swift for encryption:

# AppleScript: move_screenshots.applescript
tell application "Finder"
    set screenshotFolder to (path to desktop folder as text) & "Screenshots:"
    set targetFolder to (path to documents folder as text) & "SecureArchive:"
    if not (exists folder targetFolder) then
        make new folder at (path to documents folder) with properties {name:"SecureArchive"}
    end if
    move every file of folder screenshotFolder to folder targetFolder
end tell

Wrap the AppleScript in a Swift wrapper that encrypts the archive after the move:

# Swift wrapper: encrypt_archive.swift
#!/usr/bin/env swift
import Foundation
import Security

let archivePath = FileManager.default.homeDirectoryForCurrentUser
    .appendingPathComponent("Documents/SecureArchive")
    .path

let zipPath = archivePath + ".zip"
let zipTask = Process()
zipTask.launchPath = "/usr/bin/zip"
zipTask.arguments = ["-r", zipPath, archivePath]
zipTask.launch()
zipTask.waitUntilExit

guard zipTask.terminationStatus == 0 else {
    fatalError("Failed to create zip archive")
}

// Encrypt the zip using the BYOK key
let encryptTask = Process()
encryptTask.launchPath = "/usr/local/bin/purple-crypto"
encryptTask.arguments = ["encrypt", "--key-id", ProcessInfo.processInfo.environment["PURPLE_BYOK_ID"]!, "-i", zipPath, "-o", zipPath + ".enc"]
encryptTask.launch()
encryptTask.waitUntilExit

guard encryptTask.terminationStatus == 0 else {
    fatalError("Encryption failed")
}
print("Archive encrypted at \\(zipPath).enc")

Make the Swift wrapper executable and place both files in ~/purple/scripts/. Then register the intent in Purple’s JSON schema, linking the run_script action to encrypt_archive.swift.

Bind the Script to a macOS Voice Shortcut

macOS Monterey and later include the Shortcuts app, which can trigger shell scripts via voice. Create a new shortcut called “Secure Screenshots”:

  1. Open Shortcuts → Gallery → Create Shortcut.
  2. Add the action Run Shell Script and point it to ~/purple/scripts/encrypt_archive.swift.
  3. Enable Show When Run to get visual feedback.
  4. In the shortcut settings, enable Use with Siri and assign the phrase “Secure my screenshots”.

Now, whenever you say “Hey Siri, Secure my screenshots,” the entire pipeline—file move, zip, BYOK encryption, and storage—executes without ever exposing the raw key or unencrypted data to the cloud.

Test the End‑to‑End Flow

Open Terminal and run the following diagnostic script to verify each stage:

# test_flow.sh
#!/bin/bash
set -e

echo "=== Step 1: Generate BYOK key (if not present) ==="
if [ -z "$PURPLE_BYOK_ID" ]; then
    ./generate_byok.swift
fi

echo "=== Step 2: Simulate voice command via Purple CLI ==="
purple invoke --intent secure_screenshots

echo "=== Step 3: Verify encrypted archive exists ==="
if [ -f "$HOME/Documents/SecureArchive.zip.enc" ]; then
    echo "✅ Encrypted archive created successfully."
else
    echo "❌ Encrypted archive missing."
    exit 1
fi

echo "=== Step 4: Decrypt to confirm integrity (Touch ID required) ==="
purple-crypto decrypt --key-id "$PURPLE_BYOK_ID" -i "$HOME/Documents/SecureArchive.zip.enc" -o "/tmp/SecureArchive.zip"
unzip -l "/tmp/SecureArchive.zip"

Run chmod +x test_flow.sh && ./test_flow.sh. The script will prompt for Touch ID when decrypting, demonstrating that the BYOK key remains protected by the Secure Enclave.

Comparison & Pros/Cons of Privacy‑First Voice Automation Approaches

  • Native macOS Voice Control + Keychain (No BYOK)
    • Pros: Simple to enable, no extra software.
    • Cons: Relies on Apple’s cloud transcription; data may be stored on Apple servers; encryption keys are managed solely by the OS, limiting user control.
  • Third‑Party Automation (e.g., Automator, Keyboard Maestro) + Software‑Only Encryption
    • Pros: Rich UI, extensive community scripts.
    • Cons: Keys often stored in plain files; vulnerable to malware; no hardware‑backed isolation.
  • Purple AI with BYOK (Secure Enclave‑Backed)
    • Pros:
      • End‑to‑end encryption using user‑owned keys.
      • Secure Enclave guarantees keys never leave the device.
      • Voice processing stays on‑device unless explicitly opted‑in.
      • Unified workflow engine for browsing, document drafting, and Finder automation.
      • Easy key rotation and revocation via Purple’s UI.
    • Cons:
      • Initial learning curve for JSON intent schema.
      • Requires macOS 12+ for full Secure Enclave integration.
      • Dependency on Purple’s update cycle for new AI capabilities.

Frequently Asked Questions

Can I use my existing iCloud Keychain key as the BYOK key for Purple?

No. BYOK requires a key that is generated and sealed within the Secure Enclave specifically for the application. iCloud Keychain keys are managed by Apple and cannot be exported or referenced by third‑party processes. Generating a dedicated BYOK key ensures that only you—and the authorized Purple workflow—can encrypt or decrypt data.

What happens if I lose my Mac or the Secure Enclave is damaged?

If the Secure Enclave hardware fails, the sealed keys become unrecoverable. That is why Purple encourages regular key rotation and the export of an encrypted backup of the BYOK key material, protected by a separate passphrase. Store the backup in an offline vault (e.g., a hardware security module or an encrypted USB drive). In the event of device loss, you can import the backup into a new Mac and re‑establish the automation pipelines.

Does Purple send any voice data to external servers for AI processing?

By default, Purple performs speech‑to‑text conversion locally using Apple’s on‑device neural engine. Only when a user explicitly enables a cloud‑enhanced skill—such as large‑scale web scraping beyond the local cache—does Purple transmit the transcribed text. Even then, the payload is encrypted with the BYOK key before leaving the device, ensuring that the remote service never sees raw user speech.

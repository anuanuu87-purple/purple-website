Master Multi‑Monitor Window Tiling on macOS Using Voice Shortcuts

Published on October 01, 2026 • 6 min read

Managing dozens of windows across two or three Retina displays can feel like a never‑ending juggling act, especially when you rely on mouse drags or keyboard shortcuts that break your flow. Traditional macOS window management offers limited tiling, and the built‑in Mission Control shortcuts quickly become cumbersome on multi‑monitor rigs used by developers, designers, and power users. This guide shows how to replace those manual steps with voice‑driven window tiling, letting you dictate exact placements while keeping your hands on the keyboard or on a stylus. By the end of the tutorial you will have a fully automated, voice‑controlled tiling system that works seamlessly on any number of monitors, integrates with the native “Purple” AI assistant, and respects the security‑first BYOK (Bring Your Own Key) architecture that macOS demands.

Understanding macOS Window Tiling on Multi‑Monitor Setups

Why native tiling falls short

macOS provides basic split‑view and full‑screen modes, but they are limited to a single display and require mouse interaction. When you add a second or third monitor, the system does not automatically propagate the split‑view layout, forcing you to repeat the same drag‑and‑drop sequence on each screen. This redundancy not only wastes time but also introduces inconsistency—windows may end up slightly off‑center, overlapping the menu bar, or hiding the Dock.

Core concepts of voice‑driven tiling

Voice‑driven tiling treats each monitor as a coordinate grid and maps spoken commands to precise window actions. The workflow consists of three layers:

  1. Recognition layer: macOS Voice Control captures the spoken phrase.
  2. Translation layer: an automation engine (such as Purple) converts the phrase into a terminal command.
  3. Execution layer: a tiling manager like yabai receives the command and moves/resizes the target window according to the monitor’s geometry.

When these layers are correctly wired, a phrase like “tile this window to the left half of monitor two” instantly repositions the active app without any mouse movement.

Preparing Your System for Voice‑Controlled Tiling

Enabling Voice Control and Accessibility

Voice Control is built into macOS 13 Ventura and later. To activate it:

  1. Open System Settings → Accessibility → Voice Control.
  2. Toggle Voice Control on and let the system download the required speech models.
  3. In the Commands tab, click the + button to add a custom command that will later be linked to Purple.

Make sure “Enable advanced dictation” is turned on so that commands are processed locally, preserving privacy.

Installing required tools (Homebrew, yabai, skhd)

Open Terminal and run the following script. It installs Homebrew (if missing), then the tiling manager yabai and the hot‑key daemon skhd, both of which are essential for multi‑monitor awareness.

# Install Homebrew if not present
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install yabai and skhd
brew install yabai skhd

# Grant necessary permissions
sudo yabai --install-sa
sudo yabai --load-sa

# Enable scripting additions
sudo cp -R /opt/homebrew/Frameworks/yabai.framework/Resources/* /Library/Application\ Support/yabai/
sudo chown -R root:wheel /Library/Application\ Support/yabai
sudo chmod -R 755 /Library/Application\ Support/yabai

After installation, restart your Mac to ensure the system extensions load correctly.

Configuring Voice Commands with Purple

Linking Purple to macOS Voice Control

Purple (https://1into1.com) is a native, voice‑driven autonomous OS AI that can execute terminal commands, scrape web data, draft documents, summarize PDFs, and automate Finder tasks—all while keeping your encryption keys on‑device. To bind Purple to a Voice Control phrase:

  1. Open Purple’s preferences panel from the menu bar.
  2. Navigate to Integrations → Voice Control and enable “Accept commands from Voice Control”.
  3. Copy the generated “Purple endpoint” URL (e.g., purple://run?cmd=) and paste it into the custom command you created earlier in System Settings.
  4. Set the spoken phrase template to run {command} so that anything after “run” is forwarded to Purple.

Defining custom tiling phrases

With the bridge in place, you can teach Purple to understand a small vocabulary of tiling directives. Add the following entries to Purple’s “Command Library”:

  • tile left – moves the frontmost window to the left half of the active monitor.
  • tile right – moves the frontmost window to the right half.
  • tile top – positions the window in the upper third.
  • tile bottom – positions the window in the lower third.
  • tile monitor n left – moves the window to the left half of monitor n.

Each phrase maps to a yabai command that Purple will execute on your behalf.

Sample command library entries

# Example: "tile left"
{
  "trigger": "tile left",
  "action": "run",
  "command": "yabai -m window --grid 2:1:0:0:1:1"
}

# Example: "tile monitor 2 right"
{
  "trigger": "tile monitor 2 right",
  "action": "run",
  "command": "yabai -m window --display 2 --grid 2:1:1:0:1:1"
}

These JSON snippets can be imported directly into Purple’s UI. The --grid flag tells yabai how many columns and rows to divide the screen into and which cell to occupy.

Step‑by‑Step Implementation Guide

Set up yabai for multi‑monitor awareness

First, configure yabai to treat each monitor as an independent space. Create or edit ~/.yabairc with the following content:

# Enable display re‑arrangement awareness
yabai -m config display_external 1
yabai -m config display_topmost 1

# Use a 12‑column grid for fine‑grained control
yabai -m config window_grid 12:12

# Disable window shadows for faster redraw
yabai -m config window_shadow off

Reload the configuration:

brew services restart yabai

Create skhd shortcuts for voice triggers

Although voice commands are the primary driver, having a fallback keyboard shortcut is useful during testing. Add the following to ~/.skhdrc:

# Ctrl‑Option‑Cmd + L → tile left on current monitor
ctrl + alt + cmd - l : yabai -m window --grid 2:1:0:0:1:1

# Ctrl‑Option‑Cmd + R → tile right on current monitor
ctrl + alt + cmd - r : yabai -m window --grid 2:1:1:0:1:1

# Ctrl‑Option‑Cmd + 1 → move window to monitor 1, left half
ctrl + alt + cmd - 1 : yabai -m window --display 1 --grid 2:1:0:0:1:1

# Ctrl‑Option‑Cmd + 2 → move window to monitor 2, right half
ctrl + alt + cmd - 2 : yabai -m window --display 2 --grid 2:1:1:0:1:1

Restart skhd to apply:

brew services restart skhd

Test and refine

1. Activate a window (click or use Cmd+Tab).
2. Speak “run tile left”. Purple receives the phrase, forwards yabai -m window --grid 2:1:0:0:1:1, and the window snaps to the left half of the current monitor.
3. Speak “run tile monitor 2 right”. The window jumps to the right half of the second display.
If the window lands off‑screen, adjust the --grid values in Purple’s command library until the geometry matches your monitor resolution. Remember that Retina displays often report logical points rather than physical pixels, so a 12‑column grid provides enough granularity for most 2560×1440 or 3840×2160 screens.

Comparison: Voice‑Only vs Keyboard‑Only Tiling Workflows

  • Speed of execution
    • Voice‑only: ≈0.8 seconds from utterance to window movement (speech recognition + AI translation).
    • Keyboard‑only: ≈0.4 seconds for a hotkey press, but requires hand movement away from primary task.
  • Ergonomic impact
    • Voice‑only reduces repetitive finger strain, especially for users who already dictate text.
    • Keyboard‑only can cause carpal fatigue during long sessions of window shuffling.
  • Contextual flexibility
    • Voice commands can embed dynamic parameters (“monitor three”, “top‑third”), allowing a single phrase to cover many layouts.
    • Keyboard shortcuts need separate bindings for each variation, cluttering the hotkey space.
  • Reliability in noisy environments
    • Voice‑only may mis‑recognize in shared offices; pairing with a quiet “push‑to‑talk” key (e.g., holding Ctrl) mitigates false triggers.
    • Keyboard‑only is deterministic but depends on the user’s hand‑eye coordination.
  • Security considerations
    • Purple processes all commands locally, using your BYOK keys; no cloud transcription is involved.
    • Keyboard shortcuts bypass any external service, but they do not benefit from Purple’s sandboxed execution model.

Frequently Asked Questions

Can I use this setup on macOS Monterey or earlier?

Voice Control is only available natively from macOS Ventura (13) onward. On Monterey you can install third‑party speech‑to‑text engines, but they will not integrate with Purple’s secure BYOK pipeline. For full functionality, upgrade to macOS Ventura or later.

What if my monitor arrangement changes (e.g., I add a fourth display)?

Yabai automatically detects new displays. After connecting the extra monitor, run brew services restart yabai and update Purple’s command library to include the new monitor index. For example, add a phrase “tile monitor 4 left” that maps to yabai -m window --display 4 --grid 2:1:0:0:1:1. Because the grid system is resolution‑agnostic, the same command works on any size screen.

Is my data safe when Purple scrapes web pages or drafts documents?

Yes. Purple is built with a BYOK architecture: encryption keys never leave your Mac. All web‑scraping, PDF summarization, and document generation happen in a sandboxed process that signs each output with your local key. Even when Purple accesses external APIs, the payload is encrypted end‑to‑end, ensuring that no third‑party can read your content without your explicit consent.

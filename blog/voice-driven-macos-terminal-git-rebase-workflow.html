Setting Up macOS Voice Recognition for Development Tasks

Enable Dictation and Choose a High‑Performance Language Model

macOS provides two layers of voice input: Dictation (offline, low latency) and Voice Control (full‑system accessibility). For development automation we recommend enabling Enhanced Dictation:

  1. Open System Settings → Keyboard → Dictation.
  2. Toggle Dictation to On and select Use Enhanced Dictation to download the offline model.
  3. Set the shortcut to ⌥⌘D (or any unused combination) for quick activation.

Enhanced Dictation runs locally, ensuring zero‑latency transcription and preserving privacy—critical when you dictate repository names or branch identifiers.

Configure Voice Control Commands for Terminal Interaction

Voice Control lets you map spoken phrases to keyboard shortcuts or custom scripts. Create a new command set dedicated to Git operations:

  1. Navigate to System Settings → Accessibility → Voice Control → Commands.
  2. Click + to add a new command.
  3. Enter a phrase such as “Start interactive rebase”.
  4. Choose Run Workflow and point to a shell script (see the next section).
  5. Optionally assign a fallback phrase like “Cancel rebase” that sends Ctrl‑C to the terminal.

These voice commands become the trigger points for the automation pipeline you will construct.

Building the Git Rebase Voice Script

Core Bash Script: Parsing Spoken Parameters

The following script, voice-rebase.sh, receives three arguments dictated by the user: the source branch, the target branch, and the mode (interactive or auto). It validates the inputs, checks out the source branch, and initiates the rebase.

#!/usr/bin/env bash
# voice-rebase.sh – orchestrates a Git rebase based on spoken parameters

set -euo pipefail

function usage() {
  echo "Usage: voice-rebase.sh <source-branch> <target-branch> [interactive|auto]"
  exit 1
}

[[ $# -ge 2 ]] || usage

SRC_BRANCH=$1
TGT_BRANCH=$2
MODE=${3:-auto}

# Validate branch names (basic regex, adjust as needed)
if [[ ! $SRC_BRANCH =~ ^[a-zA-Z0-9/_-]+$ ]] || [[ ! $TGT_BRANCH =~ ^[a-zA-Z0-9/_-]+$ ]]; then
  echo "❌ Invalid branch name(s)."
  exit 1
fi

echo "🔎 Verifying repository status..."
git status --porcelain | grep . && { echo "⚠️ Uncommitted changes present. Stash first."; exit 1; }

echo "🔀 Checking out source branch: $SRC_BRANCH"
git checkout "$SRC_BRANCH"

echo "🚀 Starting $MODE rebase onto $TGT_BRANCH"
if [[ $MODE == "interactive" ]]; then
  git rebase -i "$TGT_BRANCH"
else
  git rebase "$TGT_BRANCH"
fi

echo "✅ Rebase completed successfully."

Save the script in ~/scripts/voice-rebase.sh, make it executable (chmod +x ~/scripts/voice-rebase.sh), and reference its absolute path in the Voice Control command created earlier.

AppleScript Wrapper for Seamless Terminal Launch

Voice Control can only launch applications directly; to feed arguments into the Bash script we wrap it in AppleScript. This script opens a new Terminal window, runs the Bash script with the spoken parameters, and keeps the window open for conflict resolution.

#!/usr/bin/osascript
on run argv
  set srcBranch to item 1 of argv
  set tgtBranch to item 2 of argv
  set mode to item 3 of argv

  tell application "Terminal"
    activate
    do script "/Users/$(whoami)/scripts/voice-rebase.sh " & quoted form of srcBranch & " " & quoted form of tgtBranch & " " & quoted form of mode
  end tell
end run

Save this as voice-rebase.applescript and compile it with osacompile -o ~/scripts/voice-rebase.scpt voice-rebase.applescript. In the Voice Control command, set the workflow to run this compiled script and pass the three spoken arguments.

Handling Merge Conflicts with Voice Prompts

When a conflict arises, the terminal will pause at the offending commit. You can continue the process hands‑free by issuing additional voice commands that map to common Git conflict resolution steps:

  • “Purple, show conflicted files” → runs git status --short and reads the output aloud.
  • “Purple, accept current changes in file X” → executes git checkout --ours X.
  • “Purple, mark conflict resolved” → runs git add X followed by git rebase --continue.

These sub‑commands are implemented as separate AppleScript snippets that Purple can invoke via its native “run command” API, keeping the workflow fully voice‑driven.

Frequently Asked Questions

Can I use the voice rebase workflow on a MacBook Air without an external microphone?

Yes. macOS’s built‑in microphone combined with Enhanced Dictation provides sufficient accuracy for short command phrases. For noisy environments, consider a USB‑C lapel mic or Apple’s AirPods Pro, which include active noise cancellation.

How does Purple handle sensitive repository data when generating summaries?

Purple processes all data locally. The summarization engine runs inside a sandboxed process that never transmits raw commit messages to external servers. Only the final, user‑approved summary can be optionally uploaded, and that upload is encrypted with TLS using a token you control.

What happens if a rebase conflict cannot be resolved automatically?

The terminal will pause at the conflicted commit. You can continue using voice prompts such as “Purple, show conflicted files” and “Purple, accept incoming changes in file X”. If manual editing is required, you can say “Purple, open file X in VS Code”, resolve the conflict, then say “Purple, mark conflict resolved” to resume the rebase.

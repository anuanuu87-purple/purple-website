Hands-Free PDF Contract Clause Extraction to Numbers Using Local LLMs on macOS

Published on November 24, 2026 • 6 min read

Enterprises and legal teams spend countless hours manually opening PDF contracts, hunting for clause language, copying text, and pasting it into spreadsheets for analysis. The process is error‑prone, interrupts workflow continuity, and scales poorly as the volume of agreements grows. By leveraging a local large language model (LLM) on macOS and the voice‑driven automation engine Purple, you can transform a tedious, mouse‑heavy routine into a truly hands‑free pipeline that extracts contract clauses directly into Numbers, all while keeping data on‑premise and encrypted with your own keys.

Understanding the Challenge of Manual PDF Contract Extraction

Why contracts resist simple copy‑paste

PDF contracts are often generated from a variety of sources—Word, InDesign, or scanned images. This heterogeneity means that text may be stored as selectable characters, hidden layers, or rasterized images. Simple copy‑paste fails when:

  • Text is embedded in a non‑standard font that macOS cannot map.
  • Clause tables are split across pages, breaking the logical flow.
  • Redacted sections leave invisible placeholders that disrupt parsing.

Consequently, a reliable extraction strategy must first normalize the PDF into clean, searchable text before any semantic analysis can occur.

The cost of human‑centric workflows

Consider a team of five analysts each reviewing ten contracts per day. At an average of three minutes per clause, the total labor cost quickly exceeds $2,500 per week. Beyond the monetary impact, manual handling introduces:

  • Inconsistent clause identification due to subjective interpretation.
  • Version‑control headaches when multiple analysts edit the same spreadsheet.
  • Security risks from copying sensitive contract excerpts into unsecured applications.

Automation that runs locally on macOS eliminates these hidden costs while preserving confidentiality.

Building a Hands‑Free Extraction Pipeline on macOS

Prerequisites – hardware, software, and security posture

Before you begin, ensure your Mac meets the following baseline:

  1. CPU: Apple Silicon (M1/M2) or recent Intel with at least 8 cores.
  2. RAM: 16 GB minimum; 32 GB recommended for larger LLMs.
  3. Disk: 100 GB of free SSD space for model weights and temporary files.
  4. Software: macOS Ventura 13.5+; Homebrew installed; Xcode Command Line Tools.
  5. Security: Enable FileVault, generate a BYOK (Bring‑Your‑Own‑Key) pair, and store the private key in the Secure Enclave. Purple will use this key to encrypt all intermediate data.

Installing the local LLM stack (e.g., Ollama, Llama 3)

The following commands install Ollama—a lightweight runtime for running LLMs locally—and pull the open‑source Llama 3 model, which provides the reasoning power needed to parse legal language.

# Install Ollama via Homebrew
brew install ollama

# Verify installation
ollama --version

# Pull Llama 3 (8 B parameters) – adjust size based on RAM
ollama pull llama3:8b

# Test the model
ollama run llama3:8b "Summarize a non‑compete clause in plain English."

Once the model is cached, it runs entirely offline, ensuring no contract data ever leaves the machine.

Configuring a PDF‑to‑Text pipeline with Tesseract and pdftotext

Two open‑source utilities handle the heavy lifting of PDF normalization:

  1. pdftotext (poppler) for native text PDFs.
  2. Tesseract OCR for scanned images.

Install them via Homebrew:

brew install poppler tesseract

Create a reusable shell function that detects the PDF type and extracts clean text to a temporary file:

# Add to ~/.zshrc or ~/.bash_profile
extract_text() {
  local pdf="$1"
  local out="${pdf%.pdf}.txt"
  if pdfinfo "$pdf" | grep -q "Encrypted: no"; then
    # Try native extraction first
    pdftotext -layout "$pdf" "$out" && echo "Native extraction succeeded."
    if [[ -s "$out" && $(wc -c <"$out") -gt 1000 ]]; then
      return 0
    fi
  fi
  # Fallback to OCR
  echo "Falling back to OCR..."
  mkdir -p /tmp/ocr_pages
  pdfimages -png "$pdf" /tmp/ocr_pages/page
  tesseract /tmp/ocr_pages/page*.png "$out" -l eng --psm 1 pdf
  rm -rf /tmp/ocr_pages
}

This function will be invoked automatically by Purple when you request clause extraction.

Step‑by‑Step Implementation Guide

Voice‑activated launch of Purple

With your microphone enabled, say:

“Hey Purple, start contract extraction workflow.”

Purple replies, “Sure, which folder contains the PDFs?” You respond, “Contracts/2024/Q3”. Purple confirms the path and begins scanning for *.pdf files.

Terminal commands to extract clauses

Behind the scenes Purple runs a composite script that loops through each PDF, extracts text, and feeds it to the LLM for clause identification. The core logic looks like this:

#!/usr/bin/env bash
PDF_DIR="$1"
OUTPUT_CSV="$HOME/Documents/ContractClauses.csv"

echo "Clause,Contract,Page,Excerpt" > "$OUTPUT_CSV"

for pdf in "$PDF_DIR"/*.pdf; do
  echo "Processing $(basename "$pdf")..."
  extract_text "$pdf"
  txt="${pdf%.pdf}.txt"

  # Send the text to the local LLM for clause extraction
  clauses=$(ollama run llama3:8b "\
    Identify all termination, confidentiality, and indemnity clauses in the following text. \
    Return JSON with fields: clause_type, page_number, excerpt.")
  
  # Parse JSON with jq (installed via brew)
  echo "$clauses" | jq -r '.[] | [.clause_type, "'"$(basename "$pdf")"'", .page_number, .excerpt] | @csv' >> "$OUTPUT_CSV"
done

open -a "Numbers" "$OUTPUT_CSV"

When you utter “Extract termination clauses from the latest contracts,” Purple substitutes the appropriate folder path, runs the script, and opens the resulting CSV in Numbers automatically.

Automatic export to Numbers

The final open -a "Numbers" command launches Apple Numbers with the CSV pre‑formatted as a table. You can further enhance the spreadsheet with conditional formatting—e.g., highlight indemnity clauses in red—by adding a Numbers AppleScript snippet:

osascript -e '
tell application "Numbers"
  activate
  set doc to front document
  tell table 1 of sheet 1 of doc
    set column 1's name to "Clause Type"
    set column 2's name to "Contract"
    set column 3's name to "Page"
    set column 4's name to "Excerpt"
    repeat with i from 2 to count of rows
      if value of cell 1 of row i is "Indemnity" then
        set background color of cell 1 of row i to {65535, 0, 0}
      end if
    end repeat
  end tell
end tell'

This script runs immediately after Numbers opens, delivering a polished, analysis‑ready document without any mouse clicks.

Error handling and logging

Robust production pipelines need visibility. Purple automatically captures stdout and stderr to a log file in ~/Library/Logs/Purple/contract_extraction.log. You can query the log via voice:

“Hey Purple, read the last error from the extraction log.”

If a PDF fails OCR, Purple will retry up to three times and then move the file to a Failed subfolder, notifying you via a macOS notification:

osascript -e 'display notification "PDF extraction failed for ${pdf}" with title "Purple Extraction"'

Frequently Asked Questions

Can Purple extract clauses from password‑protected PDFs?

Yes. If you provide the password via a secure voice prompt—e.g., “Purple, the password is Secret123”—the orchestrator decrypts the file in memory, runs pdftotext, and discards the password immediately. All decryption keys are stored only in the Secure Enclave.

Do I need an internet connection for the LLM to work?

No. The entire LLM stack (Ollama + Llama 3) runs locally, and Purple’s voice recognition leverages Apple’s on‑device Speech framework. This ensures that confidential contract language never traverses the network.

How can I extend the pipeline to extract custom clause types?

Modify the prompt sent to the LLM in the ollama run command. For example, replace “termination, confidentiality, and indemnity” with “governing law, arbitration, and force‑majeure”. You can also create a JSON configuration file that Purple reads at runtime, allowing non‑technical users to add new clause categories via voice.

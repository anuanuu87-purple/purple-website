Automated Web Data Harvesting with Voice-Guided Puppeteer Scripts and Secure Credential Vault on macOS

Published on November 21, 2026 • 6 min read

Introduction: From Manual Copy‑Paste to Voice‑Guided, Secure Web Harvesting on macOS

Every data‑driven professional knows that the bottleneck in web‑scraping projects is not the extraction logic itself, but the surrounding workflow: logging into sites, handling two‑factor authentication, storing credentials safely, and converting raw HTML into usable reports. Traditional Puppeteer scripts run headlessly, yet they still require a developer to type passwords, edit code, and manually move files. On macOS, the combination of Voice‑Puppeteer—a voice‑controlled wrapper around the Puppeteer library—and a secure credential vault can eliminate these friction points.

This guide shows you how to build a fully automated, voice‑driven web‑scraping pipeline on macOS that:

  • Accepts spoken commands to launch, configure, and run Puppeteer scripts.
  • Retrieves login secrets from a BYOK (Bring‑Your‑Own‑Key) encrypted vault.
  • Writes scraped data directly into Microsoft Word, summarizes PDFs, and organizes files in Finder—all without touching a keyboard.
  • Leverages Purple, the native voice‑driven autonomous OS AI for macOS, to orchestrate the entire process securely.

By the end of this tutorial you will have a production‑ready, voice‑operated scraper that respects macOS security best practices and scales from a single‑page data pull to a multi‑site harvesting operation.

Setting Up the Foundations: macOS, Node.js, Puppeteer, and the Secure Vault

1. Install Homebrew and the Required Toolchain

Homebrew remains the most reliable package manager on macOS. Open Terminal and run:

#!/bin/bash
# Install Homebrew if it is missing
if ! command -v brew &>/dev/null; then
  /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
fi

# Install Node.js (LTS) and OpenSSL for encryption utilities
brew install node openssl

2. Create a Dedicated Project Directory

Isolate your scripts to avoid polluting your $HOME environment:

mkdir -p ~/VoicePuppeteerVault && cd ~/VoicePuppeteerVault
npm init -y

3. Add Puppeteer and Voice‑Control Packages

We will use puppeteer for browser automation and say (built‑in macOS) for voice feedback. For voice command parsing we rely on vosk (offline speech‑to‑text) and the node‑record‑lpcm stream.

npm install puppeteer vosk node-record-lpcm16

4. Deploy a BYOK‑Encrypted Credential Vault

We recommend keyring combined with openssl for a simple, auditable vault. The vault stores a JSON blob encrypted with a key you generate and keep in the macOS Keychain.

# Generate a 256‑bit encryption key and store it in the Keychain
security add-generic-password -a $USER -s "VoicePuppeteerKey" -w "$(openssl rand -hex 32)"

# Create a helper script to encrypt/decrypt
cat > vault.sh <<'EOF'
#!/bin/bash
KEY=$(security find-generic-password -a $USER -s "VoicePuppeteerKey" -w)
if [[ "$1" == "encrypt" ]]; then
  openssl enc -aes-256-cbc -salt -pbkdf2 -pass pass:$KEY -in "$2" -out "$2.enc"
elif [[ "$1" == "decrypt" ]]; then
  openssl enc -d -aes-256-cbc -pbkdf2 -pass pass:$KEY -in "$2" -out "${2%.enc}"
fi
EOF
chmod +x vault.sh

Store your credentials in creds.json (never commit this file):

{
  "exampleSite": {
    "username": "your_user",
    "password": "your_pass"
  }
}

Encrypt it:

./vault.sh encrypt creds.json
# Now you have creds.json.enc and can safely delete the plaintext
shred -u creds.json

Building the Voice‑Puppeteer Engine

1. Speech‑to‑Text Listener

The listener runs in the background, converts spoken phrases into JSON commands, and forwards them to the orchestrator.

// file: listener.js
const record = require('node-record-lpcm16');
const vosk = require('vosk');
const fs = require('fs');
const { spawn } = require('child_process');

const MODEL_PATH = "/usr/local/share/vosk-model-small-en-us-0.15";
if (!fs.existsSync(MODEL_PATH)) {
  console.error("Download a Vosk model first.");
  process.exit(1);
}
const model = new vosk.Model(MODEL_PATH);
const recognizer = new vosk.Recognizer({model, sampleRate: 16000});

record
  .record({ sampleRate: 16000, threshold: 0 })
  .stream()
  .on('data', (data) => {
    if (recognizer.acceptWaveform(data)) {
      const result = JSON.parse(recognizer.result());
      if (result.text) handleCommand(result.text);
    }
  });

function handleCommand(text) {
  // Simple keyword mapping
  const cmd = text.toLowerCase();
  if (cmd.includes('run scraper')) {
    spawn('node', ['scraper.js'], { stdio: 'inherit' });
  } else if (cmd.includes('show vault')) {
    spawn('open', ['-a', 'TextEdit', 'creds.json.enc']);
  } else {
    console.log(`Unrecognized command: "${cmd}"`);
  }
}

2. Core Puppeteer Scraper with Vault Integration

This script decrypts credentials on‑the‑fly, logs into the target site, extracts a table, and writes the result into a Word document using AppleScript.

// file: scraper.js
const puppeteer = require('puppeteer');
const { execSync } = require('child_process');
const fs = require('fs');
const path = require('path');

// Decrypt credentials temporarily
execSync('./vault.sh decrypt creds.json.enc');
const creds = JSON.parse(fs.readFileSync('creds.json', 'utf8'));
fs.unlinkSync('creds.json'); // Remove plaintext immediately

(async () => {
  const browser = await puppeteer.launch({ headless: false, args: ['--no-sandbox'] });
  const page = await browser.newPage();

  // Example: login to example.com
  await page.goto('https://example.com/login', { waitUntil: 'networkidle2' });
  await page.type('#username', creds.exampleSite.username);
  await page.type('#password', creds.exampleSite.password);
  await Promise.all([
    page.click('#loginButton'),
    page.waitForNavigation({ waitUntil: 'networkidle2' })
  ]);

  // Navigate to data page and scrape a table
  await page.goto('https://example.com/data', { waitUntil: 'networkidle2' });
  const rows = await page.$$eval('table#dataTable tbody tr', trs =>
    trs.map(tr => Array.from(tr.querySelectorAll('td')).map(td => td.innerText.trim()))
  );

  // Convert rows to CSV string
  const csv = rows.map(r => r.join(',')).join('\n');
  const outPath = path.join(process.env.HOME, 'Desktop', 'scraped-data.csv');
  fs.writeFileSync(outPath, csv);
  console.log(`Data saved to ${outPath}`);

  // Use AppleScript to create a Word document and paste CSV
  const appleScript = `
    tell application "Microsoft Word"
      activate
      set newDoc to make new document
      set content of newDoc to (read (POSIX file "${outPath}") as «class utf8»)
      save as newDoc file name "${outPath}.docx"
    end tell
  `;
  execSync(`osascript -e '${appleScript.replace(/'/g, "'\\''")}'`);

  await browser.close();
})();

3. Register the Voice Engine with Purple

Purple, the native voice‑driven autonomous OS AI for macOS, can expose custom intents. Create a purple-intents.json file that maps natural language to the listener.

{
  "intents": [
    {
      "phrase": "Run the web scraper",
      "action": "open -a Terminal ~/VoicePuppeteerVault/listener.js"
    },
    {
      "phrase": "Show my encrypted vault",
      "action": "open -a TextEdit ~/VoicePuppeteerVault/creds.json.enc"
    }
  ]
}

Import this file into Purple via its Settings → Intents panel. Once imported, you can say “Hey Purple, run the web scraper” and the entire pipeline launches hands‑free.

Step‑by‑Step Implementation Guide

Step 1: Prepare the macOS Environment

  1. Open Terminal (⌘ Space → type “Terminal”).
  2. Run the Homebrew script shown earlier to install node and openssl.
  3. Verify installations: 
    node -v
openssl version

Step 2: Configure the Secure Vault

  1. Generate a Keychain entry named VoicePuppeteerKey (the script does this automatically).
  2. Create creds.json with your site credentials.
  3. Encrypt the file with ./vault.sh encrypt creds.json and shred the plaintext.
  4. Test decryption: 
    ./vault.sh decrypt creds.json.enc
cat creds.json   # should display JSON
shred -u creds.json

Step 3: Install Vosk Model for Offline Speech Recognition

  1. Download a small English model: 
    curl -L -o vosk-model.zip https://alphacephei.com/vosk/models/vosk-model-small-en-us-0.15.zip
unzip vosk-model.zip -d /usr/local/share/
  2. Confirm the path /usr/local/share/vosk-model-small-en-us-0.15 exists.

Step 4: Launch the Listener and Test Voice Commands

  1. Start the listener in a new Terminal window: 
    node listener.js
  2. Speak “Run scraper” or “Show vault”. The listener should spawn the appropriate process.
  3. If you have Purple installed, say “Hey Purple, run the web scraper” and watch the system open Terminal, start the listener, and eventually produce a .docx file on your Desktop.

Step 5: Automate Post‑Processing with Finder and PDF Summaries

Purple can chain additional actions after the scraper finishes. Create a second intent:

{
  "phrase": "Summarize the latest report",
  "action": "python3 ~/VoicePuppeteerVault/summarizer.py"
}

Where summarizer.py uses pdfminer.six to extract text and OpenAI’s API (or a local LLM) to generate a concise summary, then saves it back to the same folder. This demonstrates the full “scrape → Word → PDF → Finder” loop.

Frequently Asked Questions

Can I use a cloud‑based speech service instead of Vosk?

Yes. Replace the Vosk recognizer with an API call to services like Google Speech‑to‑Text or Azure Speech. Keep in mind that sending raw audio to the cloud may conflict with the security posture of a BYOK vault. For maximum privacy, Vosk runs entirely offline.

How do I rotate the encryption key stored in the Keychain?

Generate a new 256‑bit key, replace the existing entry, and re‑encrypt the vault:

# Generate new key
NEWKEY=$(openssl rand -hex 32)
security delete-generic-password -s "VoicePuppeteerKey"
security add-generic-password -a $USER -s "VoicePuppeteerKey" -w "$NEWKEY"

# Decrypt old vault, then re‑encrypt with new key
./vault.sh decrypt creds.json.enc
./vault.sh encrypt creds.json   # uses the new key automatically
shred -u creds.json

All scripts automatically pick up the updated key on the next run.

Is it safe to let Purple execute arbitrary shell commands?

Purple respects macOS sandboxing and runs intents with the same privileges as the invoking user. To mitigate risk:

  • Limit Purple’s intent list to vetted commands only.
  • Store intents in a read‑only directory (/Library/Application Support/Purple/intents).
  • Enable macOS Gatekeeper and notarization for any compiled binaries you distribute.

When configured properly, Purple becomes a controlled voice interface rather than an open backdoor.
